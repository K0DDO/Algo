# BFS: обход в ширину

## Введение / определения с нуля

BFS, или Breadth-First Search, — это обход графа в ширину.

Идея: сначала посещаются все вершины на расстоянии 1 от стартовой, затем все вершины на расстоянии 2, затем на расстоянии 3 и так далее.

В лекции BFS объясняется через очередь «горящих» вершин:

- стартовая вершина загорается первой;
- очередь хранит вершины, которые уже загорелись, но еще не «сгорели» полностью;
- когда вершину достают из очереди, ее обрабатывают;
- от нее загораются еще не посещенные соседи;
- после обработки вершина считается сгоревшей.

Такой образ хорошо показывает главное свойство BFS: волна распространяется слоями.

Граф:

$$
G=(V,E)
$$

Для невзвешенного графа расстояние между вершинами — минимальное число ребер в пути.

BFS из стартовой вершины `s` находит:

- все вершины, достижимые из `s`;
- расстояние `d[v]` от `s` до каждой достижимой вершины;
- массив родителей `parent[v]`, по которому можно восстановить кратчайший путь;
- дерево BFS.

Важно: BFS ищет кратчайшие пути только в невзвешенном графе или в графе, где все ребра имеют одинаковый вес. Для взвешенных графов нужны другие алгоритмы, например Дейкстра или Беллман-Форд.

## Логика работы (пошагово + псевдокод)

### Базовый BFS

Пошагово:

1. Все расстояния `d[v]` устанавливаем равными бесконечности.
2. Для стартовой вершины `s` ставим `d[s] = 0`.
3. Кладем `s` в очередь.
4. Пока очередь не пуста:
   - достаем вершину `u`;
   - просматриваем всех соседей `v`;
   - если `v` еще не посещена, то есть `d[v] = ∞`:
     - ставим `d[v] = d[u] + 1`;
     - запоминаем `parent[v] = u`;
     - кладем `v` в очередь.

Псевдокод по лекционной идее:

```text
BFS(G, source):
    for v in V:
        d[v] = infinity
        parent[v] = null

    d[source] = 0
    Q = empty queue
    Q.push(source)

    while Q is not empty:
        u = Q.pop()

        for v in G.adj[u]:
            if d[v] == infinity:
                d[v] = d[u] + 1
                parent[v] = u
                Q.push(v)

    return d, parent
```

В лекции отдельно подчеркивается:

- очередь нужна для отслеживания вершин, которые «горят»;
- массив `d` нужен для расстояний;
- массив `parent` нужен для восстановления путей;
- при списке смежности сложность `O(|V|+|E|)`.

### Поиск расстояния до одной вершины

Если нужна только дистанция от `source` до `destination`, можно вернуть `d[destination]` после BFS.

```text
BFS_distance(G, source, destination):
    d, parent = BFS(G, source)
    return d[destination]
```

Если `d[destination] = infinity`, пути нет.

Можно остановиться раньше, когда `destination` впервые достали или впервые обнаружили. Но для учебной реализации часто проще выполнить весь BFS.

### Восстановление пути

После BFS путь от `s` до `t` восстанавливается через `parent`.

```text
RestorePath(parent, s, t):
    if t != s and parent[t] == null:
        return "path does not exist"

    path = empty list
    cur = t

    while cur != null:
        path.push(cur)
        cur = parent[cur]

    reverse(path)
    return path
```

Пример:

```text
parent[5] = 3
parent[3] = 1
parent[1] = null
```

Путь от 1 до 5:

```text
1 -> 3 -> 5
```

### BFS для всех компонент

Если граф может быть несвязным, но нужно обойти все вершины:

```text
for v in V:
    d[v] = infinity

for v in V:
    if d[v] == infinity:
        d[v] = 0
        BFS_from(v)
```

Так можно также считать компоненты связности в неориентированном графе.

## Структура данных

Главная структура данных BFS — очередь FIFO:

```text
first in, first out
```

То есть вершина, добавленная раньше, обрабатывается раньше.

Это принципиально важно. Если заменить очередь на стек, получится DFS, а не BFS.

Основные структуры:

- `adj[v]` — список смежности;
- `Q` — очередь;
- `d[v]` — расстояние от стартовой вершины;
- `parent[v]` — предок в дереве BFS;
- `used[v]` или проверка `d[v] != infinity` — признак посещения.

В лекции упомянуто, что граф можно хранить:

- списком смежности;
- матрицей инцидентности.

На практике для BFS чаще используют список смежности, потому что он позволяет пройти по всем ребрам за `O(V+E)`.

Для матрицы смежности просмотр всех соседей одной вершины стоит `O(V)`, поэтому весь BFS будет `O(V^2)`.

### Дерево BFS

BFS строит дерево поиска в ширину.

Изначально дерево состоит из одного корня `s`.

Когда мы впервые добавляем непосещенную вершину `v` в очередь из вершины `u`, мы добавляем в дерево:

- вершину `v`;
- ребро `(u, v)`;
- запись `parent[v] = u`.

Так как каждая вершина впервые посещается только один раз, у каждой достижимой вершины кроме корня будет ровно один родитель.

После окончания BFS путь в дереве BFS от `s` до любой достижимой вершины `t` является кратчайшим путем в исходном невзвешенном графе.

## Сложность по времени и памяти

Пусть граф задан списком смежности.

В очередь каждая вершина добавляется не более одного раза, потому что после первого обнаружения ее `d[v]` перестает быть бесконечным.

Операции с очередью:

- `push`;
- `pop`.

Каждая стоит `O(1)`, поэтому суммарно:

$$
O(|V|)
$$

Для каждой вершины просматриваются ее инцидентные ребра.

В неориентированном графе:

$$
\sum_{v \in V} deg(v)=2|E|
$$

В ориентированном графе суммарное число элементов во всех списках смежности равно `|E|`.

Итого:

$$
O(|V|+|E|)
$$

Это ровно лекционная асимптотика BFS.

Память:

- список смежности: `O(|V|+|E|)`;
- очередь: до `O(|V|)`;
- массив `d`: `O(|V|)`;
- массив `parent`: `O(|V|)`.

Итого дополнительная память без хранения графа:

$$
O(|V|)
$$

## Ограничения

BFS работает для невзвешенных кратчайших путей.

Если ребра имеют веса:

- все веса одинаковые — BFS применим;
- веса 0 и 1 — лучше использовать 0-1 BFS с деком;
- веса неотрицательные разные — алгоритм Дейкстры;
- есть отрицательные веса — Беллман-Форд или другие алгоритмы.

BFS из одной стартовой вершины не обходит недостижимые вершины.

Для несвязного неориентированного графа нужен внешний цикл по всем вершинам.

Для ориентированного графа достижимость зависит от направления ребер.

Порядок вершин на одном уровне зависит от порядка соседей в списках смежности, но расстояния от этого не меняются.

Если граф огромный, очередь может занимать много памяти, особенно на широких уровнях.

## Применимость

BFS применяют для:

- кратчайших путей в невзвешенном графе;
- восстановления кратчайшего пути через `parent`;
- проверки достижимости;
- поиска компонент связности;
- проверки двудольности;
- обхода состояний в задачах поиска;
- нахождения минимального числа операций;
- построения дерева BFS;
- вычисления расстояний от одной вершины до всех остальных.

Типичные задачи:

- минимальное число ходов коня на шахматной доске;
- кратчайший путь в лабиринте;
- минимальное число преобразований строки;
- социальные графы: расстояние по знакомствам;
- распространение пожара или инфекции по клеткам.

Образ «горящих» вершин из лекции особенно хорошо подходит для задач распространения: очередь хранит фронт процесса.

## Примеры с разбором

Рассмотрим граф:

```text
1 -- 2 -- 4
|    |
3 -- 5
```

Список смежности:

```text
adj[1] = [2, 3]
adj[2] = [1, 4, 5]
adj[3] = [1, 5]
adj[4] = [2]
adj[5] = [2, 3]
```

Запустим BFS из вершины 1.

Начало:

```text
d[1] = 0
d[2] = d[3] = d[4] = d[5] = infinity
Q = [1]
```

Достаем 1.

Соседи 1: 2 и 3.

Они еще не посещены:

```text
d[2] = 1, parent[2] = 1
d[3] = 1, parent[3] = 1
Q = [2, 3]
```

Достаем 2.

Соседи 2: 1, 4, 5.

1 уже посещена. 4 и 5 новые:

```text
d[4] = 2, parent[4] = 2
d[5] = 2, parent[5] = 2
Q = [3, 4, 5]
```

Достаем 3.

Соседи 3: 1 и 5.

Обе уже посещены, ничего не меняется.

Достаем 4, затем 5. Новых вершин нет.

Итог:

| Вершина | d | parent |
|---:|---:|---:|
| 1 | 0 | null |
| 2 | 1 | 1 |
| 3 | 1 | 1 |
| 4 | 2 | 2 |
| 5 | 2 | 2 |

Кратчайший путь от 1 до 5:

```text
5 -> parent[5] = 2 -> parent[2] = 1
```

После разворота:

```text
1 -> 2 -> 5
```

Путь длины 2. Другой кратчайший путь `1 -> 3 -> 5` тоже существует, но BFS выбрал родителя 2, потому что вершина 5 впервые была обнаружена из 2.

## Типичные ошибки / вопросы на экзамен

Типичные ошибки:

- использовать стек вместо очереди;
- помечать вершину посещенной только при извлечении, из-за чего она может попасть в очередь много раз;
- забывать инициализировать `d` бесконечностью;
- не ставить `d[source] = 0`;
- забывать `parent`;
- ожидать кратчайших путей во взвешенном графе;
- не обрабатывать недостижимые вершины;
- путать BFS-дерево с исходным графом;
- считать сложность `O(VE)`, хотя при списке смежности она `O(V+E)`.

Вопросы на экзамен:

1. Почему BFS находит кратчайшие пути в невзвешенном графе?
2. Зачем нужна очередь?
3. Что хранит массив `d`?
4. Что хранит массив `parent`?
5. Что такое дерево BFS?
6. Какая сложность BFS при списке смежности?
7. Почему каждая вершина попадает в очередь не более одного раза?
8. Можно ли BFS использовать для компонент связности?
9. Чем BFS отличается от DFS?
10. Почему BFS не подходит для произвольных весов ребер?

Короткие ответы:

- BFS идет слоями расстояний: сначала 0, потом 1, потом 2.
- Очередь сохраняет порядок обработки слоев.
- `d[v]` — расстояние от старта до `v`.
- `parent[v]` — предыдущая вершина на найденном кратчайшем пути.
- Сложность при списке смежности `O(V+E)`.

## Дополнительно (доказательства идей, варианты)

### Почему BFS находит кратчайшие расстояния

Докажем идею по слоям.

Стартовая вершина имеет расстояние 0.

Когда BFS обрабатывает вершину `u` с расстоянием `d[u]`, все еще не посещенные соседи получают расстояние:

$$
d[u]+1
$$

Очередь гарантирует, что вершины с меньшим расстоянием будут обработаны раньше вершин с большим расстоянием.

Поэтому когда вершина `v` впервые обнаруживается, найденный путь до нее имеет минимальную длину. Если бы существовал более короткий путь, предпоследняя вершина этого пути была бы обработана раньше и обнаружила бы `v` раньше.

### Мультистартовый BFS

Иногда стартовых вершин несколько. Например, несколько источников пожара.

Тогда:

```text
for s in sources:
    d[s] = 0
    Q.push(s)
```

Дальше обычный BFS. В результате `d[v]` будет расстоянием до ближайшего источника.

### 0-1 BFS

Если веса ребер только 0 или 1, можно использовать дек:

- ребро веса 0 добавляет вершину в начало;
- ребро веса 1 добавляет вершину в конец.

Это уже не обычный BFS, но идея очереди сохраняется.

### BFS и двудольность

Граф двудолен, если вершины можно раскрасить в два цвета так, чтобы каждое ребро соединяло вершины разных цветов.

BFS помогает:

- стартовую вершину красим в 0;
- соседей — в 1;
- соседей соседей — снова в 0;
- если встречаем ребро между вершинами одного цвета, граф не двудолен.

Цвет можно хранить как:

```text
color[v] = d[v] mod 2
```

для каждой компоненты.

# 06. Гамильтонов цикл

## Введение

Гамильтонов цикл в графе - это простой цикл, который проходит через каждую вершину ровно один раз и возвращается в стартовую вершину. Если цикл не обязан возвращаться в начало, говорят о гамильтоновом пути.

Задача поиска гамильтонова цикла принципиально отличается от задач про эйлеров цикл. Эйлеров цикл контролируется локальными условиями на степени вершин, а гамильтонов цикл зависит от глобальной структуры графа. В общем случае задача является NP-трудной: неизвестен полиномиальный алгоритм, который для любого графа быстро находит цикл или доказывает его отсутствие.

На практике поэтому различают две ситуации:

- граф удовлетворяет сильным достаточным условиям, например условиям Дирака или Оре;
- гарантий нет, и тогда используют перебор, бэктрекинг, динамическое программирование по подмножествам или эвристики.

## Основные определения

Пусть дан неориентированный граф `G = (V, E)`, `n = |V|`.

Гамильтонов путь - последовательность различных вершин `v1, v2, ..., vn`, такая что каждое соседнее множество вершин соединено ребром: `(vi, v{i+1}) in E`.

Гамильтонов цикл - гамильтонов путь, для которого дополнительно есть ребро `(vn, v1)`.

Граф называется гамильтоновым, если в нем существует гамильтонов цикл.

## Достаточные условия

### Теорема Дирака

Если `n >= 3` и степень каждой вершины не меньше `n / 2`, то граф гамильтонов.

Формально:

```text
для всех v in V: deg(v) >= n / 2
=> в G есть гамильтонов цикл
```

Важно: это достаточное, но не необходимое условие. Если условие Дирака не выполнено, гамильтонов цикл все равно может существовать.

### Теорема Оре

Если `n >= 3` и для любой пары несмежных вершин `u, v` выполнено

```text
deg(u) + deg(v) >= n
```

то граф гамильтонов.

Условие Оре обобщает идею Дирака. Если каждая вершина имеет степень хотя бы `n / 2`, то сумма степеней любых двух вершин хотя бы `n`, значит Дирак следует из Оре.

## Логика алгоритма при выполнении условий

Сами теоремы говорят о существовании цикла. Для учебной реализации можно использовать конструктивную идею через замыкание графа.

Идея замыкания:

1. Пока есть несмежная пара вершин `u, v`, для которой `deg(u) + deg(v) >= n`, добавим ребро `(u, v)`.
2. Если в результате получился полный граф, гамильтонов цикл очевиден.
3. Затем можно восстанавливать цикл в исходном графе, заменяя добавленные ребра подходящими участками существующего цикла.

В олимпиадной или учебной практике часто используют более простой алгоритм построения цикла при условии Дирака:

1. Поддерживаем текущий простой путь.
2. Пытаемся расширять путь влево или вправо вершинами, которые еще не использованы.
3. Если расширить нельзя, из-за высокой степени вершин существует поворот пути: можно заменить конец пути на другую вершину, сохранив простоту.
4. Повторяем, пока в пути не окажутся все вершины.
5. После этого по условию Дирака можно замкнуть путь в цикл или выполнить еще один поворот, чтобы появились ребро между концами.

В конспекте важно понимать не конкретную низкоуровневую реализацию, а смысл: большие степени не дают пути "застрять" слишком рано.

## Бэктрекинг

Если достаточные условия не выполнены, стандартный точный подход - перебор с возвратом.

Псевдокод:

```text
path = [start]
used[start] = true

dfs(last):
    if len(path) == n:
        if edge(last, start):
            найден гамильтонов цикл
        return

    for v in neighbors(last):
        if not used[v]:
            used[v] = true
            path.push(v)
            dfs(v)
            path.pop()
            used[v] = false
```

Ускорения:

- начинать с вершины малой степени, чтобы быстрее обнаруживать тупики;
- сортировать кандидатов по степени;
- заранее проверять связность графа;
- отсекать ветку, если оставшиеся неиспользованные вершины распались на несколько компонент;
- фиксировать стартовую вершину, чтобы не перебирать циклические сдвиги одного и того же цикла.

## Эвристики

Эвристики не гарантируют ответ, но полезны на больших графах.

Типичные подходы:

- жадно строить длинный путь, каждый раз выбирая "перспективную" соседнюю вершину;
- применять случайные перестановки вершин и пытаться улучшать найденный цикл;
- использовать локальные перестройки наподобие 2-opt;
- сначала искать гамильтонов путь, затем пытаться замкнуть его в цикл;
- для плотных графов проверять условия Дирака/Оре или близкие к ним критерии.

## Структуры данных

Для плотного графа удобна матрица смежности `adj[n][n]`, потому что проверка наличия ребра выполняется за `O(1)`. Это особенно полезно в бэктрекинге, где часто надо быстро проверить `edge(last, start)`.

Для разреженного графа удобны списки смежности `g[v]`. Они экономят память и позволяют перебирать только реальные ребра.

Дополнительные структуры:

- `used[v]` - была ли вершина уже включена в текущий путь;
- `path` - текущий путь;
- `deg[v]` - степени вершин для проверки условий Дирака/Оре;
- множество или матрица ребер для быстрых проверок смежности.

## Сложность

Проверка условия Дирака:

- время `O(V + E)` при списках смежности, если степени известны или легко считаются;
- память `O(V)`.

Проверка условия Оре:

- наивно `O(V^2)` пар вершин плюс проверка смежности;
- при матрице смежности проверка пары `O(1)`;
- память матрицы `O(V^2)`.

Бэктрекинг:

- время в худшем случае экспоненциальное, грубо `O(n!)`;
- память `O(V)` на путь, `used` и стек рекурсии, не считая хранения графа.

Динамическое программирование по подмножествам для гамильтонова пути/цикла:

- состояние `dp[mask][v]`: можно ли прийти в `v`, посетив множество `mask`;
- время `O(2^V * V^2)`;
- память `O(2^V * V)`;
- применимо только при небольшом `V`.

## Ограничения

Главное ограничение - NP-трудность задачи. Для произвольного графа нельзя рассчитывать на быстрый точный алгоритм при больших `n`.

Условия Дирака и Оре не являются необходимыми. Их невыполнение не означает, что цикла нет.

Бэктрекинг может быть очень быстрым на некоторых графах и очень медленным на других. Время зависит от порядка перебора и структуры графа.

Матрица смежности удобна для проверок, но требует `O(V^2)` памяти, что плохо для больших разреженных графов.

## Применимость

Гамильтоновы циклы появляются в задачах, где нужно посетить каждый объект ровно один раз:

- маршрутизация и варианты задачи коммивояжера;
- планирование обхода состояний;
- задачи на перестановки и туры;
- проверка существования циклического расписания;
- теоретические задачи про свойства графов.

Если граф плотный, сначала стоит проверить условия Дирака и Оре. Если граф небольшой, можно использовать бэктрекинг или DP по подмножествам. Если граф большой и произвольный, чаще используют эвристики.

## Примеры

Пусть `n = 6`, и степени вершин:

```text
deg = [3, 4, 3, 5, 3, 4]
```

Так как `n / 2 = 3`, у каждой вершины степень хотя бы `3`. Значит, по теореме Дирака граф гамильтонов.

Мы можем не знать сам цикл сразу, но теорема гарантирует его существование. Дальше можно запустить конструктивный алгоритм или бэктрекинг, который найдет один из циклов.

Другой пример:

```text
V = {1, 2, 3, 4}
E = {(1,2), (2,3), (3,4), (4,1)}
```

Цикл `1 -> 2 -> 3 -> 4 -> 1` является гамильтоновым. Условие Дирака тоже выполнено: `n / 2 = 2`, степени всех вершин равны `2`.

## Типичные ошибки

- Путать гамильтонов и эйлеров циклы: гамильтонов проходит по вершинам, эйлеров - по ребрам.
- Считать условия Дирака и Оре необходимыми.
- Забывать проверять ребро из последней вершины пути в стартовую.
- В бэктрекинге не снимать отметку `used` при возврате.
- Для ориентированного графа применять неориентированные формулировки без изменений.

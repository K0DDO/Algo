# DFS: обход в глубину

## Введение / определения с нуля

DFS, или Depth-First Search, — это обход графа в глубину.

Идея: из текущей вершины мы идем в еще не посещенного соседа, затем из него снова в еще не посещенного соседа, и так далее, пока не упремся в вершину, из которой больше некуда идти. После этого возвращаемся назад.

Граф:

$$
G=(V,E)
$$

где:

- `V` — множество вершин;
- `E` — множество ребер.

DFS можно запускать:

- в неориентированном графе;
- в ориентированном графе;
- из одной стартовой вершины;
- серией запусков из всех еще не посещенных вершин.

Если граф несвязный, один запуск DFS из одной вершины обойдет только те вершины, которые достижимы из нее. Чтобы обойти весь граф, нужно запустить DFS из каждой белой вершины.

В лекции DFS описан через три цвета:

- `white` — вершина еще не посещалась;
- `gray` — вершина сейчас находится в активном рекурсивном стеке, мы вошли в нее, но еще не вышли;
- `black` — вершина полностью обработана.

Эти цвета особенно важны в ориентированных графах:

- переход в белую вершину означает обычное углубление;
- переход в серую вершину означает обратное ребро и наличие цикла;
- переход в черную вершину означает, что та вершина уже полностью обработана.

DFS используется как базовый инструмент для многих алгоритмов:

- поиск компонент связности;
- поиск цикла;
- топологическая сортировка;
- поиск компонент сильной связности;
- построение времен входа и выхода;
- классификация ребер;
- проверка достижимости.

## Логика работы (пошагово + псевдокод)

### Базовая идея

Пошагово:

1. Все вершины красим в `white`.
2. Перебираем вершины графа.
3. Если очередная вершина белая, запускаем из нее `Visit`.
4. При входе в вершину красим ее в `gray`.
5. Просматриваем всех соседей.
6. Если сосед белый, рекурсивно запускаем DFS из него.
7. Когда все соседи обработаны, красим вершину в `black`.

Псевдокод из лекционной идеи:

```text
DFS(G):
    for u in G.V:
        u.color = white

    for u in G.V:
        if u.color == white:
            Visit(G, u)

Visit(G, u):
    u.color = gray

    for v in G.adj[u]:
        if v.color == white:
            Visit(G, v)

    u.color = black
```

Здесь `G.adj[u]` — список соседей вершины `u`.

### DFS с временем входа и выхода

Часто дополнительно хранят:

- `tin[v]` — время входа в вершину;
- `tout[v]` — время выхода из вершины.

Псевдокод:

```text
timer = 0

DFS(G):
    for v in V:
        color[v] = white

    for v in V:
        if color[v] == white:
            Visit(v)

Visit(v):
    color[v] = gray
    timer = timer + 1
    tin[v] = timer

    for to in adj[v]:
        if color[to] == white:
            parent[to] = v
            Visit(to)

    color[v] = black
    timer = timer + 1
    tout[v] = timer
```

Время выхода используется в топологической сортировке и алгоритмах сильной связности.

### Итеративный DFS

Рекурсию можно заменить стеком.

Простой вариант:

```text
DFS_iterative(start):
    stack = empty stack
    stack.push(start)

    while stack is not empty:
        v = stack.pop()

        if color[v] != white:
            continue

        color[v] = gray

        for to in adj[v]:
            if color[to] == white:
                stack.push(to)

        color[v] = black
```

Но этот простой вариант не полностью имитирует рекурсивный DFS, потому что вершина быстро становится черной, не оставаясь серой на время обработки потомков.

Если нужны именно три цвета, поиск цикла или времена выхода, лучше использовать стек кадров:

```text
DFS_iterative_precise(start):
    stack.push((start, 0))
    color[start] = gray

    while stack is not empty:
        v, i = stack.top()

        if i == adj[v].size:
            color[v] = black
            stack.pop()
            continue

        to = adj[v][i]
        stack.top().i = i + 1

        if color[to] == white:
            parent[to] = v
            color[to] = gray
            stack.push((to, 0))
```

## Структура данных

Для DFS обычно используют список смежности:

```text
adj[v] = список вершин, в которые есть ребро из v
```

Для неориентированного ребра `(u, v)` добавляют:

```text
adj[u].push(v)
adj[v].push(u)
```

Для ориентированного ребра `u -> v` добавляют:

```text
adj[u].push(v)
```

Основные массивы:

- `color[v]` — цвет вершины;
- `visited[v]` — упрощенный вариант, если хватает двух состояний;
- `parent[v]` — предок в DFS-дереве;
- `tin[v]` — время входа;
- `tout[v]` — время выхода;
- `component[v]` — номер компоненты, если ищем компоненты связности.

Рекурсивная реализация использует системный стек вызовов.

Итеративная реализация использует явный стек:

```text
stack<Vertex>
```

или:

```text
stack<(Vertex, nextNeighborIndex)>
```

Матрица смежности тоже возможна, но при ней просмотр соседей вершины стоит `O(V)`, поэтому полный обход будет `O(V^2)`. Для разреженных графов список смежности гораздо эффективнее.

## Сложность по времени и памяти

Пусть граф задан списком смежности.

DFS просматривает:

- каждую вершину хотя бы один раз;
- каждое ребро при просмотре списка смежности.

Для ориентированного графа каждое ребро рассматривается один раз.

Для неориентированного графа каждое ребро встречается в списках два раза: у обоих концов.

Итоговая сложность:

$$
O(|V|+|E|)
$$

Это совпадает с лекционной оценкой: просматриваем все вершины и все смежные ребра, пока красим вершины в черный.

Память:

- список смежности: `O(|V|+|E|)`;
- массив цветов: `O(|V|)`;
- массив родителей: `O(|V|)`;
- времена входа/выхода: `O(|V|)`;
- стек рекурсии: до `O(|V|)`.

Если граф задан матрицей смежности, память:

$$
O(|V|^2)
$$

и обход всех соседей всех вершин:

$$
O(|V|^2)
$$

## Ограничения

DFS не гарантирует кратчайшие пути в невзвешенном графе. Для кратчайших путей по числу ребер нужен BFS.

Рекурсивный DFS может переполнить стек, если граф большой и путь очень длинный.

В языках с небольшим лимитом рекурсии, например Python, для больших графов нужно:

- увеличивать лимит рекурсии осторожно;
- использовать итеративную реализацию;
- следить за глубиной.

Порядок обхода зависит от порядка соседей в списке смежности. Поэтому DFS-дерево может быть разным при разных порядках хранения ребер.

Для поиска циклов в неориентированном графе нельзя просто считать ребро в серую вершину циклом, если это ребро ведет к родителю. Нужно отдельно проверять `to != parent[v]`.

Для ориентированного графа переход в серую вершину действительно означает цикл.

## Применимость

DFS применим, когда нужно глубоко исследовать структуру графа.

Типичные задачи:

- проверить достижимость;
- обойти все вершины;
- найти компоненты связности;
- найти компоненты слабой связности после превращения ориентированного графа в неориентированный;
- найти цикл в ориентированном графе по серой вершине;
- восстановить цикл через массив `parent`;
- построить топологическую сортировку;
- найти времена выхода для алгоритма Косарайю;
- проверить свойства дерева;
- решить задачи на лабиринты и перебор.

DFS удобен там, где естественна рекурсия: зайти, обработать потомков, выйти.

## Примеры с разбором

Рассмотрим ориентированный граф:

```text
1 -> 2
1 -> 3
2 -> 4
3 -> 4
4 -> 5
```

Списки смежности:

```text
adj[1] = [2, 3]
adj[2] = [4]
adj[3] = [4]
adj[4] = [5]
adj[5] = []
```

Запускаем DFS из 1.

Шаги:

1. Входим в 1, цвет 1 становится `gray`.
2. Первый сосед 1 — вершина 2, она `white`, идем в 2.
3. Входим в 2, цвет 2 становится `gray`.
4. Сосед 2 — вершина 4, она `white`, идем в 4.
5. Входим в 4, цвет 4 становится `gray`.
6. Сосед 4 — вершина 5, она `white`, идем в 5.
7. У 5 нет соседей, красим 5 в `black`.
8. Возвращаемся в 4, все соседи обработаны, красим 4 в `black`.
9. Возвращаемся в 2, красим 2 в `black`.
10. Возвращаемся в 1, следующий сосед — 3, она `white`, идем в 3.
11. У 3 сосед 4, но 4 уже `black`, рекурсию не запускаем.
12. Красим 3 в `black`.
13. Красим 1 в `black`.

Одно возможное DFS-дерево:

```text
1
└── 2
    └── 4
        └── 5
└── 3
```

Ребро `3 -> 4` не вошло в дерево, потому что 4 уже была посещена.

Теперь пример с циклом:

```text
1 -> 2
2 -> 3
3 -> 1
```

При DFS:

1. Входим в 1: `gray`.
2. Идем в 2: `gray`.
3. Идем в 3: `gray`.
4. Из 3 видим ребро в 1.
5. Вершина 1 сейчас `gray`.
6. Значит, найден цикл `1 -> 2 -> 3 -> 1`.

## Типичные ошибки / вопросы на экзамен

Типичные ошибки:

- использовать только `visited`, когда нужны три цвета;
- красить вершину в `black` слишком рано;
- не запускать DFS из всех компонент;
- забывать, что в ориентированном и неориентированном графах поиск цикла отличается;
- не учитывать переполнение стека;
- ожидать от DFS кратчайшие пути;
- путать время входа и время выхода;
- неправильно восстанавливать путь через `parent`;
- изменять список смежности во время обхода без необходимости.

Вопросы на экзамен:

1. Что означают цвета `white`, `gray`, `black`?
2. Почему переход в серую вершину в ориентированном графе означает цикл?
3. Какова сложность DFS при списке смежности?
4. Почему нужно запускать DFS из всех белых вершин?
5. Чем рекурсивный DFS отличается от итеративного?
6. Что такое DFS-дерево?
7. Где используются времена выхода?
8. Почему DFS не ищет кратчайший путь?
9. Как найти компоненты связности через DFS?
10. Как избежать переполнения рекурсии?

Короткие ответы:

- `white` — не посещена, `gray` — в стеке рекурсии, `black` — полностью обработана.
- Серая вершина является предком текущей в рекурсивном стеке, значит есть путь от нее к текущей и ребро назад.
- При списке смежности сложность `O(V+E)`.
- Если граф несвязный, один запуск не обойдет все вершины.

## Дополнительно (доказательства идей, варианты)

### Лемма о DFS из лекции

В лекции сформулирована важная идея:

> Нет такого момента в процессе выполнения DFS, когда существует ребро из черной вершины в белую.

Интуиция:

если вершина стала черной, значит DFS уже просмотрел всех ее соседей. Если у нее был белый сосед, DFS обязан был бы зайти в него до покраски исходной вершины в черный.

### Лемма о белых путях

Лекционная формулировка:

Пусть во время выполнения DFS мы остановились в первый момент `T1` на некоторой серой вершине `u`, а затем продолжили выполнение `dfs(u)` до момента `T2`, когда `u` стала черной.

Тогда вершины графа `G \ u`, которые были черными и серыми в момент `T1`, не поменяют свой цвет ко второму моменту, а белые вершины либо останутся белыми, либо станут черными. Черными станут именно те, которые были достижимы от `u` по белым путям.

Белый путь — путь, все вершины которого на момент `T1` были белыми.

Идея доказательства:

- DFS из `u` может заходить только в белые вершины;
- если белая вершина достижима из `u` через белые вершины, рекурсия постепенно дойдет до нее;
- серые и черные вершины уже не становятся белыми;
- после полного завершения `dfs(u)` все достижимые по белым путям вершины будут обработаны.

Эта лемма помогает доказывать корректность DFS-алгоритмов, например топологической сортировки и поиска компонент сильной связности.

### Классификация ребер

В ориентированном графе при DFS ребра можно классифицировать:

- tree edge — ребро в белую вершину, входит в DFS-дерево;
- back edge — ребро в серую вершину, указывает на цикл;
- forward edge — ребро к потомку, который уже черный;
- cross edge — ребро между разными ветвями DFS.

Для базовых задач обычно достаточно помнить главное: ребро в серую вершину в ориентированном графе означает цикл.

### DFS как шаблон

Многие алгоритмы строятся по одному шаблону:

```text
enter vertex
process before children
for each neighbor:
    process edge
    if neighbor is new:
        dfs(neighbor)
process after children
exit vertex
```

Важный навык — понимать, что нужно делать при входе, при просмотре ребра и при выходе.

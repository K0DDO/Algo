# 18. Сведение максимального паросочетания к максимальному потоку

## 1. Идея

Задачу максимального паросочетания в двудольном графе можно решить через задачу максимального потока.

Это полезно, потому что потоки являются универсальным инструментом: через них решаются задачи назначений, покрытий, распределений и многие другие комбинаторные задачи.

В лекции идея формулировалась так:

> Максимальный поток = максимальное паросочетание.

Для этого исходный двудольный граф превращается в потоковую сеть.

## 2. Исходная задача

Дан двудольный граф:

```text
G = (L union R, E)
```

где:

- `L` - левая доля;
- `R` - правая доля;
- каждое ребро идет из вершины `L` в вершину `R`;
- нужно выбрать максимальное количество ребер так, чтобы никакие два выбранных ребра не имели общей вершины.

То есть нужно найти максимальное паросочетание.

## 3. Построение сети

Строим ориентированную сеть.

Добавляем две новые вершины:

- `s` - источник;
- `t` - сток.

Затем добавляем ребра:

1. Из источника в каждую вершину левой доли:

```text
s -> l
capacity = 1
```

2. Для каждого ребра исходного двудольного графа `(l, r)` добавляем ориентированное ребро:

```text
l -> r
capacity = 1
```

3. Из каждой вершины правой доли в сток:

```text
r -> t
capacity = 1
```

Итого конструкция:

```text
s -> L -> R -> t
```

Все пропускные способности равны `1`.

## 4. Почему емкости равны `1`

Ребро `s -> l` емкости `1` означает:

> левая вершина `l` может быть использована не более одного раза.

Ребро `r -> t` емкости `1` означает:

> правая вершина `r` может быть использована не более одного раза.

Ребро `l -> r` емкости `1` означает:

> можно выбрать пару `(l, r)`, но не больше одного раза.

Именно эти ограничения совпадают с определением паросочетания: вершина не может входить в две выбранные пары.

## 5. Пример с `L1, L2, L3` и `R1, R2, R3`

Пусть исходный граф:

```text
L1: R1, R2
L2: R2, R3
L3: R3
```

Строим сеть:

```text
s -> L1 capacity 1
s -> L2 capacity 1
s -> L3 capacity 1

L1 -> R1 capacity 1
L1 -> R2 capacity 1
L2 -> R2 capacity 1
L2 -> R3 capacity 1
L3 -> R3 capacity 1

R1 -> t capacity 1
R2 -> t capacity 1
R3 -> t capacity 1
```

Если максимальный поток равен `3`, то существует паросочетание размера `3`, например:

```text
(L1, R1)
(L2, R2)
(L3, R3)
```

Поток выглядит как три независимых пути:

```text
s -> L1 -> R1 -> t
s -> L2 -> R2 -> t
s -> L3 -> R3 -> t
```

Каждый путь несет `1` единицу потока и соответствует одной паре.

## 6. Как восстановить паросочетание из потока

После нахождения максимального потока смотрим только на ребра между `L` и `R`.

Если по ребру `l -> r` течет `1`, то добавляем пару:

```text
(l, r)
```

в ответ.

Если по ребру `l -> r` течет `0`, то это ребро не входит в паросочетание.

При реализации через остаточные емкости:

- исходная емкость ребра `l -> r` была `1`;
- если остаточная емкость стала `0`, значит по ребру прошел поток `1`;
- значит ребро входит в паросочетание.

## 7. Почему поток задает корректное паросочетание

Рассмотрим любой целочисленный поток в построенной сети.

Так как все ребра `s -> l` имеют емкость `1`, из каждой левой вершины может выйти не больше одной единицы потока, пришедшей из `s`.

Значит каждая вершина `l` участвует не более чем в одной выбранной паре.

Так как все ребра `r -> t` имеют емкость `1`, в каждую правую вершину может войти не больше одной единицы потока, которая затем уйдет в `t`.

Значит каждая вершина `r` участвует не более чем в одной выбранной паре.

Следовательно, множество ребер `l -> r`, по которым идет поток `1`, является паросочетанием.

## 8. Почему паросочетание задает поток

Пусть есть паросочетание `M`.

Для каждой пары `(l, r) in M` отправим единицу потока по пути:

```text
s -> l -> r -> t
```

Так как `M` - паросочетание:

- ни одна левая вершина не используется дважды;
- ни одна правая вершина не используется дважды.

Значит емкости `s -> l` и `r -> t`, равные `1`, не нарушаются.

Поток сохраняется во всех промежуточных вершинах:

- в `l` входит `1` из `s` и выходит `1` в `r`;
- в `r` входит `1` из `l` и выходит `1` в `t`.

Получаем допустимый поток величины `|M|`.

## 9. Эквивалентность

Мы доказали две стороны:

1. Любой целочисленный поток величины `k` задает паросочетание размера `k`.
2. Любое паросочетание размера `k` задает поток величины `k`.

Значит максимальный поток в построенной сети равен размеру максимального паросочетания.

```text
max matching size = max flow value
```

## 10. Почему поток будет целочисленным

Все пропускные способности в построенной сети целые, более того равны `1`.

Алгоритмы Форда-Фалкерсона и Эдмондса-Карпа при целых емкостях проталкивают целые bottleneck-значения.

Поэтому итоговый поток будет целочисленным.

Это важно: если бы поток мог быть дробным, ребро `l -> r` с потоком `0.5` было бы неудобно интерпретировать как выбранную пару. Но при целых емкостях такой проблемы нет.

## 11. Связь с алгоритмом Куна

Алгоритм Куна ищет увеличивающие цепи напрямую в двудольном графе.

Потоковый подход делает почти то же самое, но в построенной сети:

- свободная левая вершина соответствует свободной пропускной способности на ребре `s -> l`;
- свободная правая вершина соответствует свободной пропускной способности на ребре `r -> t`;
- переназначение пары соответствует проходу по обратным ребрам в остаточной сети;
- увеличивающая цепь соответствует дополняющему пути из `s` в `t`.

Например путь в остаточной сети:

```text
s -> L3 -> R3 -> L2 -> R2 -> L1 -> R1 -> t
```

означает цепочку переназначений:

- `L3` хочет `R3`;
- `R3` занята `L2`, поэтому надо переставить `L2`;
- `L2` идет в `R2`;
- `R2` занята `L1`, поэтому надо переставить `L1`;
- `L1` идет в свободную `R1`.

Это ровно логика увеличивающей цепи.

## 12. Сложность

Пусть:

- `nL = |L|`;
- `nR = |R|`;
- `m = |E|` в исходном двудольном графе.

В построенной сети:

```text
V_flow = nL + nR + 2
E_flow = m + nL + nR
```

### Если использовать Форд-Фалкерсон с DFS

Все увеличения имеют величину `1`, потому что все емкости равны `1`.

Максимальный поток не больше:

```text
min(nL, nR)
```

Сложность:

```text
O(E_flow * max_matching)
```

В худшем случае:

```text
O((m + nL + nR) * min(nL, nR))
```

Это сопоставимо с простым алгоритмом Куна.

В лекции для алгоритма Форда-Фалкерсона для максимального паросочетания указывалась оценка:

```text
O(E * V)
```

где `E` и `V` относятся к размеру построенной сети или исходного графа с точностью до добавленных ребер и вершин.

### Если использовать Эдмондса-Карпа

Общая оценка:

```text
O(V_flow * E_flow^2)
```

Для единичных сетей на практике могут быть более тонкие оценки, но в базовом курсе достаточно стандартной оценки Эдмондса-Карпа.

## 13. Структуры данных

Для исходного двудольного графа:

- список ребер `L -> R`;
- или списки смежности `g[l]`.

Для потоковой сети:

- списки смежности;
- для каждого ребра хранится обратное ребро;
- текущая остаточная емкость;
- исходная информация о том, какие ребра являются ребрами `L -> R`, чтобы потом восстановить пары.

Практичный вариант:

```text
add_edge(s, l, 1)
add_edge(l, r, 1)   // запомнить это ребро как matching-edge
add_edge(r, t, 1)
```

После max-flow пройти по сохраненным ребрам `l -> r` и проверить, был ли по ним поток.

## 14. Ограничения и применимость

Метод применим для:

- максимального паросочетания в двудольном графе;
- задач назначения без весов;
- случаев, где удобно использовать уже написанный алгоритм max-flow;
- обобщений, где у вершин или групп есть емкости больше `1`.

Метод не является прямым решением для:

- максимального паросочетания в недвудольном графе;
- минимального или максимального весового паросочетания;
- задачи, где нужно оптимизировать стоимость, а не только количество пар.

Для весов обычно нужны другие алгоритмы, например min-cost max-flow или венгерский алгоритм для задачи назначения.

## 15. Пример прикладной интерпретации

Есть:

- студенты `L`;
- проекты `R`;
- ребро `student -> project`, если студент согласен делать проект.

Строим:

```text
s -> каждый студент capacity 1
студент -> интересный проект capacity 1
каждый проект -> t capacity 1
```

Максимальный поток показывает, сколько студентов можно распределить.

Ребра студент-проект с потоком `1` дают конкретное распределение.

## 16. Итог

Сведение паросочетания к потоку строится по схеме:

```text
s -> L -> R -> t
```

с емкостями `1` на всех ребрах.

Емкости из `s` и в `t` гарантируют, что каждая вершина будет использована не более одного раза. Каждый единичный путь из `s` в `t` соответствует одной паре. Поэтому величина максимального потока равна размеру максимального паросочетания, а само паросочетание восстанавливается по ребрам `L -> R`, по которым прошел поток.

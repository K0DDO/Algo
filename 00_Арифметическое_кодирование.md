# Арифметическое кодирование

## Введение / определения с нуля

Арифметическое кодирование — это метод сжатия, который представляет все сообщение одним числом из интервала `[0, 1)`.

В отличие от кодирования Хаффмана, арифметическое кодирование не обязано выдавать целое число бит на каждый отдельный символ. Оно кодирует сообщение целиком, поэтому может подходить к энтропийному пределу точнее.

Основная идея:

1. Берем начальный интервал `[0, 1)`.
2. Делим его на части пропорционально вероятностям символов.
3. Читаем сообщение символ за символом.
4. На каждом шаге сужаем текущий интервал до подинтервала, соответствующего очередному символу.
5. После обработки всего сообщения выбираем любое число внутри итогового интервала.
6. Это число и есть код сообщения.

Пусть алфавит:

$$
\Sigma = \{a_1, a_2, \dots, a_n\}
$$

Каждому символу задана вероятность:

$$
p(a_i)
$$

Сумма вероятностей:

$$
\sum_i p(a_i)=1
$$

Для каждого символа строится полуинтервал внутри `[0,1)`. Например:

| Символ | Вероятность | Интервал |
|---|---:|---|
| A | 0.5 | `[0.0, 0.5)` |
| B | 0.3 | `[0.5, 0.8)` |
| C | 0.2 | `[0.8, 1.0)` |

Эти интервалы задаются через накопленные вероятности:

$$
low(a_i)=\sum_{j<i}p(a_j)
$$

$$
high(a_i)=\sum_{j\le i}p(a_j)
$$

Для символа `B` в примере:

$$
low(B)=0.5,\quad high(B)=0.8
$$

Интервалы обычно полуоткрытые: левая граница включается, правая не включается. Это помогает избежать неоднозначностей на границах.

Важно: на практике арифметическое кодирование не хранят как обычное вещественное число с бесконечной точностью. Реальные реализации используют целочисленную арифметику, нормализацию и вывод битов по мере возможности. Но учебная идея проще объясняется через интервалы.

## Логика работы (пошагово + псевдокод)

### Кодирование

Пусть текущий интервал:

$$
[L, R)
$$

Его ширина:

$$
range = R - L
$$

Для очередного символа `x` с модельным интервалом:

$$
[low(x), high(x))
$$

новый интервал:

$$
L' = L + range \cdot low(x)
$$

$$
R' = L + range \cdot high(x)
$$

То есть мы берем внутри текущего интервала ту же относительную долю, которая соответствует символу `x` в базовом интервале `[0,1)`.

Пошагово:

1. Построить вероятностную модель символов.
2. Для каждого символа вычислить накопленные границы `low` и `high`.
3. Установить `L = 0`, `R = 1`.
4. Для каждого символа сообщения:
   - вычислить `range = R - L`;
   - заменить `R` на `L + range * high(symbol)`;
   - заменить `L` на `L + range * low(symbol)`;
   - важно использовать старые значения `L` и `R`, поэтому обычно сначала сохраняют их.
5. После последнего символа выбрать число `code` из `[L, R)`.
6. Передать `code`, модель и длину сообщения или специальный символ конца.

Псевдокод:

```text
ArithmeticEncode(message, model):
    L = 0
    R = 1

    for x in message:
        range = R - L
        oldL = L

        L = oldL + range * model.low[x]
        R = oldL + range * model.high[x]

    code = any number in [L, R)
    return code
```

Часто выбирают середину:

$$
code = \frac{L+R}{2}
$$

Это удобно для демонстрации, но в реальном кодере надо вывести минимальное число бит, которое однозначно задает число внутри интервала.

### Декодирование

Декодер знает:

- число `code`;
- вероятностную модель;
- длину сообщения или символ конца.

Идея декодирования:

1. Начать с интервала `[0,1)`.
2. Найти, в какой символ попадает `code` относительно текущего интервала.
3. Вывести этот символ.
4. Сузить интервал так же, как при кодировании.
5. Повторять, пока не восстановим нужное число символов или не встретим символ конца.

Чтобы понять, какой символ закодирован на текущем шаге, вычисляют нормализованное значение:

$$
value = \frac{code - L}{R - L}
$$

Затем находят символ `x`, для которого:

$$
low(x) \le value < high(x)
$$

Псевдокод:

```text
ArithmeticDecode(code, model, length):
    L = 0
    R = 1
    result = empty string

    repeat length times:
        range = R - L
        value = (code - L) / range

        find symbol x such that:
            model.low[x] <= value < model.high[x]

        result.append(x)

        oldL = L
        L = oldL + range * model.low[x]
        R = oldL + range * model.high[x]

    return result
```

Если вместо длины используется специальный символ `EOF`, то декодирование продолжается до него.

### Почему интервал сужается

Если вероятность символа высокая, его подинтервал широкий. При выборе такого символа текущий интервал сужается не очень сильно.

Если вероятность символа низкая, его подинтервал узкий. Выбор редкого символа резко сужает интервал.

Итоговая длина интервала примерно равна произведению вероятностей символов сообщения:

$$
|I| = \prod_{i=1}^{m} p(x_i)
$$

Чтобы задать число внутри интервала, нужно примерно:

$$
-\log_2 |I| = -\sum_{i=1}^{m}\log_2 p(x_i)
$$

бит. Это напрямую связано с энтропией.

## Структура данных

Для учебной реализации нужны:

- таблица вероятностей `prob[symbol]`;
- таблица нижних границ `low[symbol]`;
- таблица верхних границ `high[symbol]`;
- текущие границы `L` и `R`;
- список символов в фиксированном порядке.

Модель можно хранить так:

```text
SymbolRange:
    symbol
    low
    high
```

Пример:

```text
model = [
    { symbol: 'A', low: 0.0, high: 0.5 },
    { symbol: 'B', low: 0.5, high: 0.8 },
    { symbol: 'C', low: 0.8, high: 1.0 }
]
```

Для быстрого декодирования надо по `value` быстро найти символ. В простом варианте используется линейный поиск по алфавиту:

```text
for each symbol x:
    if low[x] <= value < high[x]:
        return x
```

Если алфавит большой, лучше использовать:

- бинарный поиск по накопленным границам;
- Fenwick tree для адаптивной модели;
- сегментное дерево;
- таблицы для ускорения поиска.

В реальных реализациях вместо вещественных чисел используются целые границы:

```text
L, R внутри диапазона 0..2^k-1
```

Кодер выводит старшие одинаковые биты `L` и `R`, пока они совпадают. Это называется нормализацией или ренормализацией.

## Сложность по времени и памяти

Пусть:

- `m` — длина сообщения;
- `n` — размер алфавита.

Построение частот:

$$
O(m)
$$

Построение накопленных интервалов:

$$
O(n)
$$

Кодирование:

$$
O(m)
$$

если доступ к `low[x]` и `high[x]` выполняется за `O(1)`.

Декодирование:

- при линейном поиске символа: `O(mn)`;
- при бинарном поиске по границам: `O(m \log n)`;
- при специализированных структурах: часто близко к `O(m log n)` или быстрее по практике.

Память:

$$
O(n)
$$

для модели, плюс память на вход и выход.

Если модель адаптивная, нужно хранить текущие частоты и поддерживать их обновление.

## Ограничения

Главное ограничение учебной версии — точность чисел.

Если использовать обычные `float` или `double`, интервал быстро станет очень узким. Для длинного сообщения границы могут перестать различаться из-за ошибок округления.

Поэтому реальный арифметический кодер:

- не хранит бесконечно точное число;
- выводит биты постепенно;
- поддерживает интервал в целых числах;
- выполняет ренормализацию;
- аккуратно обрабатывает переносы и границы.

Еще одно ограничение: декодер должен знать ту же модель, что и кодер.

Если кодер использовал вероятности:

```text
A: 0.5, B: 0.3, C: 0.2
```

а декодер использует:

```text
A: 0.4, B: 0.4, C: 0.2
```

то сообщение будет восстановлено неверно.

Также надо знать, где сообщение заканчивается:

- передавать длину;
- или включить специальный символ конца `EOF`.

Ограничения метода:

- сложнее в реализации, чем Хаффман;
- чувствителен к точности;
- требует одинаковой модели на кодере и декодере;
- при ошибке в потоке может испортиться вся оставшаяся декодировка;
- патентные ограничения исторически мешали широкому использованию, хотя сейчас это в основном исторический факт.

## Применимость

Арифметическое кодирование применимо, когда нужно хорошее сжатие и есть вероятностная модель.

Подходит для:

- текстового сжатия;
- сжатия изображений;
- статистического кодирования после преобразований;
- адаптивных моделей;
- ситуаций, где Хаффман теряет эффективность из-за целочисленных длин кодов.

Особенно полезно, когда вероятности символов не являются степенями `1/2`.

Например, символ с вероятностью `0.9` в коде Хаффмана все равно не может иметь длину меньше 1 бита в одиночном кодовом слове. Арифметическое кодирование на длинной последовательности может приблизиться к:

$$
-\log_2 0.9 \approx 0.152
$$

бита на такой символ в среднем.

Не лучший выбор:

- если нужна максимально простая реализация;
- если сообщение очень короткое;
- если нельзя передать модель;
- если канал часто вносит ошибки без защиты;
- если нужна независимая декодируемость отдельных символов.

## Примеры с разбором

Возьмем алфавит:

| Символ | Вероятность | Интервал |
|---|---:|---|
| A | 0.5 | `[0.0, 0.5)` |
| B | 0.3 | `[0.5, 0.8)` |
| C | 0.2 | `[0.8, 1.0)` |

Закодируем сообщение:

```text
BAC
```

Начальный интервал:

```text
[0, 1)
```

### Шаг 1: символ B

Для `B` базовый интервал:

```text
[0.5, 0.8)
```

Текущий `range = 1 - 0 = 1`.

Новый интервал:

```text
L = 0 + 1 * 0.5 = 0.5
R = 0 + 1 * 0.8 = 0.8
```

Получили:

```text
[0.5, 0.8)
```

### Шаг 2: символ A

Текущий интервал:

```text
[0.5, 0.8)
```

Ширина:

```text
range = 0.3
```

Для `A` базовый интервал `[0.0, 0.5)`.

Новый интервал:

```text
L = 0.5 + 0.3 * 0.0 = 0.5
R = 0.5 + 0.3 * 0.5 = 0.65
```

Получили:

```text
[0.5, 0.65)
```

### Шаг 3: символ C

Текущий интервал:

```text
[0.5, 0.65)
```

Ширина:

```text
range = 0.15
```

Для `C` базовый интервал `[0.8, 1.0)`.

Новый интервал:

```text
L = 0.5 + 0.15 * 0.8 = 0.62
R = 0.5 + 0.15 * 1.0 = 0.65
```

Итог:

```text
[0.62, 0.65)
```

Любое число из этого интервала кодирует сообщение `BAC`. Например:

```text
code = 0.63
```

### Декодирование числа 0.63

Начинаем с `[0,1)`.

Нормализованное значение:

```text
value = (0.63 - 0) / 1 = 0.63
```

`0.63` попадает в интервал `B = [0.5, 0.8)`. Первый символ — `B`.

Сужаем интервал до `[0.5, 0.8)`.

Теперь:

```text
value = (0.63 - 0.5) / 0.3 = 0.433333...
```

`0.433...` попадает в `A = [0.0, 0.5)`. Второй символ — `A`.

Сужаем интервал до `[0.5, 0.65)`.

Теперь:

```text
value = (0.63 - 0.5) / 0.15 = 0.866666...
```

`0.866...` попадает в `C = [0.8, 1.0)`. Третий символ — `C`.

Восстановили:

```text
BAC
```

## Типичные ошибки / вопросы на экзамен

Типичные ошибки:

- считать, что каждый символ получает отдельный битовый код, как в Хаффмане;
- использовать закрытые интервалы и получать неоднозначность на границах;
- обновлять `L`, а потом использовать уже обновленный `L` для вычисления `R`;
- забывать передавать длину сообщения или символ конца;
- думать, что можно безопасно кодировать длинные сообщения через `double`;
- строить разные модели на кодере и декодере;
- не нормализовать `code` при декодировании;
- путать вероятность символа и ширину текущего подинтервала.

Вопросы на экзамен:

1. Чем арифметическое кодирование отличается от Хаффмана?
2. Почему сообщение можно представить одним числом?
3. Как строятся интервалы символов?
4. Как обновляются границы `L` и `R`?
5. Как декодер понимает первый символ?
6. Зачем нужна длина сообщения или `EOF`?
7. Почему нельзя полагаться на обычные вещественные числа?
8. Как связана длина итогового интервала с вероятностью сообщения?
9. Когда арифметическое кодирование лучше Хаффмана?
10. Что произойдет, если модель декодера отличается от модели кодера?

Короткие ответы:

- Хаффман кодирует символы отдельными целочисленными кодами, а арифметическое кодирование кодирует всю строку одним интервалом.
- Интервал после каждого символа сужается; итоговый интервал уникален для сообщения.
- Границы строятся по накопленным вероятностям.
- Декодирование идет через нормализацию числа внутри текущего интервала.
- Длина или `EOF` нужны, чтобы знать, когда остановиться.

## Дополнительно (доказательства идей, варианты)

### Связь с вероятностью сообщения

Если символы считаются независимыми, вероятность сообщения:

$$
P(x_1x_2\dots x_m)=\prod_{i=1}^{m}p(x_i)
$$

Арифметическое кодирование после всех шагов получает интервал именно такой ширины:

$$
R-L=\prod_{i=1}^{m}p(x_i)
$$

Чтобы указать число внутри интервала ширины `w`, нужно примерно:

$$
\lceil -\log_2 w \rceil
$$

бит.

Значит, длина кода примерно:

$$
-\log_2 P(message)
$$

Это и есть информационная стоимость сообщения.

### Адаптивная модель

В статической модели вероятности известны заранее и не меняются.

В адаптивной модели:

1. Кодер и декодер начинают с одинаковых начальных частот.
2. После каждого символа оба обновляют частоты.
3. Следующий символ кодируется уже новой моделью.

Плюс: не надо передавать таблицу частот целиком.

Минус: реализация сложнее, а ошибки синхронизации ломают декодирование.

### Символ конца

Если не передавать длину сообщения, добавляют специальный символ `EOF`.

Например:

```text
alphabet = {A, B, C, EOF}
```

Кодер кодирует:

```text
BAC EOF
```

Декодер останавливается, когда получает `EOF`.

### Реальная целочисленная реализация

На практике интервал хранят в виде целых чисел:

```text
low  = 0
high = 2^k - 1
```

При сужении интервала используются частоты, а не вещественные вероятности:

```text
range = high - low + 1
high = low + floor(range * cumHigh[x] / total) - 1
low  = low + floor(range * cumLow[x]  / total)
```

Когда старшие биты `low` и `high` совпадают, их можно вывести в поток. Это не меняет смысла интервала, но не дает числам стать слишком большими или слишком близкими.

### Сравнение с Хаффманом

Хаффман:

- проще;
- быстро декодируется по дереву;
- оптимален среди префиксных кодов;
- имеет целочисленные длины кодов символов.

Арифметическое кодирование:

- сложнее;
- кодирует всю строку как число;
- лучше использует дробные вероятности;
- может быть ближе к энтропии.

В современных алгоритмах сжатия часто используются идеи статистического кодирования, близкие к арифметическому кодированию, например range coding и ANS.

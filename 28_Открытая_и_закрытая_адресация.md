# 28. Открытая и закрытая адресация

## Проблема коллизий

Коллизия возникает, когда разные ключи дают один и тот же индекс:

```text
x != y, но h(x) = h(y)
```

Хеш-таблица должна уметь хранить оба ключа. Для этого используют методы разрешения коллизий.

Два основных подхода из лекции:

- закрытая адресация, или метод цепочек;
- открытая адресация.

## Закрытая адресация: метод цепочек

В закрытой адресации ячейка таблицы хранит не один элемент, а контейнер элементов с одинаковым хешем.

Обычно:

```text
table[i] = список ключей, у которых h(key) = i
```

В лекции подчеркивается:

- используются динамические структуры данных, например списки;
- исходная таблица может быть меньше числа входных данных;
- память выделяется по необходимости;
- метод менее чувствителен к типу ключей;
- выгоден при частом удалении;
- можно заменять список деревом или другой структурой.

## Пример `H(k) = k mod 11`

Нужно вставить:

```text
23, 1, 12, 34, 2, 5, 7, 121, 21, 11, 45
```

Считаем хеши:

```text
23  mod 11 = 1
1   mod 11 = 1
12  mod 11 = 1
34  mod 11 = 1
2   mod 11 = 2
5   mod 11 = 5
7   mod 11 = 7
121 mod 11 = 0
21  mod 11 = 10
11  mod 11 = 0
45  mod 11 = 1
```

Итоговая таблица цепочек:

```text
0: 121 -> 11
1: 23 -> 1 -> 12 -> 34 -> 45
2: 2
3: -
4: -
5: 5
6: -
7: 7
8: -
9: -
10: 21
```

Поиск `12`:

1. `h(12) = 1`.
2. Идем в цепочку `table[1]`.
3. Последовательно проверяем `23`, `1`, `12`.
4. Нашли.

Поиск `56`:

1. `h(56) = 1`.
2. Идем в цепочку `table[1]`.
3. Проверяем все элементы цепочки.
4. Цепочка закончилась, значит `56` нет.

Удаление: найти элемент в цепочке и переставить указатели.

## Сложность цепочек

Пусть:

```text
n = число элементов
m = размер таблицы
alpha = n / m
```

`alpha` - коэффициент загрузки.

При равномерном распределении средняя длина цепочки `alpha`, поэтому:

- поиск: `O(1 + alpha)`;
- вставка: `O(1)`, если не проверять дубликаты или хранить хвост;
- удаление: `O(1 + alpha)`.

В худшем случае все элементы попадают в одну цепочку:

```text
O(n)
```

Если вместо списка использовать дерево поиска, худший поиск внутри цепочки можно улучшить до `O(log n)`.

## Открытая адресация

В открытой адресации все элементы хранятся прямо в массиве таблицы.

Если ячейка занята, алгоритм исследует другие ячейки по некоторой последовательности.

Особенности из лекции:

- таблица фиксирована и непрерывна;
- нет списков и "висячих" ссылок;
- проще управление памятью;
- исследование ячеек обычно быстрее из-за локальности памяти;
- при высокой заполненности эффективность падает;
- удаление сложнее, чем в цепочках.

Методы исследования:

- последовательный;
- линейный;
- квадратичный;
- двойное хеширование;
- метод кукушки.

## Последовательное исследование

Частный случай линейного исследования с шагом `q = 1`:

```text
h(key, i) = (h(key) + i) mod m
```

Если ячейка занята, смотрим следующую, потом следующую и так далее.

Недостаток: образуются кластеры занятых ячеек. Чем больше кластер, тем чаще новые элементы в него попадают.

## Линейное исследование

Формула из лекции:

```text
h(key, i) = (h(key) + i * q) mod m
```

где `i` - номер попытки от `0` до `m-1`.

Чтобы пройти всю таблицу, `q` и `m` должны быть взаимно простыми.

Пример из лекции:

```text
h(x) = x mod 11
h(x, i) = (h(x) + 3i) mod 11
```

Так как `gcd(3, 11) = 1`, последовательность исследования может охватить всю таблицу. Поэтому при вставке лекционного набора удалось заполнить все 11 ячеек.

## Квадратичное исследование

Формула:

```text
h(key, i) = (h(key) + c1 * i + c2 * i^2) mod m
```

Часто берут:

```text
h(key, i) = (h(key) + i^2) mod m
```

Плюс: меньше первичная кластеризация, чем у линейного исследования.

Минус: не всегда гарантированно просматривает все ячейки. В лекции для `m = 11` и набора ключей показывается ситуация, когда элемент `45` не удается вставить даже при долгом переборе попыток. Решение - перехеширование.

## Двойное хеширование

Использует две независимые хеш-функции:

```text
h(key, i) = (h1(key) + i * h2(key)) mod m
```

Где:

- `h1` - начальная позиция;
- `h2` - шаг исследования, индивидуальный для ключа.

Требования к `h2`:

- не равно нулю;
- независимо от `h1`;
- взаимно просто с размером таблицы `m`.

Пример из лекции:

```text
h(key, i) = (h1(key) + i * h2(key)) mod 13
h1(key) = key mod 13
h2(key) = key mod 11 + 1
```

Для ключа `14`:

```text
h(14, 0) = 1
h(14, 1) = 5
h(14, 2) = 9
```

Если `9` свободна, вставляем туда.

Двойное хеширование обычно лучше распределяет попытки, чем линейное и квадратичное исследование.

## Удаление в открытой адресации

Удалять элемент простым очищением ячейки нельзя: поиск других элементов может остановиться слишком рано.

Два подхода из лекции:

### Флаг `deleted`

Ячейка помечается как удаленная:

- `insert` может использовать ее как свободную;
- `search` считает ее занятой и продолжает исследование дальше.

Плюс: просто.

Минус: много `deleted` ухудшает поиск, нужна периодическая перестройка.

### Восстановление свойств таблицы

После удаления элементы сдвигаются назад так, чтобы в цепочке исследования не было дыр.

Для линейного исследования это возможно, но аккуратно. Для двойного хеширования обычно требуется полное перехеширование оставшихся элементов.

Вывод из лекции: восстановление свойств таблицы после удаления дорого.

## Перехеширование

Перехеширование нужно, когда таблица становится слишком заполненной или структура коллизий ухудшается.

Из лекции:

- метод цепочек: когда добавлено примерно `4m/3` элементов;
- открытая адресация: когда таблица заполнена примерно на `m/2`.

Шаги:

1. Создать новую таблицу размера `2m`.
2. Сменить хеш-функцию под диапазон `0..2m-1`.
3. Последовательно перенести все элементы.

Перехеширование дорого в момент выполнения, но амортизированно поддерживает быстрые операции.

## Сравнение подходов

Закрытая адресация:

- проще удаление;
- может хранить больше элементов, чем размер таблицы;
- требует дополнительной памяти на списки или деревья;
- хуже локальность памяти.

Открытая адресация:

- все элементы внутри одного массива;
- хорошая локальность памяти;
- не требует указателей;
- чувствительна к заполненности;
- удаление и перехеширование сложнее.

## Ограничения

- Оценка `O(1)` является средней, а не худшей.
- Нужен контроль коэффициента загрузки.
- Для открытой адресации таблица не должна быть почти полной.
- Для линейного исследования важно выбирать шаг, взаимно простой с `m`.
- Для двойного хеширования важно, чтобы `h2` не давала нулевой или плохой шаг.

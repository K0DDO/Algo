# 07. Эйлеров цикл

## Введение

Эйлеров цикл - это цикл в графе, который проходит по каждому ребру ровно один раз и возвращается в стартовую вершину. Вершины при этом могут повторяться.

Классическая задача об эйлеровом цикле возникла из задачи о кёнигсбергских мостах. Именно она стала одним из исторических источников теории графов.

Главная особенность темы: для существования эйлерова цикла есть простые критерии через степени вершин, а сам цикл можно построить за линейное время алгоритмом Иерохольцера.

## Основные определения

Эйлеров путь - путь, который проходит по каждому ребру графа ровно один раз.

Эйлеров цикл - эйлеров путь, который начинается и заканчивается в одной вершине.

Для неориентированного графа степень вершины `deg(v)` - число инцидентных ей ребер.

Для ориентированного графа:

- `in(v)` - входящая степень;
- `out(v)` - исходящая степень.

## Условия существования

### Неориентированный граф

В неориентированном графе эйлеров цикл существует тогда и только тогда, когда:

1. Все вершины ненулевой степени лежат в одной компоненте связности.
2. Степень каждой вершины четная.

Изолированные вершины не мешают существованию эйлерова цикла по ребрам: они не должны быть посещены, потому что у них нет ребер.

Почему степени должны быть четными: каждый раз, когда цикл входит в вершину по одному ребру, он должен выйти из нее по другому. Ребра около вершины разбиваются на пары "вход-выход".

### Ориентированный граф

В ориентированном графе эйлеров цикл существует тогда и только тогда, когда:

1. Все вершины с ненулевой суммарной степенью лежат в одной компоненте слабой связности.
2. Для каждой вершины `in(v) = out(v)`.
3. Вершины с ребрами находятся в одной сильносвязной части относительно достижимости по направлению для маршрута. На практике для строгой проверки обычно проверяют сильную связность среди вершин ненулевой степени или запускают обходы в графе и обратном графе.

Ключевой экзаменационный факт: для ориентированного эйлерова цикла входящие и исходящие степени каждой вершины должны быть равны.

## Логика алгоритма Иерохольцера

Алгоритм Иерохольцера строит эйлеров цикл, постепенно "сшивая" циклы.

Идея:

1. Начать из любой вершины, у которой есть ребро.
2. Идти по еще не использованным ребрам, удаляя их из рассмотрения.
3. Так как степени четные, если мы вошли в вершину, то обычно можем из нее выйти, пока не вернемся в начало текущего цикла.
4. Если в построенном цикле есть вершина, из которой еще остались неиспользованные ребра, запускаем из нее новый цикл.
5. Вставляем новый цикл в старый.
6. Повторяем, пока не используем все ребра.

Удобная стековая реализация сразу строит ответ без явного сшивания.

## Псевдокод

Для неориентированного графа:

```text
stack = [start]
answer = []

while stack is not empty:
    v = stack.top()
    if у v есть неиспользованное ребро (v, to):
        удалить ребро (v, to) из графа
        stack.push(to)
    else:
        answer.push(v)
        stack.pop()

answer.reverse()
```

Для ориентированного графа отличие только в удалении дуги `v -> to`.

В неориентированном графе ребро нужно удалить из списка обеих вершин. Обычно каждому ребру дают идентификатор `id` и хранят `usedEdge[id]`, чтобы не удалять элементы из середины вектора.

## Структуры данных

Для алгоритма Иерохольцера чаще всего используют:

- списки смежности;
- массив указателей `ptr[v]`, который показывает, какие ребра из списка уже просмотрены;
- массив `usedEdge[id]` для неориентированного графа;
- стек текущего пути;
- список `answer` для итогового цикла;
- массивы `in[v]`, `out[v]` или `deg[v]` для проверки условий.

Для проверки связности:

- DFS или BFS по неориентированному графу;
- для ориентированного графа часто нужен обход исходного и обратного графа.

## Сложность

Алгоритм Иерохольцера работает за `O(E)`, если каждое ребро рассматривается константное число раз.

Проверка условий:

- подсчет степеней: `O(V + E)`;
- проверка связности через DFS/BFS: `O(V + E)`;
- построение цикла: `O(E)`.

Итого:

```text
время: O(V + E)
память: O(V + E)
```

Память нужна на хранение графа, стек, ответ и служебные массивы.

## Ограничения

Алгоритм не работает корректно, если предварительно не проверить условия существования. Он может построить цикл только по части ребер, если граф несвязный.

В неориентированном графе нельзя просто удалять ребро из одного списка смежности: нужно пометить обе копии одного ребра.

Для мультиграфов алгоритм сохраняется, но каждое ребро должно иметь отдельный идентификатор.

Петли учитываются особым образом: в неориентированном графе петля добавляет `2` к степени вершины.

## Применимость

Эйлеровы циклы применяются там, где нужно пройти все связи ровно один раз:

- построение маршрута уборочной машины или почтальона по улицам;
- проверка возможности нарисовать фигуру одним росчерком;
- задачи на восстановление последовательности по перекрытиям;
- сборка строк и ДНК-последовательностей через графы де Брейна;
- генерация обходов ребер в сетях.

Если задача говорит "пройти все ребра ровно один раз", почти всегда надо думать про Эйлера, а не про Гамильтона.

## Примеры

### Неориентированный граф

Пусть есть цикл:

```text
1 - 2 - 3 - 4 - 1
```

Степени всех вершин равны `2`, граф связен. Значит, эйлеров цикл существует:

```text
1 -> 2 -> 3 -> 4 -> 1
```

Если добавить ребро `1 - 3`, степени станут:

```text
deg(1) = 3
deg(2) = 2
deg(3) = 3
deg(4) = 2
```

Вершины `1` и `3` имеют нечетную степень, поэтому эйлерова цикла нет.

### Ориентированный граф

Пусть дуги:

```text
1 -> 2
2 -> 3
3 -> 1
```

Для каждой вершины `in = out = 1`, граф связен по направлению на вершинах с ребрами. Эйлеров цикл:

```text
1 -> 2 -> 3 -> 1
```

## Типичные ошибки

- Проверять только четность степеней и забывать про связность.
- Путать эйлеров цикл с гамильтоновым.
- В ориентированном графе проверять только суммарные степени вместо `in(v) = out(v)`.
- Удалять неориентированное ребро только из одного списка смежности.
- Возвращать ответ в обратном порядке при стековой реализации.
- Считать изолированные вершины препятствием для эйлерова цикла.

# 12. Кратчайшие пути в DAG

## Введение

DAG - это ориентированный ациклический граф. В таком графе нет ориентированных циклов, поэтому вершины можно упорядочить топологически: для каждой дуги `u -> v` вершина `u` стоит раньше `v`.

Кратчайшие пути в DAG находятся быстрее, чем в общем графе. Достаточно сделать топологическую сортировку, а затем один раз пройти вершины в топологическом порядке и выполнить релаксации исходящих ребер.

Ключевой факт: алгоритм использует топосорт + одну релаксацию ребер в топологическом порядке.

## Почему DAG особенный

В обычном графе путь может возвращаться к уже обработанным вершинам через циклы. Поэтому алгоритмам приходится многократно уточнять расстояния или использовать жадные свойства.

В DAG циклов нет. Если вершина `u` стоит раньше `v` в топологическом порядке, то после обработки всех вершин до `v` расстояние до `v` уже окончательно учитывает все возможные входящие пути.

Из-за этого достаточно одного прохода по вершинам.

## Логика алгоритма

1. Проверить, что граф ациклический, или сразу построить топологический порядок.
2. Инициализировать расстояния:
   - `dist[source] = 0`;
   - остальные `dist[v] = INF`.
3. Перебирать вершины в топологическом порядке.
4. Для текущей вершины `u`, если `dist[u] != INF`, релаксировать все исходящие ребра `u -> v`.
5. После прохода массив `dist` содержит кратчайшие расстояния от источника.

Алгоритм работает даже с отрицательными весами, потому что отрицательных циклов в DAG быть не может: циклов нет вообще.

## Топологическая сортировка

Топологический порядок можно получить:

- DFS с добавлением вершины в ответ после обработки всех потомков и последующим разворотом списка;
- алгоритмом Кана через входящие степени;
- алгоритмом Демукрона, если он рассматривается в лекциях.

DFS-вариант:

```text
dfs(u):
    visited[u] = true
    for v in g[u]:
        if not visited[v]:
            dfs(v)
    order.push(u)

после всех DFS:
order.reverse()
```

Для DAG верно: если есть дуга `u -> v`, то `u` будет раньше `v`.

## Псевдокод кратчайших путей

```text
order = topologicalSort(G)

dist = array[V] filled with INF
parent = array[V] filled with -1
dist[source] = 0

for u in order:
    if dist[u] == INF:
        continue

    for (v, w) in g[u]:
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
            parent[v] = u
```

Для восстановления пути до `target` идем по `parent[target]`, пока не придем в `source`.

## Структуры данных

Нужны:

- список смежности `g[u]`, элементы `(v, weight)`;
- массив `visited` или цвета для DFS-топосорта;
- список `order`;
- массив `dist`;
- массив `parent`;
- при алгоритме Кана - массив `indegree[v]` и очередь.

Если надо проверять ацикличность через DFS, удобно использовать цвета:

- `white` - не посещена;
- `gray` - находится в стеке рекурсии;
- `black` - полностью обработана.

Ребро в серую вершину означает цикл.

## Сложность

Топологическая сортировка:

```text
O(V + E)
```

Один проход релаксаций:

```text
O(V + E)
```

Итого:

```text
время: O(V + E)
память: O(V + E)
```

Дополнительная память сверх графа: `O(V)` на `dist`, `parent`, `visited`, `order`.

## Ограничения

Алгоритм применим только к ориентированным ациклическим графам.

Если в графе есть цикл, топологического порядка не существует, и логика одного прохода ломается.

Отрицательные веса разрешены, но только потому, что нет циклов. Если граф не DAG, отрицательные веса требуют других алгоритмов, например Беллмана-Форда.

Если вершина недостижима из источника, ее расстояние останется `INF`.

## Применимость

Кратчайшие пути в DAG полезны в задачах:

- расписания и зависимости работ;
- динамическое программирование на графе состояний;
- вычисление критического пути;
- графы компиляции и зависимостей;
- ориентированные ациклические сети.

Часто DAG возникает неявно: состояние может переходить только "вперед" по времени, индексу, количеству выбранных элементов или уровню.

## Примеры

### Пример из лекции (Теория графов III–IV)

Матрица весов \(W\) (строка → столбец), вершины \(1..5\):

```text
     1    2    3    4    5
1   inf   2   inf  -1   inf
2   inf  inf  inf  inf  inf
3    6   inf  inf  inf   2
4   inf  -2   inf  inf  inf
5    7    2   inf   4   inf
```

Топологический порядок (например, алгоритм Демукрона / DFS): `3, 5, 1, 4, 2`.

Старт = `3`:

1. Из 3 релаксируем рёбра к 5 и 1.
2. Из 5 — к 1, 4, 2.
3. Из 1 — к 4 и 2.
4. Из 4 — к 2.

Итог: `d(1)=6, d(2)=3, d(3)=0, d(4)=5, d(5)=2`.

Если старт = `5`, в том же топопорядке релаксируем только начиная с 5: вершина 3 остаётся `inf` (в DAG нет пути «назад»). Итог: `d(1)=7, d(2)=2, d(3)=∞, d(4)=4, d(5)=0`.

### Короткий пример

Пусть вершины уже упорядочены топологически:

```text
1, 2, 3, 4
```

Рёбра:

```text
1 -> 2 (3)
1 -> 3 (2)
2 -> 4 (4)
3 -> 4 (-1)
```

Старт `1` → ответ `dist[4] = 1`, путь `1 -> 3 -> 4`.

## Связь с динамическим программированием

Алгоритм кратчайших путей в DAG можно воспринимать как DP:

```text
dist[v] = min(dist[u] + w(u, v)) по всем входящим ребрам u -> v
```

Топологический порядок гарантирует, что когда мы считаем `dist[v]`, все нужные `dist[u]` уже готовы.

Именно поэтому многие задачи динамического программирования можно представить как поиск кратчайшего или длиннейшего пути в DAG.

## Типичные ошибки

- Применять алгоритм к графу с циклами.
- Забыть сделать топологическую сортировку.
- Обрабатывать вершины в произвольном порядке.
- Не проверять `dist[u] != INF` перед релаксацией.
- Считать, что отрицательные ребра запрещены.
- Путать DAG shortest paths с Дейкстрой.

# A4. Ахо-Корасик

## Задача

Дан текст `T` и множество шаблонов:

```text
P1, P2, ..., Pq
```

Нужно найти позиции всех вхождений всех шаблонов в текст.

Если запускать КМП отдельно для каждого шаблона, получится:

```text
O(sum |P_i| + q * |T|)
```

Ахо-Корасик обрабатывает текст один раз:

```text
O(sum |P_i| + |T| + result)
```

где `result` - число найденных вхождений.

## Главная идея

КМП строит автомат для одного образца. Ахо-Корасик строит автомат для множества образцов.

Основа автомата:

1. Строим бор всех шаблонов.
2. Добавляем суффиксные ссылки.
3. Добавляем автоматные переходы `go(v, c)`.
4. Добавляем терминальные, или выходные, ссылки для быстрого вывода совпадений.

В лекции это формулируется так: бор сам по себе не является автоматом, но его переходы являются частью автоматных переходов; кроме них нужны ссылки, которые позволяют откатываться как в КМП.

## Бор шаблонов

Каждая вершина бора соответствует некоторому префиксу одного или нескольких шаблонов.

В вершине храним:

- переходы `trie[v][c]`;
- признак терминальности;
- список id шаблонов, которые заканчиваются в этой вершине;
- суффиксную ссылку `suf[v]`;
- выходную ссылку `out[v]`;
- автоматные переходы `go[v][c]`.

Пример из лекции:

```text
patterns = {a, abac, acb, caba}
```

Все шаблоны складываются в один бор. Если текстовый префикс совпал с путем в боре, мы находимся в соответствующей вершине.

## Состояние автомата

Состояние `v` - это самая длинная строка из бора, которая является суффиксом уже прочитанной части текста.

Например, если прочитанный текст заканчивается на `abac`, и такой путь есть в боре, состояние соответствует вершине `abac`.

Если следующий символ не продолжает путь в боре, нужно перейти к более короткому суффиксу, как КМП делает откат через префикс-функцию.

## Суффиксная ссылка

Определение из лекции:

```text
suf(v) - самая глубокая вершина, соответствующая суффиксу строки v,
         причем suf(v) != v
```

Если подходящего суффикса нет, ссылка ведет в корень.

Корень соответствует пустой строке.

По смыслу суффиксная ссылка в Ахо-Корасике - аналог префикс-функции, но не для одной строки, а для множества строк в боре.

## Как вычислять суффиксные ссылки

Пусть вершина `v` получена из родителя `p` по символу `c`.

Тогда:

```text
suf(v) = go(suf(p), c)
```

Для детей корня суффиксная ссылка ведет в корень.

Ссылки строят BFS, потому что для вершины нужно, чтобы ссылка ее родителя уже была посчитана.

Наивная логика из лекции:

```text
k = suf(parent(v))
while k != root and trie[k][c] отсутствует:
    k = suf(k)
if trie[k][c] существует:
    suf(v) = trie[k][c]
else:
    suf(v) = root
```

Умная формула через `go` убирает повторяющийся `while`.

## Автоматный переход `go(v, c)`

Определение:

```text
go(v, c) - состояние после чтения символа c из состояния v
```

Правила:

```text
если есть переход trie(v, c):
    go(v, c) = trie(v, c)
иначе:
    go(v, c) = go(suf(v), c)
```

Для корня, если перехода нет:

```text
go(root, c) = root
```

Смысл: если текущий префикс не продолжился, пробуем самый длинный подходящий суффикс.

## Терминальные и выходные ссылки

При проходе по автомату недостаточно проверять только текущую вершину.

Например, если шаблоны:

```text
he, she, hers
```

и мы пришли в вершину `she`, то одновременно найден шаблон `he`, потому что `he` - суффикс `she`.

Чтобы не идти каждый раз по всей цепочке суффиксных ссылок, строят терминальную, или выходную, ссылку:

```text
out(v) = ближайшая терминальная вершина на пути по suf-ссылкам
```

Из лекции:

```text
если suf(v) терминальная:
    out(v) = suf(v)
иначе:
    out(v) = out(suf(v))
```

Если терминальной вершины нет, `out(v) = none`.

При матчинге:

1. Переходим по `go`.
2. Проверяем текущую вершину.
3. Идем по цепочке `out`, выводя все шаблоны.

## Построение автомата

Общий план:

1. Создать корень.
2. Добавить все шаблоны в бор, пометить терминальные вершины.
3. Запустить BFS от корня.
4. Для каждой вершины:
   - посчитать `suf`;
   - посчитать `out`;
   - заполнить или отложить `go`.

Псевдокод для плотного алфавита:

```text
build(patterns):
    root.suf = root
    queue = children(root)

    for child of root:
        child.suf = root

    while queue not empty:
        v = pop(queue)

        for c in alphabet:
            if trie[v][c] exists:
                u = trie[v][c]
                u.suf = go[v.suf][c]

                if u.suf is terminal:
                    u.out = u.suf
                else:
                    u.out = u.suf.out

                push(u)
            else:
                go[v][c] = go[v.suf][c]
```

В реализации с ленивыми переходами `go(v, c)` можно считать рекурсивно и мемоизировать.

## Матчинг текста

```text
search(T):
    v = root
    for i = 0..len(T)-1:
        v = go(v, T[i])

        if v is terminal:
            output patterns ending at i

        u = out(v)
        while u != none:
            output patterns ending at i
            u = out(u)
```

Если в терминальной вершине хранится id шаблона и его длина, начало вхождения:

```text
start = i - len(pattern) + 1
```

## Сложность

Пусть:

```text
M = sum |P_i|
A = размер алфавита
R = число найденных вхождений
```

Построение бора:

```text
O(M)
```

Построение суффиксных и выходных ссылок:

```text
O(M)
```

Если заранее строить все автоматные переходы для плотного алфавита:

```text
O(M * A)
```

Если переходы считать лениво или хранить только существующие:

```text
O(M) или O(M log A) в зависимости от структуры переходов
```

Поиск:

```text
O(|T| + R)
```

В лекции отмечен крайний случай:

```text
T = aaaaa...
P = {a, aa, aaa, ...}
```

Тогда ответов очень много, поэтому сложность обязана содержать `+ result`.

## Структуры данных

Для каждой вершины:

```text
next: переходы бора
go: автоматные переходы
suf: суффиксная ссылка
out: выходная ссылка
terminal: bool
ids: список шаблонов, заканчивающихся здесь
parent, parent_char: удобно для построения
```

Способы хранения переходов:

- массив, если алфавит маленький;
- `map`, если нужен порядок;
- `unordered_map`, если алфавит большой и нужен средний `O(1)`.

## Связь с КМП

КМП:

- один шаблон;
- состояние - длина совпавшего префикса;
- откат через `pi`.

Ахо-Корасик:

- много шаблонов;
- состояние - вершина бора;
- откат через `suf`;
- выход через `out`.

Поэтому Ахо-Корасик можно воспринимать как обобщение автомата КМП на множество строк.

## Ограничения

- Для очень большого алфавита таблица `go[v][c]` может быть слишком большой.
- При огромном числе совпадений вывод ответа может доминировать по времени.
- Если шаблоны динамически добавляются и удаляются, классический автомат приходится перестраивать или усложнять.
- Реализация требует аккуратной обработки терминальных ссылок, иначе будут пропущены шаблоны, являющиеся суффиксами других шаблонов.

## Применимость

- Поиск множества слов в тексте.
- Антивирусные сигнатуры.
- Фильтрация запрещенных слов.
- Биоинформатика.
- Поисковые системы.
- Лексический анализ.
- Поиск словаря шаблонов в потоке.

## Типичные ошибки

- Проверять только текущую терминальную вершину и забыть выходные ссылки.
- Строить суффиксные ссылки DFS без гарантии, что ссылка родителя уже готова.
- Для детей корня не поставить `suf = root`.
- Не обработать отсутствующий переход из корня как переход в корень.
- Не хранить длины шаблонов, из-за чего нельзя восстановить начало вхождения.
- Считать сложность поиска `O(|T|)`, забыв про `+ result`.

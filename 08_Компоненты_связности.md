# 08. Компоненты связности в неориентированном графе

## Введение

Компонента связности в неориентированном графе - это максимальное множество вершин, между любыми двумя из которых существует путь.

Если граф связный, у него одна компонента связности. Если несвязный, его можно разложить на несколько независимых частей. Поиск компонент связности - одна из базовых задач на DFS и BFS.

В лекциях эта тема появляется рядом с обходами графа: после одного запуска DFS/BFS мы находим все вершины, достижимые из стартовой. Если после этого остались непосещенные вершины, запускаем обход из одной из них и получаем следующую компоненту.

## Логика алгоритма

Обход из вершины `s` посещает ровно те вершины, которые лежат с `s` в одной компоненте связности.

Поэтому алгоритм такой:

1. Заводим массив `visited` или массив `component`.
2. Перебираем все вершины графа.
3. Если вершина еще не посещена, начинаем из нее DFS или BFS.
4. Все вершины, найденные этим обходом, получают один номер компоненты.
5. Увеличиваем номер компоненты и продолжаем внешний цикл.

Ключевой факт: компоненты можно искать и DFS, и BFS. Сложность при списках смежности одинаковая: `O(V + E)`.

## DFS-реализация

Псевдокод:

```text
component = array[V] filled with 0
count = 0

for v in V:
    if component[v] == 0:
        count += 1
        dfs(v, count)

dfs(u, count):
    component[u] = count
    for to in g[u]:
        if component[to] == 0:
            dfs(to, count)
```

Массив `component` одновременно заменяет `visited`: если `component[v] == 0`, вершина еще не посещена; иначе она уже отнесена к некоторой компоненте.

## BFS-реализация

Псевдокод:

```text
component = array[V] filled with 0
count = 0

for s in V:
    if component[s] == 0:
        count += 1
        queue.push(s)
        component[s] = count

        while queue is not empty:
            u = queue.pop()
            for v in g[u]:
                if component[v] == 0:
                    component[v] = count
                    queue.push(v)
```

BFS удобен, если дополнительно нужны расстояния в невзвешенном графе. DFS часто проще записывать рекурсивно.

## Слабая связность

Для ориентированного графа есть понятие слабой связности. Компоненты слабой связности ищутся как компоненты связности в неориентированной версии графа.

То есть для каждой дуги `u -> v` во вспомогательном графе считаем, что есть неориентированное ребро `u - v`, и запускаем обычный DFS/BFS.

Это ровно идея из лекций: для слабой связности используется вспомогательный неориентированный граф и обход по нему с пометкой вершин соответствующими компонентами исходного графа.

## Структуры данных

Основные структуры:

- список смежности `g[v]`;
- массив `component[v]`;
- очередь для BFS или стек/рекурсия для DFS;
- счетчик `count`, номер текущей компоненты.

Можно использовать матрицу смежности, но для разреженных графов она хуже по памяти и может ухудшить время обхода до `O(V^2)`.

Для слабой связности ориентированного графа можно:

- построить отдельный неориентированный список смежности;
- или при чтении каждой дуги `u -> v` сразу добавить `v` в `g[u]` и `u` в `g[v]` для задачи слабой связности.

## Сложность

При списке смежности:

```text
время: O(V + E)
память: O(V + E)
```

Почему время линейное:

- каждая вершина получает номер компоненты один раз;
- каждое ребро в неориентированном графе просматривается с двух концов;
- сумма степеней равна `2E`.

Дополнительная память:

- `component`: `O(V)`;
- очередь BFS или стек DFS: `O(V)`;
- сам граф: `O(V + E)`.

Для слабой связности, если строится отдельная неориентированная версия ориентированного графа, нужна дополнительная память `O(V + E)`.

## Ограничения

Рекурсивный DFS может переполнить стек на больших графах. В таких случаях лучше использовать итеративный DFS или BFS.

Если граф хранится матрицей смежности, обход всех соседей одной вершины стоит `O(V)`, поэтому общая сложность становится `O(V^2)`.

Для ориентированного графа нельзя путать слабую связность и сильную связность. Слабая связность игнорирует направления ребер, сильная требует достижимости по направлениям.

## Применимость

Компоненты связности нужны для:

- проверки, связен ли граф;
- разбиения задачи на независимые части;
- предварительной проверки перед алгоритмами, которым нужна связность;
- анализа сетей, карт, дорог, социальных графов;
- поиска островов в двумерной сетке;
- проверки существования эйлерова цикла в неориентированном графе.

Во многих задачах после нахождения компонент можно решать подзадачу отдельно на каждой компоненте.

## Примеры

Пусть:

```text
V = {1, 2, 3, 4, 5, 6}
E = {(1,2), (2,3), (4,5)}
```

Списки смежности:

```text
1: 2
2: 1, 3
3: 2
4: 5
5: 4
6:
```

Запускаем DFS:

1. Из вершины `1` посещаем `1, 2, 3`, присваиваем компоненту `1`.
2. Вершины `2` и `3` уже отмечены.
3. Из вершины `4` посещаем `4, 5`, присваиваем компоненту `2`.
4. Вершина `6` изолирована, получает компоненту `3`.

Итог:

```text
component[1] = 1
component[2] = 1
component[3] = 1
component[4] = 2
component[5] = 2
component[6] = 3
```

Всего `3` компоненты связности.

## Типичные ошибки

- Запустить DFS только один раз и забыть внешний цикл по всем вершинам.
- Использовать только `visited`, хотя в задаче нужен номер компоненты.
- Путать компоненты связности неориентированного графа и компоненты сильной связности ориентированного.
- Для слабой связности не добавить обратные ребра.
- Не учитывать изолированные вершины: каждая из них является отдельной компонентой.

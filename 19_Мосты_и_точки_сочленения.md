# 19. Мосты и точки сочленения

## 1. Общая идея

Мосты и точки сочленения описывают уязвимые места в неориентированном графе.

Мост - это ребро, удаление которого увеличивает число компонент связности.

Точка сочленения - это вершина, удаление которой вместе со всеми инцидентными ребрами увеличивает число компонент связности.

Интуитивно:

- мост - "единственная дорога" между частями графа;
- точка сочленения - "перекресток", через который соединяются несколько частей графа.

## 2. Где применяется

Такие алгоритмы нужны для анализа надежности сетей:

- дороги и мосты между городами;
- компьютерные сети;
- социальные графы;
- зависимости в системах;
- графы переходов;
- проверка, какие элементы являются критическими.

Если мост удалить, граф развалится на большее число компонент.

Если точку сочленения удалить, часть графа может стать недостижимой из другой части.

## 3. DFS-дерево

Алгоритм строится на обходе в глубину.

Когда запускаем DFS в неориентированном графе, ребра условно делятся на:

- древесные ребра - по ним DFS впервые входит в новую вершину;
- обратные ребра - ведут из вершины или ее потомка к уже посещенному предку.

В неориентированном графе нет перекрестных ребер в обычном DFS для одной компоненты: если ребро ведет в уже посещенную вершину и это не ребро к родителю, то оно связывает вершину с предком или уже обработанной частью, что для low-link логики учитывается как обратное.

## 4. Времена входа `tin`

Для каждой вершины `v` запоминаем время входа:

```text
tin[v]
```

Это номер момента, когда DFS впервые зашел в `v`.

Например:

```text
timer = 0
dfs(v):
    tin[v] = timer
    timer += 1
```

Чем меньше `tin[v]`, тем раньше вершина была открыта.

Иногда дополнительно хранят `tout[v]` - время выхода из вершины. Для поиска мостов и точек сочленения обычно достаточно `tin` и `up` / `low`. Но `tout` полезен для проверки отношения "предок-потомок" в DFS-дереве:

```text
u является предком v <=> tin[u] <= tin[v] and tout[v] <= tout[u]
```

## 5. Значение `up` или `low`

Обычно используется массив:

```text
up[v]
```

или:

```text
low[v]
```

Это одно и то же по смыслу.

`up[v]` - минимальное `tin` вершины, в которую можно попасть из поддерева `v`, используя:

- ноль или несколько древесных ребер вниз;
- и не более одного обратного ребра вверх.

Формально:

```text
up[v] = min(
    tin[v],
    tin[to] для обратных ребер v -> to,
    up[child] для детей child в DFS-дереве
)
```

Интуитивно `up[v]` отвечает на вопрос:

> насколько высоко в DFS-дереве может "зацепиться" поддерево вершины `v`, не используя ребро к родителю?

## 6. Как считать `up`

DFS по неориентированному графу:

```text
dfs(v, parent):
    visited[v] = true
    tin[v] = up[v] = timer
    timer += 1

    for to in g[v]:
        if to == parent:
            continue

        if visited[to]:
            up[v] = min(up[v], tin[to])
        else:
            dfs(to, v)
            up[v] = min(up[v], up[to])
```

Но есть важная тонкость для мультиграфа: если между `v` и `parent` несколько ребер, нельзя просто пропускать все `to == parent`, иначе можно потерять обратное ребро к родителю. Надежнее хранить идентификатор ребра и пропускать только ребро, по которому пришли:

```text
dfs(v, parent_edge_id):
    for edge in g[v]:
        if edge.id == parent_edge_id:
            continue
```

## 7. Критерий моста

Пусть `v` - вершина, а `to` - ее ребенок в DFS-дереве. То есть ребро `(v, to)` является древесным.

Ребро `(v, to)` - мост тогда и только тогда, когда:

```text
up[to] > tin[v]
```

### Почему

`up[to]` показывает, может ли поддерево `to` добраться до `v` или какого-то предка `v` по обратному ребру.

Если:

```text
up[to] <= tin[v]
```

то из поддерева `to` есть обходной путь наверх. Удаление ребра `(v, to)` не разорвет связность между поддеревом и остальным графом.

Если:

```text
up[to] > tin[v]
```

то поддерево `to` не может добраться ни до `v`, ни до предков `v` без ребра `(v, to)`. Значит это ребро - единственная связь поддерева с остальным графом. Оно является мостом.

## 8. Пример для мостов

Граф:

```text
1 - 2 - 3
    |
    4
```

Если в графе нет дополнительных ребер, то все ребра являются мостами:

```text
(1, 2)
(2, 3)
(2, 4)
```

Удаление любого из них увеличивает число компонент.

Теперь добавим ребро:

```text
3 - 4
```

Получится цикл:

```text
2 - 3 - 4 - 2
```

Теперь ребра `(2, 3)`, `(3, 4)`, `(4, 2)` не являются мостами, потому что внутри цикла есть обходной путь.

Но ребро `(1, 2)` все еще мост.

DFS-критерий отразит это так:

- для поддерева с вершинами `3` и `4` значение `up` сможет подняться к `2`;
- для вершины `2` относительно родителя `1` обхода к `1` нет.

## 9. Критерий точки сочленения

Критерии отличаются для корня DFS и для не-корня.

### 9.1. Вершина не является корнем DFS

Пусть `v` - не корень DFS-дерева.

`v` является точкой сочленения, если существует ребенок `to` такой, что:

```text
up[to] >= tin[v]
```

### Почему здесь `>=`, а для моста было `>`

Для моста проверяем ребро `(v, to)`. Если `up[to] == tin[v]`, значит из поддерева `to` есть обратное ребро в саму вершину `v`. Тогда удаление ребра `(v, to)` не разрывает связь, потому что есть другой путь к `v`.

Для точки сочленения удаляется сама вершина `v`. Если поддерево `to` может добраться только до `v`, но не выше, то после удаления `v` оно оторвется.

Поэтому условие:

```text
up[to] >= tin[v]
```

### 9.2. Корень DFS

Корень DFS-дерева является точкой сочленения тогда и только тогда, когда у него хотя бы два ребенка в DFS-дереве.

```text
root_children >= 2
```

Почему:

- у корня нет родителя и предков;
- если DFS из корня породил два независимых поддерева, между ними нет ребра, которое позволило бы DFS попасть из одного поддерева в другое напрямую;
- при удалении корня эти поддеревья станут разными компонентами.

Если у корня только один ребенок, удаление корня не разделяет уже найденную компоненту: все остальные вершины лежат в одном DFS-поддереве.

## 10. Псевдокод для мостов и точек сочленения

```text
timer = 0
visited = [false] * n
tin = [0] * n
up = [0] * n
is_cutpoint = [false] * n
bridges = []

dfs(v, parent_edge_id):
    visited[v] = true
    tin[v] = up[v] = timer
    timer += 1
    children = 0

    for edge in g[v]:
        to = edge.to

        if edge.id == parent_edge_id:
            continue

        if visited[to]:
            up[v] = min(up[v], tin[to])
        else:
            dfs(to, edge.id)
            up[v] = min(up[v], up[to])

            if up[to] > tin[v]:
                bridges.append((v, to))

            if parent_edge_id != -1 and up[to] >= tin[v]:
                is_cutpoint[v] = true

            children += 1

    if parent_edge_id == -1 and children >= 2:
        is_cutpoint[v] = true

for v in 0..n-1:
    if not visited[v]:
        dfs(v, -1)
```

## 11. Почему нужно запускать DFS из всех вершин

Граф может быть несвязным.

Если запустить DFS только из вершины `0`, будут обработаны только вершины ее компоненты связности.

Поэтому внешний цикл:

```text
for v in vertices:
    if not visited[v]:
        dfs(v, -1)
```

Каждая компонента получит свой DFS-корень.

## 12. Сложность

DFS посещает:

- каждую вершину один раз;
- каждое ребро в неориентированном графе два раза: из `u` в `v` и из `v` в `u`.

Сложность:

```text
O(V + E)
```

Память:

```text
O(V + E)
```

где:

- `O(E)` - списки смежности;
- `O(V)` - массивы `visited`, `tin`, `up`, `is_cutpoint`;
- `O(V)` - стек рекурсии DFS в худшем случае.

## 13. Структуры данных

Для простого графа:

```text
g[v] = список соседей
```

Для мультиграфа лучше:

```text
Edge:
    to
    id
```

и:

```text
g[v] = список Edge
```

Массивы:

- `visited[v]`;
- `tin[v]`;
- `up[v]` или `low[v]`;
- `is_cutpoint[v]`;
- список `bridges`.

Если нужно вывести мосты в исходной нумерации, надо хранить `id` ребра.

## 14. Ограничения и применимость

Алгоритм предназначен для неориентированных графов.

Для ориентированных графов понятия и алгоритмы другие:

- сильная связность;
- компоненты сильной связности;
- сильные мосты и сильные точки сочленения требуют других методов.

Петли:

- петля не является мостом;
- петля обычно не влияет на `up`, потому что ведет из вершины в саму себя.

Кратные ребра:

- два параллельных ребра между одними и теми же вершинами означают, что ни одно из них по отдельности не является мостом;
- поэтому важно пропускать только родительское ребро по `id`, а не все ребра к родителю.

## 15. Типичные ошибки

1. Использовать условие `up[to] >= tin[v]` для мостов.
   Для мостов нужно строго:

```text
up[to] > tin[v]
```

2. Использовать условие `up[to] > tin[v]` для точек сочленения.
   Для не-корня нужно:

```text
up[to] >= tin[v]
```

3. Не выделять особый случай корня DFS.
   Корень - точка сочленения только при двух и более DFS-детях.

4. Пропускать все ребра к родителю в мультиграфе.
   Это ломает обработку параллельных ребер.

5. Не запускать DFS из всех компонент.
   Тогда часть мостов и точек сочленения не будет найдена.

## 16. Короткая памятка

Для древесного ребра `v -> to`:

```text
bridge if up[to] > tin[v]
```

Для вершины `v`, не являющейся корнем:

```text
cutpoint if exists child to: up[to] >= tin[v]
```

Для корня:

```text
cutpoint if root has at least 2 DFS children
```

Сложность:

```text
O(V + E)
```

Главный смысл `up[to]`: может ли поддерево `to` добраться до вершины `v` или выше без использования ребра DFS-дерева к родителю.

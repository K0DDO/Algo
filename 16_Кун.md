# 16. Алгоритм Куна: максимальное паросочетание в двудольном графе

## 1. Задача

Дан двудольный граф:

- левая доля `L`;
- правая доля `R`;
- ребра идут только между `L` и `R`;
- ребро `(l, r)` означает, что вершину `l` можно сопоставить с вершиной `r`.

Нужно найти паросочетание максимального размера.

Паросочетание `M` - это множество ребер, такое что никакие два ребра из `M` не имеют общей вершины.

Пример из лекции:

- слева студенты;
- справа дипломные проекты;
- ребро означает, что студенту интересен проект;
- нужно назначить максимум студентов на интересные им проекты так, чтобы один проект не достался двум студентам.

То есть паросочетание - это назначение без конфликтов.

## 2. Основные определения

### Свободная вершина

Вершина называется свободной относительно текущего паросочетания `M`, если она не инцидентна ни одному ребру из `M`.

Если вершина уже покрыта ребром паросочетания, то она занята.

### Чередующаяся цепь

Чередующаяся цепь - это путь, в котором ребра попеременно:

- не входят в текущее паросочетание `M`;
- входят в текущее паросочетание `M`;
- снова не входят в `M`;
- и так далее.

В лекции приводился пример чередующейся цепи:

```text
1 - 8 - 4 - 6 - 3 - 7
```

На таком пути свободные ребра и ребра из `M` чередуются.

### Увеличивающая цепь

Увеличивающая цепь - это чередующаяся цепь, которая начинается и заканчивается свободными вершинами.

В двудольном графе для алгоритма Куна удобно искать такую цепь:

```text
свободная вершина L -> ... -> свободная вершина R
```

Если увеличивающая цепь найдена, можно сделать инверсию:

- ребра пути, которые не были в `M`, добавить в `M`;
- ребра пути, которые были в `M`, удалить из `M`.

Так как путь начинается и заканчивается свободными вершинами, свободных ребер на нем на одно больше, чем занятых. Поэтому после инверсии размер паросочетания увеличивается ровно на `1`.

## 3. Теорема Бержа

Теорема Бержа:

> Паросочетание `M` максимально тогда и только тогда, когда относительно `M` не существует увеличивающей цепи.

### Почему если есть увеличивающая цепь, то `M` не максимально

Пусть есть увеличивающая цепь. На ней ребра чередуются:

```text
не в M, в M, не в M, в M, ..., не в M
```

После инверсии:

- все ребра `не в M` становятся ребрами паросочетания;
- все ребра `в M` удаляются.

Так как цепь начинается и заканчивается свободными вершинами, добавленных ребер на одно больше, чем удаленных. Значит можно получить паросочетание размера `|M| + 1`. Следовательно, исходное `M` не было максимальным.

### Почему если увеличивающей цепи нет, то `M` максимально

Идея доказательства из лекции:

1. Предположим, что `M` не максимально.
2. Тогда существует истинное максимальное паросочетание `M'`, где `|M'| > |M|`.
3. Рассмотрим симметрическую разность `M xor M'`: ребра, которые входят ровно в одно из двух паросочетаний.
4. Эта разность распадается на чередующиеся цепи и циклы.
5. В циклах количество ребер из `M` и `M'` одинаково.
6. Так как `M'` больше, должна существовать цепь, где ребер из `M'` на одно больше, чем ребер из `M`.
7. Такая цепь является увеличивающей относительно `M`.

Получили противоречие: увеличивающих цепей нет, но одна должна существовать. Значит `M` максимально.

## 4. Идея алгоритма Куна

Алгоритм Куна применим к двудольному графу. Он постепенно строит паросочетание и каждый раз пытается увеличить его на `1`.

Базовая идея из лекции:

1. Изначально паросочетание пустое.
2. Для каждой вершины левой доли запускаем DFS.
3. DFS пытается найти увеличивающую цепь до свободной вершины правой доли.
4. Если цепь найдена, ребра на ней разворачиваются.
5. После обработки всех вершин левой доли получаем максимальное паросочетание.

Почему стартуем из левой доли:

- двудольный граф имеет стороны `L` и `R`;
- обычно храним для каждой правой вершины, с какой левой она сейчас сматчена;
- попытка из `l in L` отвечает на вопрос: можно ли подобрать пару для `l`, возможно вытеснив другие левые вершины по увеличивающей цепи.

## 5. Ориентация ребер и смысл DFS

Можно думать так:

- свободные ребра направлены слева направо;
- ребра текущего паросочетания можно пройти обратно справа налево.

Тогда увеличивающая цепь - это ориентированный путь:

```text
свободная L -> R -> занятая L -> R -> ... -> свободная R
```

DFS из свободной вершины левой доли пытается пройти по такому пути.

Если правая вершина свободна, путь найден.

Если правая вершина уже занята левой вершиной `old_l`, DFS рекурсивно пытается переназначить `old_l` на другую правую вершину. Если это удается, текущая левая вершина занимает освобожденную правую вершину.

## 6. Структуры данных

Обычно используются:

- `g[l]` - список правых вершин, соседних с левой вершиной `l`;
- `matchR[r]` - какая левая вершина сейчас сматчена с правой `r`, либо `-1`;
- `used[l]` - была ли левая вершина посещена в текущем DFS;
- иногда `matchL[l]` - с какой правой вершиной сматчена левая `l`, если нужно быстро вывести пары.

Важно: `used` очищается перед каждой новой попыткой найти увеличивающую цепь из очередной левой вершины.

## 7. Псевдокод

```text
try_kuhn(v):
    if used[v]:
        return false
    used[v] = true

    for to in g[v]:
        if matchR[to] == -1:
            matchR[to] = v
            return true

        if try_kuhn(matchR[to]):
            matchR[to] = v
            return true

    return false

matching = 0
for v in L:
    used = [false] * |L|
    if try_kuhn(v):
        matching += 1
```

## 8. Почему рекурсия корректна

Пусть левая вершина `v` хочет занять правую вершину `to`.

Случаи:

1. `to` свободна.
   Тогда можно добавить ребро `(v, to)` в паросочетание.

2. `to` занята вершиной `u`.
   Тогда пробуем найти для `u` другую правую вершину. Если это получилось, `u` уходит на новое место, а `v` занимает `to`.

Именно это и есть разворот увеличивающей цепи:

```text
v -> to <- u -> other_to <- ...
```

В коде разворот не хранится явно как путь. Он происходит через последовательные присваивания `matchR[to] = v` при выходе из рекурсии.

## 9. Пример с `L1, L2, L3` и `R1, R2, R3`

Пусть есть двудольный граф:

```text
L1: R1, R2
L2: R2, R3
L3: R3
```

Идем по вершинам левой доли.

### Шаг 1. Запускаем DFS из `L1`

`L1` может пойти, например, в `R1`.

`R1` свободна, значит добавляем ребро:

```text
M = {(L1, R1)}
```

### Шаг 2. Запускаем DFS из `L2`

`L2` может пойти в `R2`.

`R2` свободна:

```text
M = {(L1, R1), (L2, R2)}
```

### Шаг 3. Запускаем DFS из `L3`

`L3` может идти только в `R3`.

Если `R3` свободна, сразу получаем:

```text
M = {(L1, R1), (L2, R2), (L3, R3)}
```

Это паросочетание размера `3`.

В лекционном разборе важен случай, где путь может идти через уже занятые вершины. Например:

```text
L1 - R2
L2 - R3
L3 - R3
L2 - R2
L1 - R1
```

Тогда DFS из `L3` сначала упирается в занятую `R3`, переходит к `L2`, пытается переставить `L2` на `R2`, затем может переставить `L1` на `R1`. В итоге находится увеличивающая цепь, и ребра инвертируются.

Главная идея: новая вершина левой доли не обязательно занимает свободную правую вершину напрямую. Она может запустить цепочку переназначений.

## 10. Сложность

Один DFS может пройти по ребрам графа за `O(E)`.

DFS запускается для каждой вершины левой доли. Если обозначать общее число вершин через `V`, то:

```text
O(V * E)
```

В более точной записи:

```text
O(|L| * E)
```

Память:

```text
O(V + E)
```

если граф хранится списками смежности.

## 11. Ограничения и применимость

Алгоритм Куна подходит, когда:

- граф двудольный;
- нужно максимальное по количеству ребер паросочетание;
- веса ребер не учитываются;
- размеры графа умеренные.

Не подходит напрямую, когда:

- граф не двудольный;
- нужно максимальное паросочетание в общем графе;
- нужно оптимизировать сумму весов ребер;
- граф очень большой, и `O(VE)` слишком медленно.

Для больших двудольных графов часто используют алгоритм Хопкрофта-Карпа со сложностью `O(E * sqrt(V))`.

## 12. Типичные ошибки

1. Не очищать `used` перед каждым запуском DFS.
   Тогда DFS будет запрещать пути, которые должны быть доступны в новой попытке.

2. Помечать правые вершины вместо левых без аккуратной логики.
   Классическая реализация помечает левые вершины, чтобы не зациклиться при переназначениях.

3. Думать, что если правая вершина занята, то ее нельзя использовать.
   Ее можно использовать, если получится переназначить текущего владельца.

4. Запускать DFS только из свободных вершин один раз и не повторять попытки после изменений.
   В простой реализации запускают попытку для каждой левой вершины; если она уже сматчена, можно пропустить, но часто проще запускать для всех.

## 13. Итог

Алгоритм Куна основан на теореме Бержа: пока есть увеличивающая цепь, паросочетание можно увеличить. В двудольном графе такую цепь удобно искать DFS из вершин левой доли. Если DFS доходит до свободной вершины правой доли или может рекурсивно переназначить уже занятую правую вершину, размер паросочетания увеличивается на `1`.

Главные характеристики:

- задача: максимальное паросочетание в двудольном графе;
- метод: DFS по увеличивающим цепям;
- ключевое действие: разворот ребер на найденном пути;
- сложность: `O(V * E)`;
- память: `O(V + E)`.

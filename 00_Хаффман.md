# Кодирование Хаффмана

## Введение / определения с нуля

Кодирование Хаффмана — это алгоритм построения оптимального префиксного кода для алфавита символов, если известны частоты или вероятности появления символов.

Идея проста:

- часто встречающиеся символы должны получать короткие коды;
- редко встречающиеся символы могут получать длинные коды;
- ни один код не должен быть префиксом другого, чтобы поток битов можно было декодировать однозначно.

Пусть есть алфавит:

$$
\Sigma = \{a_1, a_2, \dots, a_n\}
$$

Для каждого символа известна частота:

$$
f(a_i)
$$

или вероятность:

$$
p(a_i), \quad \sum_i p(a_i)=1
$$

Код — это сопоставление каждому символу некоторой битовой строки:

$$
c(a_i) \in \{0,1\}^*
$$

Длина кода символа:

$$
|c(a_i)|
$$

Средняя длина кодового слова:

$$
L = \sum_i p(a_i)|c(a_i)|
$$

Если вместо вероятностей даны частоты, то обычно минимизируют взвешенную длину:

$$
\sum_i f(a_i)|c(a_i)|
$$

Префиксный код — код, в котором никакое кодовое слово не является началом другого кодового слова.

Пример плохого кода:

| Символ | Код |
|---|---|
| A | 0 |
| B | 01 |

Код `0` является префиксом `01`, поэтому поток `01` неоднозначен: это может быть `B`, а может быть `A` и дальше что-то еще.

Пример префиксного кода:

| Символ | Код |
|---|---|
| A | 0 |
| B | 10 |
| C | 11 |

Здесь после чтения `0` сразу понятно, что это `A`; после чтения `10` — `B`; после `11` — `C`.

Код Хаффмана обычно представляют бинарным деревом:

- листья — исходные символы;
- путь от корня к листу задает код;
- переход влево часто обозначают `0`;
- переход вправо — `1`;
- частота внутренней вершины равна сумме частот ее детей.

Главный результат: алгоритм Хаффмана строит оптимальный префиксный код, то есть код с минимальной суммарной взвешенной длиной среди всех бинарных префиксных кодов для заданных частот.

## Логика работы (пошагово + псевдокод)

Алгоритм жадный. На каждом шаге он берет два объекта с минимальными частотами и объединяет их в один новый объект.

Пошагово:

1. Для каждого символа создаем отдельное дерево из одной вершины-листа.
2. Кладем все деревья в структуру, которая умеет быстро доставать элемент с минимальной частотой.
3. Пока деревьев больше одного:
   - достаем два дерева с минимальными частотами;
   - создаем новую внутреннюю вершину;
   - делаем эти два дерева ее детьми;
   - частота новой вершины равна сумме частот двух детей;
   - кладем новое дерево обратно.
4. Когда осталось одно дерево, это дерево Хаффмана.
5. Обходим дерево от корня к листьям:
   - переход влево добавляет `0`;
   - переход вправо добавляет `1`;
   - в листе получаем код символа.

Псевдокод построения дерева:

```text
Huffman(symbols, freq):
    Q = empty min-priority-queue

    for each symbol x in symbols:
        node = new leaf
        node.symbol = x
        node.freq = freq[x]
        Q.push(node, key = node.freq)

    while Q.size > 1:
        left = Q.extractMin()
        right = Q.extractMin()

        parent = new internal node
        parent.freq = left.freq + right.freq
        parent.left = left
        parent.right = right

        Q.push(parent, key = parent.freq)

    return Q.extractMin()
```

Псевдокод построения таблицы кодов:

```text
BuildCodes(node, prefix):
    if node is leaf:
        code[node.symbol] = prefix
        return

    BuildCodes(node.left,  prefix + "0")
    BuildCodes(node.right, prefix + "1")
```

Особый случай: если в алфавите ровно один символ, дерево состоит из одного листа. Тогда ему обычно дают код `0`, иначе кодовая строка была бы пустой.

Псевдокод кодирования сообщения:

```text
Encode(message, code):
    bits = empty string

    for each character ch in message:
        bits = bits + code[ch]

    return bits
```

Псевдокод декодирования:

```text
Decode(bits, root):
    result = empty string
    current = root

    for each bit b in bits:
        if b == 0:
            current = current.left
        else:
            current = current.right

        if current is leaf:
            result = result + current.symbol
            current = root

    return result
```

Почему декодирование работает без разделителей? Потому что код префиксный: как только мы дошли до листа, дальше продолжать нельзя, значит символ определен однозначно.

## Структура данных

Основная структура данных — минимальная куча или очередь с приоритетами.

Она должна поддерживать:

- `push(x)` — добавить вершину;
- `extractMin()` — достать вершину с минимальной частотой;
- `size` — узнать количество вершин.

Вершина дерева Хаффмана обычно хранит:

```text
Node:
    freq        // частота поддерева
    symbol      // символ, если это лист
    left        // левый ребенок
    right       // правый ребенок
```

Дополнительно нужны:

- таблица `freq`: символ -> частота;
- таблица `code`: символ -> битовая строка;
- корень дерева для декодирования.

Если код нужен только для хранения или передачи, вместе с закодированными данными надо передать информацию, позволяющую восстановить дерево:

- либо частоты символов;
- либо длины кодов в каноническом коде Хаффмана;
- либо само дерево в сериализованном виде.

Канонический код Хаффмана — вариант, в котором передаются только длины кодов, а сами коды восстанавливаются по стандартному правилу. Это удобно в форматах сжатия.

## Сложность по времени и памяти

Пусть:

- `n` — число различных символов;
- `m` — длина сообщения.

Построение частот:

$$
O(m)
$$

Создание `n` листьев:

$$
O(n)
$$

Работа с кучей:

- на каждом шаге достаем два минимума и кладем одну новую вершину;
- всего будет `n - 1` объединений;
- каждая операция с кучей стоит `O(log n)`.

Итого построение дерева:

$$
O(n \log n)
$$

Построение таблицы кодов обходом дерева:

$$
O(n)
$$

если не учитывать длину строк кодов, или

$$
O(\sum_i |c(a_i)|)
$$

если учитывать запись самих строк.

Кодирование сообщения:

$$
O(m)
$$

по числу символов, если конкатенация битов реализована эффективно.

Декодирование:

$$
O(B)
$$

где `B` — число битов в закодированном потоке.

Память:

- дерево содержит `2n - 1` вершин, то есть `O(n)`;
- куча хранит до `n` вершин, то есть `O(n)`;
- таблица кодов — `O(n)` плюс память на сами строки;
- результат кодирования занимает `B` бит.

## Ограничения

Кодирование Хаффмана требует знать частоты заранее. Если частоты неизвестны, есть варианты:

- сначала прочитать весь файл и посчитать частоты;
- использовать адаптивный Хаффман;
- использовать другой метод сжатия.

Алгоритм оптимален среди префиксных кодов с целочисленными длинами кодовых слов, но не всегда достигает энтропийного предела идеально.

Например, если вероятность символа равна `0.9`, а другого `0.1`, оба все равно получат коды длины 1 в бинарном алфавите из двух символов. Средняя длина будет 1 бит на символ, хотя энтропия меньше 1.

Хаффман плохо работает на очень маленьких данных, потому что накладные расходы на хранение дерева или таблицы кодов могут быть больше выигрыша.

Если частоты всех символов почти одинаковые, выигрыш по сравнению с фиксированным кодом будет небольшим.

Если нужно сжимать потоки без предварительного просмотра, классический статический Хаффман неудобен.

## Применимость

Кодирование Хаффмана применяют:

- в сжатии текстов;
- в архивации;
- в форматах изображений;
- как часть более сложных алгоритмов сжатия;
- в учебных задачах на жадные алгоритмы;
- в задачах, где надо построить оптимальное префиксное дерево.

Хаффман часто используется не один, а после предварительных преобразований. Например, сначала данные преобразуют так, чтобы возникали часто повторяющиеся значения, а затем эти значения кодируют Хаффманом.

Хороший случай для Хаффмана:

- есть дискретный алфавит;
- распределение частот неравномерное;
- можно передать или сохранить таблицу кодов;
- нужно быстрое декодирование.

Плохой случай:

- распределение почти равномерное;
- алфавит огромный, а данных мало;
- вероятности меняются по ходу потока;
- нужны дробные средние длины лучше, чем позволяет префиксный бинарный код.

## Примеры с разбором

Пусть даны частоты:

| Символ | Частота |
|---|---:|
| A | 5 |
| B | 9 |
| C | 12 |
| D | 13 |
| E | 16 |
| F | 45 |

Начальная очередь:

```text
5(A), 9(B), 12(C), 13(D), 16(E), 45(F)
```

Шаг 1: берем `A=5` и `B=9`, объединяем:

```text
AB = 14
```

Очередь:

```text
12(C), 13(D), 14(AB), 16(E), 45(F)
```

Шаг 2: берем `C=12` и `D=13`:

```text
CD = 25
```

Очередь:

```text
14(AB), 16(E), 25(CD), 45(F)
```

Шаг 3: берем `AB=14` и `E=16`:

```text
ABE = 30
```

Очередь:

```text
25(CD), 30(ABE), 45(F)
```

Шаг 4: берем `CD=25` и `ABE=30`:

```text
CDABE = 55
```

Очередь:

```text
45(F), 55(CDABE)
```

Шаг 5: берем `F=45` и `CDABE=55`, получаем корень:

```text
root = 100
```

Один из возможных кодов:

| Символ | Код |
|---|---|
| F | 0 |
| C | 100 |
| D | 101 |
| A | 1100 |
| B | 1101 |
| E | 111 |

Коды могут немного отличаться, если при равных частотах выбирать левый и правый ребенок иначе. Средняя длина при этом остается оптимальной.

Проверим префиксность:

- `0` не является префиксом кодов, начинающихся с `1`;
- `100` и `101` различаются на третьем бите;
- `1100` и `1101` различаются на четвертом бите;
- `111` не является префиксом других кодов.

Закодируем сообщение:

```text
FACE
```

По таблице:

```text
F = 0
A = 1100
C = 100
E = 111
```

Итоговый поток:

```text
01100100111
```

Декодирование:

1. Начинаем в корне.
2. Читаем `0`, попадаем в лист `F`.
3. Возвращаемся в корень.
4. Читаем `1100`, попадаем в `A`.
5. Читаем `100`, попадаем в `C`.
6. Читаем `111`, попадаем в `E`.

Получили исходное сообщение `FACE`.

## Типичные ошибки / вопросы на экзамен

Типичные ошибки:

- путать частоты и коды: частота не является кодом;
- забывать, что код должен быть префиксным;
- строить дерево, объединяя максимальные частоты вместо минимальных;
- не обрабатывать случай одного символа;
- декодировать по таблице строк медленно, хотя дерево дает естественное декодирование;
- считать, что коды Хаффмана всегда уникальны;
- забывать передать дерево или таблицу кодов вместе с данными;
- использовать обычную очередь вместо очереди с приоритетами;
- считать сложность построения `O(n)`, хотя с кучей обычно `O(n log n)`.

Вопросы на экзамен:

1. Что такое префиксный код?
2. Почему префиксный код декодируется без разделителей?
3. Почему Хаффман объединяет две минимальные частоты?
4. Какая структура данных нужна для эффективной реализации?
5. Какова сложность построения дерева?
6. Почему частые символы получают короткие коды?
7. Что надо хранить для декодирования?
8. Может ли быть несколько разных оптимальных кодов?
9. В чем отличие кода Хаффмана от фиксированной кодировки?
10. Когда Хаффман не даст хорошего сжатия?

Короткие ответы:

- Префиксный код — код, где ни одно кодовое слово не является префиксом другого.
- Декодирование однозначно, потому что лист дерева означает конец символа.
- Две минимальные частоты оказываются на максимальной глубине; их выгодно сделать соседними листьями.
- Нужна минимальная куча.
- Построение дерева обычно занимает `O(n log n)`.

## Дополнительно (доказательства идей, варианты)

### Почему две минимальные частоты можно объединять

В оптимальном префиксном коде две наименее частые буквы можно расположить на максимальной глубине и сделать братьями.

Интуиция:

- редкие символы выгоднее помещать глубже;
- если редкий символ находится выше частого, их можно поменять местами и не увеличить стоимость;
- два самых глубоких листа можно считать братьями, потому что у полного бинарного дерева листья на максимальной глубине естественно образуют пары.

Если два наименее частых символа `x` и `y` являются братьями, то их можно заменить одним псевдосимволом `z` с частотой:

$$
f(z)=f(x)+f(y)
$$

После этого задача уменьшается на один символ. Оптимальный код для уменьшенной задачи превращается в оптимальный код исходной задачи, если заменить лист `z` двумя детьми `x` и `y`.

Именно это и делает алгоритм Хаффмана.

### Связь с деревом

Стоимость кода равна взвешенной внешней длине дерева:

$$
Cost(T)=\sum_{x \in \Sigma} f(x)\cdot depth(x)
$$

Алгоритм Хаффмана строит дерево с минимальной такой стоимостью.

### Канонический код Хаффмана

В обычном дереве конкретные битовые строки зависят от того, кого положили влево, а кого вправо.

В каноническом коде:

1. Сначала строят длины кодов.
2. Символы сортируют по длине кода, затем по значению символа.
3. Коды назначают последовательно.

Плюс: для восстановления декодера достаточно хранить длины кодов.

### Адаптивный Хаффман

Адаптивный Хаффман меняет дерево во время чтения потока. Он полезен, когда частоты заранее неизвестны. Но реализация сложнее, а в современных форматах часто используют другие подходы.

### Хаффман и энтропия

Энтропия источника:

$$
H = -\sum_i p_i \log_2 p_i
$$

Для оптимального префиксного кода средняя длина близка к энтропии:

$$
H \le L < H + 1
$$

Это означает, что Хаффман хорош, но из-за целочисленных длин кодов не всегда достигает ровно `H`.

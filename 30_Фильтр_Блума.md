# 30. Фильтр Блума

## Вероятностное множество

Вероятностное множество - структура данных, которая позволяет:

- добавлять элементы;
- проверять принадлежность элемента множеству.

Главная особенность из лекции: структура может точно сказать, что элемента нет, но иногда может ошибочно сказать, что элемент есть.

Ответы:

- если фильтр говорит "нет", элемента точно нет;
- если фильтр говорит "да", элемент возможно есть, но возможен ложноположительный ответ.

Ложноотрицательных ответов в обычном фильтре Блума нет.

## Определение фильтра Блума

Фильтр Блума - реализация вероятностного множества, компактно хранящая информацию об элементах.

Он допускает:

```text
false positive: элемента нет, но фильтр говорит "есть"
```

и не допускает:

```text
false negative: элемент есть, но фильтр говорит "нет"
```

## Структура

Фильтр Блума состоит из:

- битового массива длины `m`;
- `k` хеш-функций;
- каждая хеш-функция отображает элемент в диапазон `{0, ..., m-1}`.

Изначально все биты равны `0`.

```text
bits[0..m-1] = 0
```

## Добавление элемента

Чтобы добавить элемент `x`:

1. Считаем `k` индексов:

```text
h1(x), h2(x), ..., hk(x)
```

2. В каждом из этих индексов ставим `1`:

```text
bits[hi(x)] = 1
```

Если какой-то бит уже равен `1`, ничего страшного.

Сложность:

```text
O(k)
```

## Проверка элемента

Чтобы проверить `x`:

1. Считаем те же `k` индексов.
2. Смотрим соответствующие биты.

Если хотя бы один бит равен `0`:

```text
x точно не добавляли
```

Если все биты равны `1`:

```text
x возможно добавляли
```

Сложность:

```text
O(k)
```

## Лекционный пример

Пусть:

```text
m = 7
h1(x) = x mod 7
h2(x) = (x * 5) mod 7
h3(x) = (floor(x / 2) * 4) mod 7
```

Добавим элемент `5`.

Изначально:

```text
index: 0 1 2 3 4 5 6
bits:  0 0 0 0 0 0 0
```

Считаем:

```text
h1(5) = 5 mod 7 = 5
h2(5) = (5 * 5) mod 7 = 25 mod 7 = 4
h3(5) = (floor(5 / 2) * 4) mod 7 = 8 mod 7 = 1
```

Ставим биты `5`, `4`, `1`:

```text
index: 0 1 2 3 4 5 6
bits:  0 1 0 0 1 1 0
```

Теперь при проверке элемента:

- если среди его позиций есть `0`, элемента точно нет;
- если все позиции попали в `1`, фильтр скажет "есть", но это может быть совпадением от других элементов.

## Почему бывают ложные срабатывания

Фильтр не хранит сами элементы. Он хранит только следы элементов в битовом массиве.

Разные элементы могут выставить одни и те же биты. Поэтому для элемента `y`, который никогда не добавлялся, может оказаться:

```text
bits[h1(y)] = 1
bits[h2(y)] = 1
...
bits[hk(y)] = 1
```

Тогда фильтр ошибочно ответит "возможно есть".

## Почему нет ложноотрицательных ответов

Если элемент `x` был добавлен, то при добавлении все его `k` битов были установлены в `1`.

Обычный фильтр Блума никогда не сбрасывает биты в `0`. Значит при последующей проверке все эти биты останутся `1`.

Поэтому добавленный элемент не может быть отвергнут.

## Удаление

Обычный фильтр Блума не поддерживает удаление.

Причина: один и тот же бит может быть выставлен несколькими элементами. Если при удалении `x` сбросить его биты в `0`, можно сломать проверку других элементов и получить ложноотрицательные ответы.

Решение: counting Bloom filter.

В нем вместо битов хранятся счетчики:

- при добавлении счетчики увеличиваются;
- при удалении уменьшаются;
- элемент считается возможным, если все нужные счетчики больше нуля.

Минусы counting Bloom:

- больше памяти;
- возможны переполнения счетчиков;
- удалять безопасно только элементы, которые действительно были добавлены.

## Вероятность ложного срабатывания

Пусть:

- `m` - размер битового массива;
- `n` - число добавленных элементов;
- `k` - число хеш-функций.

Классическая оценка вероятности ложного срабатывания:

```text
p ≈ (1 - e^(-kn/m))^k
```

В лекции та же идея записана через количество элементов и размер фильтра: вероятность уменьшается при увеличении массива и имеет оптимум по числу хеш-функций.

Оптимальное число хеш-функций:

```text
k ≈ (m / n) * ln 2
```

Если использовать слишком мало хеш-функций, каждый элемент оставляет слишком слабый след. Если слишком много, фильтр быстрее заполняется единицами, и ложных срабатываний становится больше.

## Как уменьшить вероятность ошибки

Из лекции:

1. Увеличить размер массива.
2. Подобрать число хеш-функций.
3. Комбинировать оба метода.

Только увеличивать число хеш-функций нельзя бесконечно: при добавлении каждый элемент будет ставить больше единиц, массив быстрее насыщается.

Только увеличивать массив можно, но это не всегда оптимально по памяти.

## Сложность

Добавление:

```text
O(k)
```

Проверка:

```text
O(k)
```

Память:

```text
O(m)
```

Фильтр не хранит сами элементы, поэтому нельзя перечислить содержимое множества.

## Применимость

Из лекции:

- поиск в интернете: быстро отсеивать ресурсы, где точно нет нужной информации;
- проверка орфографии;
- криптокошельки и поиск транзакций;
- таблицы маршрутизации и черные списки IP;
- биоинформатика и поиск фрагментов ДНК.

Также фильтр Блума часто используют:

- перед обращением к базе данных или диску;
- в кешах;
- в распределенных системах;
- для проверки "видели ли мы этот объект раньше".

## Ограничения

- Есть ложноположительные ответы.
- Обычная версия не поддерживает удаление.
- Нельзя получить список элементов.
- Вероятность ошибки растет с числом добавленных элементов.
- Нужны достаточно независимые хеш-функции.
- При переполнении фильтр становится почти бесполезным: если почти все биты равны `1`, большинство запросов возвращают "возможно есть".

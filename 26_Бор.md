# 26. Бор

## Определение

Бор, или префиксное дерево, или trie, - структура данных для хранения множества строк.

Название `trie` происходит от `retrieval`. В лекции бор описан как "автомат-дерево": вершины соответствуют префиксам, ребра подписаны символами, а в вершинах хранится признак терминальности.

Строка содержится в боре, если путь от корня по ее символам заканчивается в терминальной вершине.

## Что хранится в вершине

Типичная вершина:

```text
Node:
    terminal: bool
    next: map<char, Node>
```

Дополнительно можно хранить:

- количество строк, заканчивающихся в вершине;
- количество терминальных вершин в поддереве;
- идентификаторы строк;
- счетчик прохождений через вершину;
- ссылки для Ахо-Корасика.

Корень соответствует пустой строке.

## Пример из лекции

В лекции бор хранит слова:

```text
грааль
граф
графиня
дейкстра
дерево
```

Общие префиксы хранятся один раз. Например, у слов `граф` и `графиня` общий путь `г -> р -> а -> ф`. Вершина после `ф` терминальная для слова `граф`, но путь может продолжаться дальше для слова `графиня`.

Это важное свойство: терминальная вершина может иметь детей.

## Добавление строки

Алгоритм добавления слова `S`:

1. Начинаем в корне.
2. Для каждого символа `c`:
   - если перехода `c` нет, создаем новую вершину;
   - переходим по `c`.
3. После последнего символа помечаем текущую вершину как терминальную.

Пример из лекции:

```text
добавляем trie:
root --t--> "t" --r--> "tr" --i--> "tri" --e--> "trie"
последнюю вершину помечаем terminal = true
```

Если потом добавить `tried`, путь `trie` уже существует, создается только переход по `d`, а вершина `trie` остается терминальной.

Сложность зависит от хранения переходов:

- `map<char, Node>`: `O(|S| log |A|)`;
- `unordered_map<char, Node>`: в среднем `O(|S|)`;
- массив по символам: `O(|S|)`, но память `O(|V| * |A|)`.

## Поиск строки

Поиск похож на добавление, но новые вершины не создаются:

1. Идем из корня по символам строки.
2. Если переход отсутствует, строки нет.
3. Если все символы прочитаны, проверяем `terminal`.

Важно: если путь существует, но конечная вершина не терминальная, то в боре есть только такой префикс, но не сама строка.

Например, если добавлено `tried`, но не добавлено `trie`, путь `trie` есть, но строка `trie` отсутствует.

## Поиск префикса

Чтобы проверить, есть ли в множестве строка с префиксом `P`, достаточно пройти по символам `P`. Если путь существует, такой префикс есть.

Для вывода всех строк с данным префиксом:

1. Доходим до вершины префикса.
2. Обходим ее поддерево.
3. Выводим все терминальные вершины.

Если переходы хранятся в `map`, обход идет в отсортированном порядке символов, поэтому строки можно вывести лексикографически.

## Размер бора

Каждая новая вершина появляется только при добавлении нового префикса некоторой строки.

Поэтому:

```text
|V| <= 1 + sum |S_i|
```

Память:

```text
O(sum |S_i|)
```

с поправкой на способ хранения переходов.

## Сравнение с `set` и `unordered_set`

`unordered_set<string>`:

- быстрый поиск целой строки;
- не хранит порядок;
- не умеет естественно искать все строки по префиксу.

`set<string>`:

- хранит строки отсортированно;
- префиксы можно искать через `lower_bound`;
- операции имеют множитель `log n`;
- общие префиксы хранятся много раз.

Бор:

- хорошо работает с общими префиксами;
- естественно поддерживает поиск по префиксу;
- может выводить строки в лексикографическом порядке;
- полезен как основа для Ахо-Корасика.

## Бор суффиксов

Если для одной строки `S` добавить в бор все ее суффиксы, получится бор суффиксов.

Свойства из лекции:

- каждой вершине соответствует некоторая подстрока;
- вершин может быть `O(|S|^2)`;
- любую подстроку `P` можно найти за `O(|P|)`;
- можно использовать для подсчета различных подстрок.

Бор суффиксов прост для понимания, но слишком большой. Сжатая версия этой идеи - суффиксное дерево.

## Структуры хранения

### `map<char, Node>`

Плюсы:

- переходы отсортированы;
- удобно обходить в лексикографическом порядке;
- не нужно хранить пустые переходы.

Минусы:

- каждый переход стоит `O(log |A|)`.

### `unordered_map<char, Node>`

Плюсы:

- средний переход `O(1)`;
- хранит только существующие ребра.

Минусы:

- нет порядка;
- есть расходы хеш-таблицы;
- худший случай может быть плохим.

### Массив переходов

Плюсы:

- переход строго `O(1)`;
- простая реализация для маленького алфавита.

Минусы:

- память `O(|V| * |A|)`;
- обход всех переходов может быть дорогим.

## Ограничения

- Для большого алфавита массив переходов может быть неприемлем.
- Для случайных строк без общих префиксов бор может занимать больше памяти, чем хеш-множество.
- Удаление строк требует аккуратного удаления лишних вершин или счетчиков.
- Бор сам по себе не ищет множество шаблонов в тексте эффективно; для этого нужны суффиксные и выходные ссылки Ахо-Корасика.

## Применимость

- Автодополнение.
- Словари и проверка префиксов.
- Лексикографический вывод строк.
- IP routing и битовые боры.
- Хранение множества шаблонов для Ахо-Корасика.
- Суффиксный бор как учебная основа суффиксного дерева.

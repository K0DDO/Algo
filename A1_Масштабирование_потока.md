# A1. Масштабирование потока

## 1. Зачем нужно масштабирование

Обычный алгоритм Форда-Фалкерсона может быть медленным, если он проталкивает поток маленькими порциями.

В худшем случае с целыми пропускными способностями его сложность:

```text
O(E * |f*|)
```

где:

- `E` - число ребер;
- `|f*|` - величина максимального потока.

Проблема в том, что `|f*|` может быть очень большим числом. Например, если емкости порядка `10^9`, то зависимость от значения потока становится плохой.

Масштабирование потока решает эту проблему: вместо того чтобы сначала разрешать любые положительные увеличения, алгоритм сначала проталкивает только крупные порции, потом постепенно уменьшает масштаб.

## 2. Основная идея

Пусть:

```text
C = максимальная пропускная способность ребра в графе
```

Берем:

```text
k = floor(log2 C)
```

и начинаем с масштаба:

```text
Delta = 2^k
```

На уровне `Delta` алгоритм ищет дополняющие пути, у которых каждое ребро в остаточной сети имеет пропускную способность хотя бы `Delta`.

То есть разрешены только "широкие" ребра:

```text
residual_capacity(e) >= Delta
```

Когда таких путей больше нет, уменьшаем масштаб:

```text
Delta = Delta / 2
```

или:

```text
k = k - 1
```

И продолжаем.

Последний уровень:

```text
Delta = 1
```

Если все емкости целые, после уровня `1` будет найден максимальный поток.

## 3. Формулировка из лекции

В лекции масштабирование описывалось так:

1. Пусть `C` - максимальная пропускная способность.
2. Начинаем с:

```text
k = floor(log C)
```

обычно логарифм берется по основанию `2`.

3. На уровне `k` проталкиваем только потоки размера не меньше:

```text
2^k
```

4. Если больше не можем найти такой путь, уменьшаем `k` на `1`.
5. Продолжаем до `k = 0`.

Сложность:

```text
O(E^2 log C)
```

## 4. Алгоритм

Псевдокод:

```text
maxflow = 0
Delta = highest_power_of_two_not_greater_than(C)

while Delta >= 1:
    while exists path from s to t using only edges with residual capacity >= Delta:
        delta = bottleneck on this path
        push delta along the path
        maxflow += delta

    Delta = Delta / 2
```

Внутренний поиск пути можно делать DFS или BFS, но он должен игнорировать ребра с остаточной емкостью меньше `Delta`.

Условие прохода по ребру:

```text
edge.capacity >= Delta
```

а не просто:

```text
edge.capacity > 0
```

## 5. Почему это ускоряет Форд-Фалкерсон

Обычный DFS может выбрать путь с bottleneck `1`, даже если рядом есть путь с bottleneck `1000`.

Масштабирование запрещает такие маленькие проталкивания на ранних этапах.

Если текущий уровень:

```text
Delta = 512
```

то ребро остаточной емкости `1` вообще не рассматривается.

Алгоритм сначала насыщает крупные каналы, затем переходит к меньшим деталям:

```text
1024 -> 512 -> 256 -> ... -> 2 -> 1
```

Это похоже на приближение ответа по битам: сначала старшие биты потока, потом младшие.

## 6. Пример с плохим DFS

Рассмотрим пример из лекции:

```text
s -> A capacity 1000
s -> B capacity 1000
A -> B capacity 1
A -> t capacity 1000
B -> t capacity 1000
```

Обычный DFS может выбирать:

```text
s -> A -> B -> t
```

и проталкивать только `1`, потому что ребро `A -> B` имеет емкость `1`.

Затем может идти обратная перенастройка через `B -> A`, снова на `1`, и так много раз.

Масштабирование при начальном уровне:

```text
Delta = 512
```

не позволит использовать ребро:

```text
A -> B capacity 1
```

потому что `1 < 512`.

Зато будут доступны пути:

```text
s -> A -> t
s -> B -> t
```

Они дают крупные проталкивания и быстро набирают поток `2000`.

## 7. Остаточная сеть при масштабировании

Остаточная сеть строится так же, как в обычном max-flow.

Для ребра `(u, v)`:

- прямое остаточное ребро имеет емкость `c(u, v) - f(u, v)`;
- обратное остаточное ребро имеет емкость `f(u, v)`.

Отличается только фильтр при поиске пути:

```text
идем по ребру, если residual_capacity >= Delta
```

После проталкивания:

```text
forward.capacity -= pushed
backward.capacity += pushed
```

То есть структура данных такая же, как для Форда-Фалкерсона или Эдмондса-Карпа.

## 8. Почему алгоритм корректен

На каждом уровне алгоритм ищет дополняющие пути в ограниченной остаточной сети, где оставлены только ребра с емкостью хотя бы `Delta`.

Когда путей на уровне `Delta` больше нет, это означает:

> невозможно увеличить поток на крупную порцию, проходя только по достаточно широким ребрам.

Но могут существовать пути, использующие более узкие ребра. Поэтому алгоритм не останавливается полностью, а уменьшает `Delta`.

На последнем уровне:

```text
Delta = 1
```

для целочисленных емкостей условие:

```text
residual_capacity >= 1
```

эквивалентно:

```text
residual_capacity > 0
```

То есть на последнем уровне алгоритм ищет любые обычные дополняющие пути.

Когда на уровне `1` пути из `s` в `t` нет, в остаточной сети вообще нет дополняющего пути. По теореме Форда-Фалкерсона текущий поток максимален.

## 9. Сложность `O(E^2 log C)`

Количество масштабных уровней:

```text
floor(log2 C) + 1 = O(log C)
```

Нужно оценить работу на одном уровне `Delta`.

Интуитивная оценка:

- каждый поиск пути стоит `O(E)`;
- на одном уровне число успешных проталкиваний можно ограничить `O(E)`;
- значит один уровень стоит `O(E^2)`.

Тогда всего:

```text
O(E^2 log C)
```

Эта оценка слабее зависит от численных значений емкостей, чем `O(E * |f*|)`: вместо величины максимального потока появляется только логарифм от максимальной емкости.

## 10. Почему на уровне не слишком много проталкиваний

После завершения уровня `2Delta` не существует пути из `s` в `t`, состоящего из ребер емкости хотя бы `2Delta`.

Когда переходим к уровню `Delta`, начинают использоваться ребра с остаточной емкостью от `Delta` до `2Delta - 1`.

Можно показать, что "недостающий" поток на этом уровне ограничен величиной порядка `O(E * Delta)`. Каждое успешное проталкивание добавляет хотя бы `Delta`.

Значит число проталкиваний на уровне:

```text
O(E)
```

Каждое проталкивание требует поиска пути за `O(E)`.

Итого на уровень:

```text
O(E^2)
```

Умножаем на `O(log C)` уровней и получаем:

```text
O(E^2 log C)
```

## 11. Сравнение с другими алгоритмами из лекции

| Метод | Выбор пути | Сложность | Зависимость от емкостей |
|---|---|---:|---|
| Форд-Фалкерсон | любой путь, часто DFS | `O(E * |f*|)` | сильная |
| Эдмондс-Карп | BFS, кратчайший путь | `O(V * E^2)` | нет зависимости от значения потока |
| Масштабирование | пути с емкостью `>= 2^k` | `O(E^2 log C)` | слабая, через `log C` |

В лекции отдельно подчеркивалось:

- Форд-Фалкерсон зависит от величины потока;
- Эдмондс-Карп не зависит от весов;
- масштабирование зависит от емкостей только логарифмически.

## 12. Структуры данных

Подходят те же структуры, что и для обычного max-flow:

```text
Edge:
    to
    rev
    capacity
```

Списки смежности:

```text
g[v] = list of Edge
```

Функция добавления ребра:

```text
add_edge(u, v, c):
    add forward edge u -> v with capacity c
    add backward edge v -> u with capacity 0
```

DFS/BFS с масштабом:

```text
if edge.capacity >= Delta and not visited[edge.to]:
    go
```

## 13. Ограничения

Масштабирование обычно рассматривается для целочисленных пропускных способностей.

Причина:

- уровни `1, 2, 4, 8, ...` естественно работают с целыми емкостями;
- последний уровень `Delta = 1` означает, что все положительные целые остаточные емкости доступны.

Если емкости вещественные, надо аккуратно определять точность и критерий остановки. В учебной постановке обычно предполагаются целые емкости.

Также важно:

- емкости должны быть неотрицательными;
- граф ориентированный;
- должны быть выделены источник `s` и сток `t`;
- алгоритм работает с остаточной сетью.

## 14. Когда использовать

Масштабирование полезно, если:

- хочется сохранить простую идею Форда-Фалкерсона;
- емкости большие;
- простой DFS может давать слишком много маленьких проталкиваний;
- нужна оценка лучше, чем `O(E * |f*|)`;
- граф не настолько большой, чтобы требовались более сложные алгоритмы вроде Диница или push-relabel.

Для учебных задач масштабирование удобно как промежуточный шаг между простым Форд-Фалкерсоном и более продвинутыми алгоритмами.

## 15. Типичные ошибки

1. Начинать не с максимальной степени двойки.

Правильно:

```text
Delta = 2^floor(log2 C)
```

2. На уровне `Delta` идти по любым положительным ребрам.

Правильно:

```text
edge.capacity >= Delta
```

3. Уменьшать `Delta` после каждого найденного пути.

Правильно:

```text
пока есть путь на текущем Delta, продолжаем проталкивать
только потом Delta /= 2
```

4. Забывать про обратные ребра.

Масштабирование не отменяет остаточную сеть. Обратные ребра нужны так же, как в обычном max-flow.

5. Считать, что bottleneck всегда равен `Delta`.

Нет. На уровне `Delta` bottleneck не меньше `Delta`, но может быть больше:

```text
bottleneck >= Delta
```

## 16. Итог

Масштабирование потока - это оптимизация метода Форда-Фалкерсона.

Главная идея:

```text
сначала ищем только широкие пути,
потом постепенно разрешаем все более узкие
```

Алгоритм:

```text
k = floor(log2 C)
Delta = 2^k

while Delta >= 1:
    ищем и проталкиваем пути, где каждое ребро имеет остаточную емкость >= Delta
    когда таких путей больше нет, Delta /= 2
```

Ключевые характеристики:

- работает в остаточной сети;
- использует bottleneck на найденном пути;
- на последнем уровне превращается в обычный поиск дополняющих путей;
- сложность: `O(E^2 log C)`;
- зависимость от емкостей логарифмическая.

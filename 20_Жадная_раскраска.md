# 20. Жадная раскраска графа

## 1. Задача раскраски

Дан неориентированный граф:

```text
G = (V, E)
```

Нужно раскрасить вершины в цвета так, чтобы любые две соседние вершины имели разные цвета.

То есть если есть ребро `(u, v)`, то:

```text
color[u] != color[v]
```

Цель классической задачи - использовать как можно меньше цветов.

Минимальное возможное число цветов называется хроматическим числом графа:

```text
chi(G)
```

## 2. Жадная идея

Жадная раскраска не пытается перебрать все варианты.

Она фиксирует некоторый порядок вершин и красит вершины одну за другой.

Для каждой вершины выбирается минимальный доступный цвет, который не используется ее уже раскрашенными соседями.

Алгоритм:

1. Выбрать порядок вершин.
2. Идти по вершинам в этом порядке.
3. Для текущей вершины посмотреть цвета уже раскрашенных соседей.
4. Назначить минимальный цвет, которого среди них нет.

## 3. Псевдокод

```text
greedy_coloring(order):
    color[v] = -1 for all v

    for v in order:
        forbidden = empty set

        for to in g[v]:
            if color[to] != -1:
                forbidden.add(color[to])

        c = 0
        while c in forbidden:
            c += 1

        color[v] = c

    return color
```

Если цвета нумеруются с `1`, то вместо `0` начинаем с `1`.

## 4. Почему алгоритм корректен

Когда алгоритм красит вершину `v`, он запрещает все цвета, которые уже стоят у соседей `v`.

Поэтому после назначения цвета:

```text
color[v] != color[to]
```

для всех уже раскрашенных соседей `to`.

А если сосед еще не раскрашен, он будет обработан позже и сам не сможет взять цвет `v`, потому что увидит `v` среди уже раскрашенных соседей.

Значит после завершения никакое ребро не соединяет вершины одного цвета.

## 5. Роль порядка вершин

Жадная раскраска очень сильно зависит от порядка.

Один и тот же граф при разных порядках может получить разное число цветов.

Пример: путь из четырех вершин:

```text
1 - 2 - 3 - 4
```

Оптимально он красится в `2` цвета:

```text
1: A
2: B
3: A
4: B
```

Если идти естественным порядком `1, 2, 3, 4`, жадный алгоритм тоже даст `2` цвета.

Но в более сложных графах плохой порядок может заставить алгоритм использовать лишние цвета.

Важный вывод:

> Жадная раскраска гарантирует корректную раскраску, но не гарантирует минимальное число цветов.

## 6. Оценка через максимальную степень

Обозначим максимальную степень графа:

```text
Delta = max degree(v)
```

У любой вершины не больше `Delta` соседей.

Когда жадный алгоритм красит вершину `v`, среди ее уже раскрашенных соседей может быть занято не больше `degree(v)` цветов, а значит не больше `Delta` цветов.

Тогда среди цветов:

```text
1, 2, ..., Delta + 1
```

обязательно найдется хотя бы один свободный.

Поэтому жадная раскраска всегда использует не более:

```text
Delta + 1
```

цветов.

Следовательно:

```text
chi(G) <= Delta + 1
```

Это одна из базовых верхних оценок на хроматическое число.

## 7. Почему иногда нужно `Delta + 1`

Оценка `Delta + 1` достижима.

Примеры:

### Полный граф

В полном графе `K_n` каждая вершина соединена с каждой.

```text
Delta = n - 1
chi(K_n) = n = Delta + 1
```

Каждая вершина должна иметь свой цвет.

### Нечетный цикл

Например цикл длины `5`:

```text
1 - 2 - 3 - 4 - 5 - 1
```

У каждой вершины степень `2`, значит:

```text
Delta = 2
```

Но нечетный цикл нельзя раскрасить в `2` цвета, нужно `3`:

```text
chi(C_5) = 3 = Delta + 1
```

## 8. Теорема Брукса

Теорема Брукса уточняет оценку `Delta + 1`.

В упрощенной формулировке:

> Для связного графа хроматическое число не превосходит `Delta`, кроме двух типов графов: полных графов и нечетных циклов.

То есть почти всегда можно лучше, чем `Delta + 1`:

```text
chi(G) <= Delta
```

Исключения:

- полный граф `K_n`, где нужно `Delta + 1`;
- нечетный цикл, где `Delta = 2`, но нужно `3`.

Важно: жадный алгоритм сам по себе не доказывает теорему Брукса и не всегда находит раскраску в `Delta` цветов. Но теорема объясняет, что верхняя граница `Delta + 1` часто не является точной.

## 9. Структуры данных

Для графа:

```text
g[v] = список соседей вершины v
```

Для цветов:

```text
color[v]
```

Для запрещенных цветов можно использовать:

- `set`;
- булев массив `used_color`;
- массив с таймстемпами, чтобы не очищать его каждый раз.

### Вариант с булевым массивом

Если заранее знаем, что цветов будет не больше `Delta + 1`, можно завести:

```text
used = [false] * (Delta + 2)
```

Для каждой вершины:

1. Отмечаем цвета соседей.
2. Ищем первый неотмеченный цвет.
3. Назначаем его.
4. Снимаем отметки.

### Вариант с таймстемпами

Чтобы не очищать массив `used`, можно хранить:

```text
mark[color] = iteration
```

Для текущей вершины `v`:

```text
iteration = v_index + 1
mark[color[to]] = iteration
```

Цвет запрещен, если:

```text
mark[c] == iteration
```

Это удобно при больших графах.

## 10. Сложность

Если использовать списки смежности и эффективную отметку цветов:

- каждое ребро просматривается при обработке своих концов;
- суммарный просмотр соседей дает `O(V + E)`;
- поиск цвета может добавить `O(Delta)` на вершину.

Базовая оценка:

```text
O(V * Delta + E)
```

Так как:

```text
V * Delta <= V^2
```

можно писать:

```text
O(V^2 + E)
```

Но для разреженных графов с аккуратной реализацией часто используют оценку:

```text
O(V + E)
```

если поиск первого свободного цвета суммарно контролируется и число цветов ограничено `Delta + 1`.

Память:

```text
O(V + E)
```

для графа и массива цветов.

## 11. Ограничения и применимость

Жадная раскраска хороша, когда:

- нужна быстрая корректная раскраска;
- не обязательно минимальное число цветов;
- граф большой, и точные алгоритмы слишком дорогие;
- важна простота реализации;
- можно подобрать хороший порядок вершин.

Она применяется в:

- распределении регистров в компиляторах;
- расписаниях;
- задачах конфликтов ресурсов;
- кластеризации и маркировке;
- эвристиках для NP-трудных задач.

Не стоит ожидать, что жадный алгоритм всегда найдет оптимум:

- задача точного нахождения `chi(G)` NP-трудна;
- плохой порядок может использовать намного больше цветов, чем оптимально.

## 12. Выбор порядка

Порядок вершин - главный фактор качества.

Популярные варианты:

### Произвольный порядок

Самый простой:

```text
0, 1, 2, ..., n - 1
```

Быстро, но может дать плохой результат.

### По убыванию степени

Сначала красим вершины с большим числом соседей.

Идея:

- сложные вершины получают выбор раньше;
- менее ограниченные вершины подстраиваются позже.

Это часто лучше случайного порядка, но все еще не гарантирует оптимум.

### Случайный порядок

Можно запускать жадную раскраску несколько раз с разными случайными порядками и брать лучший результат.

Это простая эвристика.

### DSATUR как развитие идеи

DSATUR выбирает следующую вершину не заранее, а динамически:

- смотрит, у какой нераскрашенной вершины больше разных цветов среди соседей;
- при равенстве часто выбирает вершину большей степени.

Это уже более сильная эвристика, но базовая идея все равно жадная.

## 13. Пример

Граф:

```text
1 -- 2
|  / |
| /  |
3 -- 4
```

Ребра:

```text
(1,2), (1,3), (2,3), (2,4), (3,4)
```

Порядок:

```text
1, 2, 3, 4
```

Красим:

1. Вершина `1`: соседей с цветом нет, берем цвет `1`.
2. Вершина `2`: сосед `1` имеет цвет `1`, берем цвет `2`.
3. Вершина `3`: соседи `1` и `2` имеют цвета `1` и `2`, берем цвет `3`.
4. Вершина `4`: соседи `2` и `3` имеют цвета `2` и `3`, берем цвет `1`.

Итог:

```text
color[1] = 1
color[2] = 2
color[3] = 3
color[4] = 1
```

Использовано `3` цвета.

Это корректно, потому что никакие соседние вершины не имеют одинаковый цвет.

## 14. Связь с двудольностью

Если граф двудольный, его можно раскрасить в `2` цвета.

Но обычная жадная раскраска при плохом порядке не обязана сразу показать оптимальные `2` цвета для произвольного двудольного графа.

Для проверки двудольности лучше использовать BFS/DFS-раскраску в два цвета:

```text
color[to] = 1 - color[v]
```

Если обнаружили ребро между вершинами одного цвета, граф не двудольный.

## 15. Типичные ошибки

1. Считать, что жадная раскраска всегда оптимальна.
   Нет, она дает корректную раскраску, но не обязательно минимальную.

2. Игнорировать порядок вершин.
   Порядок может сильно менять число цветов.

3. Забывать проверять только уже раскрашенных соседей.
   Нераскрашенные соседи пока не запрещают цвета.

4. Неправильно очищать множество запрещенных цветов.
   Запрещенные цвета должны пересчитываться отдельно для каждой вершины.

5. Путать оценку алгоритма с хроматическим числом.
   Жадный алгоритм использует не более `Delta + 1` цветов, но `chi(G)` может быть намного меньше.

## 16. Итог

Жадная раскраска - простой алгоритм:

```text
идем по вершинам в выбранном порядке
берем минимальный цвет, которого нет у уже раскрашенных соседей
```

Она всегда строит корректную раскраску и гарантирует:

```text
chi(G) <= Delta + 1
```

На практике качество зависит от порядка вершин. Теорема Брукса говорит, что почти для всех связных графов можно уложиться в `Delta` цветов; исключения - полные графы и нечетные циклы. Но обычный жадный алгоритм без специального порядка такой результат не гарантирует.

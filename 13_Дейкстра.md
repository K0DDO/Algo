# 13. Алгоритм Дейкстры

## Введение

Алгоритм Дейкстры находит кратчайшие пути от одной стартовой вершины до всех остальных во взвешенном графе с неотрицательными весами ребер.

Главное ограничение: Дейкстра работает только при неотрицательных весах. Если есть отрицательное ребро, жадная логика алгоритма может стать неверной.

Есть две классические реализации:

- наивная с массивом за `O(V^2)`;
- с приоритетной очередью за `O((V + E) log V)` при бинарной куче.

## Логика алгоритма

Алгоритм поддерживает массив `dist[v]` - текущую лучшую известную длину пути от источника до `v`.

На каждом шаге выбирается непосещенная вершина `v` с минимальным `dist[v]`. После выбора расстояние до нее считается окончательным. Затем алгоритм релаксирует все исходящие ребра из `v`.

Почему это работает: если все веса неотрицательные, никакой путь через еще не обработанные вершины не сможет улучшить уже минимальную выбранную вершину.

### Лемма из лекции: частичные пути кратчайших путей тоже кратчайшие

Пусть \(p = \langle v_1, v_2, \ldots, v_k\rangle\) — кратчайший путь, \(p'\) — его подпуть от \(v_i\) до \(v_j\). Тогда \(p'\) тоже кратчайший.

Доказательство от противного: если есть \(p''\) с \(w(p'') < w(p')\), замена \(p'\) на \(p''\) внутри \(p\) даёт путь легче \(p\) — противоречие.

Эта лемма объясняет, почему жадный выбор Дейкстры (фиксировать вершину с минимальным текущим `dist`) корректен при неотрицательных весах.

## Релаксация

Для ребра `u -> v` веса `w`:

```text
if dist[u] + w < dist[v]:
    dist[v] = dist[u] + w
    parent[v] = u
```

`parent` нужен для восстановления пути.

## Наивная реализация `O(V^2)`

Псевдокод:

```text
dist = array[V] filled with INF
used = array[V] filled with false
parent = array[V] filled with -1

dist[source] = 0

for i in 1..V:
    v = -1

    for u in V:
        if not used[u] and (v == -1 or dist[u] < dist[v]):
            v = u

    if dist[v] == INF:
        break

    used[v] = true

    for (to, weight) in g[v]:
        if dist[v] + weight < dist[to]:
            dist[to] = dist[v] + weight
            parent[to] = v
```

Наивная версия хороша для плотных графов, где `E` близко к `V^2`, и выигрыш от кучи меньше заметен.

## Реализация с приоритетной очередью

Псевдокод:

```text
dist = array[V] filled with INF
parent = array[V] filled with -1
dist[source] = 0

pq.push((0, source))

while pq is not empty:
    (d, v) = pq.pop_min()

    if d != dist[v]:
        continue

    for (to, weight) in g[v]:
        if dist[v] + weight < dist[to]:
            dist[to] = dist[v] + weight
            parent[to] = v
            pq.push((dist[to], to))
```

В стандартной бинарной куче часто нет операции decrease-key. Поэтому при улучшении расстояния добавляют новую пару `(dist[to], to)`, а старые пары пропускают проверкой `d != dist[v]`.

## Корректность

Дейкстра опирается на жадный выбор.

Пусть `v` - непосещенная вершина с минимальным `dist[v]`. Предположим, что есть более короткий путь до `v`, который проходит через какую-то непосещенную вершину `x`. Но путь до `x` должен быть не меньше `dist[v]`, потому что `v` была минимальной среди непосещенных. А все дальнейшие ребра имеют неотрицательный вес, значит путь через `x` не может стать меньше.

Отсюда расстояние до выбранной вершины окончательно.

## Структуры данных

Общие:

- список смежности `g[v]` с парами `(to, weight)`;
- массив `dist[v]`;
- массив `parent[v]`.

Для наивной версии:

- массив `used[v]`;
- линейный поиск минимума по всем вершинам.

Для версии с кучей:

- приоритетная очередь `pq`;
- пары `(distance, vertex)`;
- проверка устаревших записей.

Если граф плотный и хранится матрицей весов, наивная версия может быть проще.

## Сложность

Наивная реализация:

```text
время: O(V^2)
память: O(V) + память на граф
```

Реализация с бинарной кучей:

```text
время: O((V + E) log V)
память: O(V + E)
```

Если каждая релаксация добавляет новую запись в кучу, размер кучи может быть `O(E)`, но логарифм обычно записывают как `log V` или `log E`; для стандартной оценки используют `O((V + E) log V)`.

## Ограничения

Главное ограничение: веса ребер должны быть неотрицательными.

Если есть отрицательное ребро, алгоритм может зафиксировать расстояние до вершины слишком рано и уже не исправить его.

Дейкстра не обнаруживает отрицательные циклы. Для отрицательных весов нужен Беллман-Форд или другой подход.

Для недостижимых вершин расстояние остается `INF`.

Нужно аккуратно выбирать тип данных для расстояний. Суммы весов могут не помещаться в 32-битный `int`.

## Применимость

Дейкстра используется в задачах:

- маршрутизация по дорогам с неотрицательными длинами;
- сетевые задержки;
- кратчайшие пути в графах состояний с неотрицательной ценой перехода;
- поиск минимальной стоимости от одного источника;
- алгоритмы как подпрограмма в более сложных задачах.

Если все веса равны `1`, лучше использовать BFS: он проще и работает за `O(V + E)`.

Если граф является DAG, можно использовать топосорт и один проход релаксаций.

## Примеры

Пусть старт `1`, ребра:

```text
1 -> 2 (2)
1 -> 3 (5)
2 -> 3 (1)
2 -> 4 (4)
3 -> 4 (1)
```

Инициализация:

```text
dist[1] = 0
dist[2] = INF
dist[3] = INF
dist[4] = INF
```

Ход:

1. Выбираем `1`, релаксируем:
   - `dist[2] = 2`;
   - `dist[3] = 5`.
2. Выбираем `2`, релаксируем:
   - `dist[3] = 3`;
   - `dist[4] = 6`.
3. Выбираем `3`, релаксируем:
   - `dist[4] = 4`.
4. Выбираем `4`.

Итог:

```text
dist[1] = 0
dist[2] = 2
dist[3] = 3
dist[4] = 4
```

Кратчайший путь до `4`:

```text
1 -> 2 -> 3 -> 4
```

## Сравнение с другими алгоритмами

```text
BFS:
    невзвешенный граф или все веса 1
    O(V + E)

Dijkstra:
    веса неотрицательные
    O(V^2) или O((V + E) log V)

Bellman-Ford:
    можно отрицательные веса
    O(VE)

DAG shortest paths:
    ориентированный ациклический граф
    O(V + E)
```

## Типичные ошибки

- Запускать Дейкстру при отрицательных ребрах.
- Забывать проверять устаревшие пары в приоритетной очереди.
- Путать `used` в наивной версии и проверку `d != dist[v]` в кучной версии.
- Использовать BFS для графа с произвольными положительными весами.
- Не восстанавливать путь через `parent`.
- Выбирать слишком маленькое значение `INF`.

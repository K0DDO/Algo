# 10. Алгоритм Прима

## Введение

Алгоритм Прима строит минимальное остовное дерево во взвешенном неориентированном графе. Как и Крускал, он решает задачу MST, но делает это другим способом.

Крускал сортирует все ребра и объединяет компоненты. Прим растит одно дерево: на каждом шаге добавляет к уже построенной части самое дешевое ребро, которое ведет в новую вершину.

Алгоритм особенно естественен, если граф хранится списками смежности и нужно постепенно расширять множество выбранных вершин.

## Основные определения

Минимальное остовное дерево - это дерево, которое:

- содержит все вершины связного неориентированного графа;
- имеет `V - 1` ребро;
- минимизирует сумму весов.

Алгоритм Прима поддерживает множество `S` - вершины, уже включенные в остов. На каждом шаге выбирается минимальное ребро из `S` в `V \ S`.

## Логика алгоритма

Идея:

1. Выбрать любую стартовую вершину.
2. Считать, что она уже находится в дереве.
3. Для каждой еще не добавленной вершины хранить минимальный вес ребра, которым ее можно присоединить к дереву.
4. На каждом шаге выбирать неиспользованную вершину с минимальным значением `minEdge[v]`.
5. Добавлять ее в дерево.
6. Релаксировать соседей: если через новую вершину можно дешевле присоединить соседа, обновить значение.

Это похоже на Дейкстру по структуре, но смысл другой:

- Дейкстра минимизирует расстояние от источника;
- Прим минимизирует стоимость ребра подключения вершины к текущему остову.

## Наивная реализация `O(V^2)`

Подходит для плотных графов или когда используется матрица смежности.

Псевдокод:

```text
used = array[V] filled with false
minEdge = array[V] filled with INF
parent = array[V] filled with -1

minEdge[start] = 0

for i in 1..V:
    v = неиспользованная вершина с минимальным minEdge[v]

    if minEdge[v] == INF:
        граф несвязный

    used[v] = true

    for to in V:
        if weight[v][to] < minEdge[to] and not used[to]:
            minEdge[to] = weight[v][to]
            parent[to] = v
```

Ответ задается массивом `parent`: ребро `(parent[v], v)` входит в MST для всех `v`, кроме стартовой.

## Реализация с приоритетной очередью

Для разреженных графов лучше использовать кучу.

Псевдокод:

```text
used = array[V] filled with false
minEdge = array[V] filled with INF
parent = array[V] filled with -1

minEdge[start] = 0
pq.push((0, start))

while pq is not empty:
    (w, v) = pq.pop_min()

    if used[v]:
        continue

    used[v] = true

    for (to, weight) in g[v]:
        if not used[to] and weight < minEdge[to]:
            minEdge[to] = weight
            parent[to] = v
            pq.push((minEdge[to], to))
```

Если в языке нет операции decrease-key, в кучу можно добавлять новые пары, а устаревшие записи пропускать через `used` или проверку текущего расстояния.

## Корректность

Корректность основана на свойстве разреза.

Пусть `S` - вершины, уже добавленные в дерево. Рассмотрим разрез между `S` и `V \ S`. Минимальное по весу ребро, пересекающее этот разрез, безопасно: оно входит в некоторое MST.

Прим каждый раз выбирает именно такое ребро. Поэтому на каждом шаге он не портит возможность получить минимальный остов.

## Структуры данных

Для наивной реализации:

- матрица весов `weight[v][to]` или списки смежности;
- массив `used[v]`;
- массив `minEdge[v]`;
- массив `parent[v]`.

Для реализации с кучей:

- списки смежности `g[v]`, где элементы `(to, weight)`;
- бинарная куча или приоритетная очередь;
- `used[v]`;
- `minEdge[v]`;
- `parent[v]`.

**Важно (из лекции):** если хранить только массив минимальных расстояний до непомеченных вершин и **не** сохранять выбранные рёбра, то по окончании алгоритма нельзя восстановить MST как набор рёбер. Поэтому на практике обязательно ведут `parent[v]` (или `edge_to[v]`): ребро остова — `(parent[v], v)`.

## Сложность

Наивная реализация:

```text
время: O(V^2)
память: O(V) + память на граф
```

Если граф хранится матрицей, память на граф `O(V^2)`.

Реализация с бинарной кучей:

```text
время: O(E log V)
```

Часто также пишут `O((V + E) log V)`, потому что в куче выполняются операции для вершин и ребер. Для связного графа `E >= V - 1`, поэтому запись `O(E log V)` обычно достаточна.

Память:

```text
O(V + E)
```

## Ограничения

Алгоритм Прима применяется к неориентированным графам.

Если граф несвязный, из одной стартовой вершины алгоритм построит MST только для ее компоненты. Чтобы получить минимальный остовный лес, надо запускать алгоритм из каждой еще не посещенной вершины.

Веса могут быть отрицательными: для MST это допустимо. В отличие от Дейкстры, Прим не требует неотрицательных весов.

Нужно не путать `minEdge[v]` с кратчайшим расстоянием от старта. Это стоимость одного лучшего ребра подключения, а не длина пути.

## Применимость

Прим удобен:

- для разреженных графов со списками смежности и кучей;
- для плотных графов в наивной версии `O(V^2)`;
- когда нужно растить MST из конкретной стартовой вершины;
- когда граф уже представлен списками соседей.

Задачи:

- минимальная стоимость соединения всех городов дорогами;
- проектирование сетей;
- построение каркаса графа;
- кластеризация и анализ связей.

## Примеры

Пусть есть граф:

```text
1 -- 2 (1)
1 -- 3 (4)
2 -- 3 (2)
2 -- 4 (5)
3 -- 4 (3)
```

Стартуем из `1`.

Ход:

1. Добавляем `1`, обновляем `2` весом `1`, `3` весом `4`.
2. Минимальная вершина для подключения - `2`, добавляем ребро `1-2`.
3. Через `2` можно лучше подключить `3` весом `2`, также `4` весом `5`.
4. Добавляем `3` через `2-3`.
5. Через `3` улучшаем подключение `4` до веса `3`.
6. Добавляем `4` через `3-4`.

MST:

```text
1-2, 2-3, 3-4
```

Суммарный вес:

```text
1 + 2 + 3 = 6
```

## Типичные ошибки

- Считать `minEdge` расстоянием от стартовой вершины.
- Применять алгоритм к ориентированному графу без переопределения задачи.
- Забыть обработать несвязный граф.
- В реализации с кучей не пропускать устаревшие элементы.
- Путать сложность наивной и кучной реализации.
- Думать, что отрицательные веса запрещены, как в Дейкстре.

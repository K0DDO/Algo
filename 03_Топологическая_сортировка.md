# Топологическая сортировка

## Введение / определения с нуля

Топологическая сортировка — это упорядочивание вершин ориентированного графа так, чтобы каждое ребро шло слева направо.

Формально, для ориентированного графа:

$$
G=(V,E)
$$

топологический порядок — это такая перестановка вершин, что для любого ребра:

$$
(u,v)\in E
$$

вершина `u` стоит раньше вершины `v`.

Пример:

```text
1 -> 2
1 -> 3
2 -> 4
3 -> 4
```

Один топологический порядок:

```text
1, 2, 3, 4
```

Другой тоже корректный:

```text
1, 3, 2, 4
```

Топологическая сортировка существует только для ориентированного ациклического графа.

Такой граф называется DAG:

```text
Directed Acyclic Graph
```

Если в графе есть ориентированный цикл, топологической сортировки нет.

Почему? Если есть цикл:

```text
a -> b -> c -> a
```

то по ребрам нужно:

```text
a раньше b
b раньше c
c раньше a
```

Это невозможно.

В лекции отдельно отмечено:

- топологическая сортировка применяется только для ациклических ориентированных графов;
- она сортирует граф так, что для любой дуги `(u, v)` вершина `u` будет перед `v`;
- один из алгоритмов — DFS: каждую черную вершину помещаем в стек, затем достаем все вершины из стека;
- также упоминается алгоритм Демукрона;
- с помощью топологической сортировки можно проверять гамильтонов путь в DAG;
- в DAG топологический порядок помогает искать кратчайшие пути.

## Логика работы (пошагово + псевдокод)

### Алгоритм через DFS и стек

Идея:

1. Запускаем DFS.
2. Когда вершина полностью обработана, то есть становится `black`, кладем ее в стек или добавляем в список ответа.
3. После завершения DFS достаем вершины из стека.

Почему это работает?

Если есть ребро `u -> v`, то `u` должен стоять раньше `v`. При DFS возможны разные случаи, но для DAG нет ребра в серую вершину, то есть нет обратного ребра. В результате время выхода `u` будет больше времени выхода `v`, если `v` достижима из `u`. Поэтому сортировка по убыванию времени выхода дает топологический порядок.

Псевдокод:

```text
TopologicalSort(G):
    for v in V:
        color[v] = white

    ans = empty list
    hasCycle = false

    for v in V:
        if color[v] == white:
            DFS(v)

    if hasCycle:
        return "topological order does not exist"

    reverse(ans)
    return ans

DFS(v):
    color[v] = gray

    for to in adj[v]:
        if color[to] == white:
            DFS(to)
        else if color[to] == gray:
            hasCycle = true

    color[v] = black
    ans.pushBack(v)
```

Здесь `ans.pushBack(v)` выполняется на выходе из вершины. Поэтому в конце список надо развернуть.

Эквивалентная формулировка из лекции:

```text
topologicalSort():
    проверить граф G на ацикличность
    fill(visited, false)

    for v in V(G):
        if not visited[v]:
            dfs(v)

    ans.reverse()

dfs(u):
    visited[u] = true

    for edge u -> v in E(G):
        if not visited[v]:
            dfs(v)

    ans.pushBack(u)
```

Если используется стек:

```text
DFS(v):
    visited[v] = true

    for to in adj[v]:
        if not visited[to]:
            DFS(to)

    stack.push(v)

После DFS:
    while stack not empty:
        print(stack.pop())
```

### Алгоритм Демукрона

Алгоритм Демукрона — это послойный алгоритм топологической сортировки.

Он похож на алгоритм Кана:

1. Считаем входящие степени `indegree[v]`.
2. Находим все вершины с `indegree = 0`.
3. Эти вершины образуют первый слой.
4. Удаляем их из графа вместе с исходящими ребрами.
5. Уменьшаем входящие степени их соседей.
6. Новые вершины с `indegree = 0` образуют следующий слой.
7. Повторяем, пока вершины не закончатся.

Если на каком-то шаге вершины остались, но нет ни одной вершины с нулевой входящей степенью, значит в графе есть цикл.

Псевдокод:

```text
Demukron(G):
    for v in V:
        indegree[v] = 0

    for u in V:
        for v in adj[u]:
            indegree[v] = indegree[v] + 1

    layers = empty list
    remaining = |V|

    while remaining > 0:
        layer = all vertices v not removed with indegree[v] == 0

        if layer is empty:
            return "cycle exists"

        layers.push(layer)

        for u in layer:
            mark u as removed
            remaining = remaining - 1

            for v in adj[u]:
                indegree[v] = indegree[v] - 1

    return layers
```

Если нужен линейный порядок, можно выписывать вершины слоями. Внутри одного слоя порядок может быть произвольным.

## Структура данных

Для DFS-варианта:

- `adj[v]` — список исходящих ребер;
- `color[v]` — `white`, `gray`, `black`;
- `ans` — список вершин в порядке выхода;
- `stack` — если используем стек вместо разворота списка;
- `hasCycle` — флаг наличия цикла.

Для алгоритма Демукрона:

- `adj[v]` — список исходящих ребер;
- `indegree[v]` — число входящих ребер;
- `removed[v]` — удалена ли вершина;
- `layer` — текущий слой нулевой входящей степени;
- `layers` — список слоев.

Для эффективной версии послойного алгоритма можно хранить очередь вершин с нулевой входящей степенью.

Тогда это будет классический алгоритм Кана:

```text
Q = all vertices with indegree 0
while Q not empty:
    u = Q.pop()
    ans.push(u)
    for v in adj[u]:
        indegree[v]--
        if indegree[v] == 0:
            Q.push(v)
```

Разница в акценте:

- Кана обычно выдает один линейный порядок;
- Демукрон естественно выдает слои.

## Сложность по времени и памяти

При списке смежности DFS-вариант:

$$
O(|V|+|E|)
$$

Потому что:

- каждая вершина посещается один раз;
- каждое ребро просматривается один раз.

Память:

$$
O(|V|)
$$

на цвета, ответ и стек рекурсии, плюс хранение графа.

Алгоритм Демукрона:

- подсчет входящих степеней: `O(V+E)`;
- удаление вершин и ребер: `O(V+E)`.

Итого:

$$
O(|V|+|E|)
$$

если эффективно поддерживать вершины с нулевой входящей степенью.

Если каждый раз заново сканировать все вершины для поиска нового слоя, может появиться дополнительный множитель и сложность станет хуже, например `O(V^2 + E)`.

Память:

- `indegree`: `O(V)`;
- очередь или слой: `O(V)`;
- ответ: `O(V)`.

## Ограничения

Топологическая сортировка определена только для ориентированных графов.

Для неориентированного графа условие «ребро должно идти слева направо» обычно не имеет смысла, потому что ребро не задает направление зависимости.

Топологический порядок существует только если нет ориентированных циклов.

Если граф имеет несколько компонент, топологическая сортировка все равно возможна: вершины разных компонент могут перемешиваться, если между ними нет зависимостей.

Топологический порядок не обязан быть единственным.

Пример:

```text
1 -> 3
2 -> 3
```

Корректны оба порядка:

```text
1, 2, 3
2, 1, 3
```

DFS-вариант зависит от порядка перебора вершин и порядка соседей.

Алгоритм с входящими степенями зависит от порядка извлечения вершин с `indegree = 0`.

## Применимость

Топологическая сортировка используется там, где есть зависимости:

- порядок выполнения задач;
- сборка проектов;
- зависимости пакетов;
- учебные курсы и prerequisites;
- вычисления в DAG;
- динамическое программирование по DAG;
- кратчайшие пути в DAG;
- проверка возможности расписания;
- анализ направленных ациклических графов.

В лекции отмечено, что топологическая сортировка помогает находить кратчайшие пути в DAG. Если граф ациклический, можно обработать вершины в топологическом порядке и релаксировать исходящие ребра.

Также в лекции указано, что с помощью топологической сортировки можно найти гамильтонов путь.

Для DAG это делается так:

1. Найти топологический порядок:

```text
v1, v2, ..., vn
```

2. Проверить, есть ли ребро:

```text
v_i -> v_{i+1}
```

для каждого `i` от 1 до `n-1`.

3. Если все такие ребра есть, то этот порядок задает гамильтонов путь.

Почему это корректно для DAG:

- любой гамильтонов путь в DAG должен согласовываться с топологическим порядком;
- если между каждой соседней парой в топологическом порядке есть ребро, то получаем путь через все вершины.

## Примеры с разбором

Пусть есть зависимости:

```text
1 -> 3
2 -> 3
3 -> 4
2 -> 5
5 -> 4
```

Список смежности:

```text
adj[1] = [3]
adj[2] = [3, 5]
adj[3] = [4]
adj[4] = []
adj[5] = [4]
```

### DFS-вариант

Запускаем DFS с вершины 1:

```text
1 -> 3 -> 4
```

На выходе добавляем:

```text
4, потом 3, потом 1
```

Дальше вершина 2 еще белая:

```text
2 -> 5
```

Вершина 3 уже черная, 5 ведет в 4, которая тоже черная.

На выходе добавляем:

```text
5, потом 2
```

Список выходов:

```text
[4, 3, 1, 5, 2]
```

Разворачиваем:

```text
[2, 5, 1, 3, 4]
```

Проверим ребра:

- `1 -> 3`: 1 перед 3;
- `2 -> 3`: 2 перед 3;
- `3 -> 4`: 3 перед 4;
- `2 -> 5`: 2 перед 5;
- `5 -> 4`: 5 перед 4.

Порядок корректен.

### Демукрон

Входящие степени:

```text
indegree[1] = 0
indegree[2] = 0
indegree[3] = 2
indegree[4] = 2
indegree[5] = 1
```

Первый слой:

```text
{1, 2}
```

Удаляем 1 и 2:

- у 3 входящая степень уменьшается с 2 до 0;
- у 5 уменьшается с 1 до 0.

Второй слой:

```text
{3, 5}
```

Удаляем 3 и 5:

- у 4 входящая степень уменьшается с 2 до 0.

Третий слой:

```text
{4}
```

Один возможный топологический порядок:

```text
1, 2, 3, 5, 4
```

или:

```text
2, 1, 5, 3, 4
```

если внутри слоев выбрать другой порядок.

## Типичные ошибки / вопросы на экзамен

Типичные ошибки:

- пытаться топологически сортировать граф с циклом;
- забывать проверку на цикл в DFS-варианте;
- добавлять вершину в ответ при входе, а не при выходе;
- забывать развернуть список после DFS;
- считать, что топологический порядок всегда единственный;
- применять алгоритм к неориентированному графу;
- путать входящую и исходящую степень в алгоритме Демукрона;
- при удалении вершины уменьшать степени не тех соседей;
- не запускать DFS из всех компонент.

Вопросы на экзамен:

1. Что такое топологическая сортировка?
2. Для каких графов она существует?
3. Почему цикл мешает топологическому порядку?
4. Как получить топологический порядок через DFS?
5. Почему вершину добавляют в ответ на выходе?
6. Как работает алгоритм Демукрона?
7. Какая сложность топологической сортировки?
8. Может ли быть несколько топологических порядков?
9. Как через топологический порядок проверить гамильтонов путь в DAG?
10. Как использовать топологический порядок для кратчайших путей в DAG?

Короткие ответы:

- Это порядок вершин, где каждое ребро `u -> v` идет от более ранней вершины к более поздней.
- Существует только в DAG.
- DFS-вариант сортирует по убыванию времени выхода.
- Демукрон удаляет слои вершин с нулевой входящей степенью.
- Сложность при списке смежности `O(V+E)`.

## Дополнительно (доказательства идей, варианты)

### Доказательство DFS-варианта

В DAG при DFS не существует ребра в серую вершину, потому что такое ребро означало бы цикл.

Рассмотрим любое ребро:

```text
u -> v
```

Нужно показать, что в итоговом порядке `u` стоит раньше `v`.

DFS добавляет вершины в список при выходе, а потом список разворачивается.

Если DFS из `u` зашел в `v`, то `v` завершится раньше `u`, значит `v` попадет в список раньше, а после разворота `u` будет раньше `v`.

Если `v` уже была обработана раньше, то ее время выхода уже меньше или больше в зависимости от порядка обхода, но в DAG невозможна ситуация, которая нарушила бы порядок для ребра `u -> v`. Для такого ребра выполняется:

$$
tout[u] > tout[v]
$$

Поэтому сортировка по убыванию `tout` корректна.

### Связь с леммой о белых путях

Лемма о белых путях помогает понять, почему DFS полностью обрабатывает все достижимые из вершины белые вершины перед выходом из нее.

Если из `u` есть путь к `v`, и `v` была белой при входе в `u`, то `v` станет потомком `u` в DFS-дереве. Значит, `v` завершится раньше `u`.

Это и дает порядок по убыванию времени выхода.

### Проверка уникальности топологического порядка

В алгоритме Кана:

- если на каждом шаге есть ровно одна вершина с нулевой входящей степенью, порядок единственный;
- если на каком-то шаге таких вершин несколько, можно выбрать разные варианты, и порядок не единственный.

### Динамика по DAG

Если вершины обработаны в топологическом порядке, то все предшественники вершины уже обработаны.

Это позволяет решать задачи вида:

```text
dp[v] = function(dp[u] for all u -> v)
```

Например, длина самого длинного пути в DAG:

```text
for v in topological_order:
    for to in adj[v]:
        dp[to] = max(dp[to], dp[v] + 1)
```

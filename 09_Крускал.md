# 09. Алгоритм Крускала

## Введение

Алгоритм Крускала строит минимальное остовное дерево во взвешенном неориентированном графе. Минимальное остовное дерево, или MST, - это набор ребер, который соединяет все вершины, не содержит циклов и имеет минимальную возможную сумму весов.

Если граф несвязный, вместо одного остовного дерева получится минимальный остовный лес: по одному MST для каждой компоненты связности.

Главная идея Крускала очень жадная: сортируем все ребра по весу и берем самые дешевые, если они не создают цикл.

## Основные определения

Остовное дерево графа `G = (V, E)` - это подграф, который:

- содержит все вершины `V`;
- является деревом;
- имеет ровно `V - 1` ребро, если исходный граф связный.

Минимальное остовное дерево - остовное дерево с минимальной суммой весов ребер.

Алгоритм работает для неориентированных графов. Веса могут быть отрицательными: это не мешает, потому что сравнение ребер по весу сохраняется.

## Логика алгоритма

Алгоритм Крускала:

1. Отсортировать все ребра по неубыванию веса.
2. Изначально каждая вершина - отдельная компонента.
3. Перебирать ребра от самого легкого к самому тяжелому.
4. Для ребра `(u, v)` проверить, лежат ли `u` и `v` в разных компонентах.
5. Если в разных, добавить ребро в ответ и объединить компоненты.
6. Если в одной, пропустить ребро, потому что оно создает цикл.
7. Остановиться, когда в ответе `V - 1` ребро.

Ключевой факт: для проверки и объединения компонент используется DSU, он же СНМ - система непересекающихся множеств.

## Почему жадность корректна

Интуитивное обоснование строится на свойстве разреза.

Если разделить вершины графа на две части, то самое легкое ребро, пересекающее этот разрез, можно безопасно добавить в некоторое минимальное остовное дерево.

В Крускале текущие компоненты задают такие разрезы. Когда алгоритм берет минимальное ребро между двумя разными компонентами, он выбирает безопасное ребро: оно соединяет части дерева и не создает цикл.

Если ребро соединяет вершины внутри одной компоненты, оно уже замыкает цикл, а дереву цикл не нужен.

## Псевдокод

```text
edges.sort by weight
dsu.init(V)
answer = []
totalWeight = 0

for edge in edges:
    (w, u, v) = edge
    if dsu.find(u) != dsu.find(v):
        dsu.union(u, v)
        answer.push(edge)
        totalWeight += w

        if len(answer) == V - 1:
            break
```

После завершения:

- если `len(answer) == V - 1`, найдено MST;
- если меньше, граф был несвязным, найден минимальный остовный лес.

## DSU / СНМ

DSU хранит разбиение вершин на непересекающиеся множества.

Операции:

- `find(v)` - найти представителя множества, в котором лежит `v`;
- `union(a, b)` - объединить множества, содержащие `a` и `b`.

Оптимизации:

- сжатие путей в `find`;
- объединение по размеру или рангу.

С этими оптимизациями операции работают почти за `O(1)` амортизированно, точнее `O(alpha(V))`, где `alpha` - обратная функция Аккермана.

## Структуры данных

Нужны:

- массив ребер `edges`, элементы вида `(weight, u, v)`;
- DSU: массив `parent[v]`;
- для оптимизации DSU: `rank[v]` или `size[v]`;
- список ребер ответа `answer`;
- переменная `totalWeight`.

Граф в Крускале удобнее хранить именно списком ребер, а не списком смежности.

## Сложность

Основная стоимость - сортировка ребер:

```text
время: O(E log E)
память: O(V + E)
```

Разбор:

- сортировка: `O(E log E)`;
- `E` операций `find` и до `V - 1` операций `union`: `O(E alpha(V))`;
- итог доминируется сортировкой.

Так как в простом графе `E <= V^2`, часто пишут, что `log E = O(log V^2) = O(log V)`, но классическая запись для Крускала - `O(E log E)`.

## Ограничения

Алгоритм предназначен для неориентированного графа. Для ориентированных графов задача минимального остовного дерева в таком виде не определена.

Если граф несвязный, MST на всех вершинах не существует. Крускал вернет лес.

Нужно аккуратно работать с параллельными ребрами: они разрешены, сортировка сама выберет подходящие более дешевые.

Петли `(v, v)` всегда создают цикл и никогда не нужны в MST.

## Применимость

Крускал особенно удобен, когда:

- граф задан списком ребер;
- граф разреженный;
- нужно быстро написать MST через сортировку и DSU;
- ребра удобно сортировать один раз;
- требуется минимальный остовный лес для несвязного графа.

Примеры задач:

- построение дешевой сети дорог, кабелей или труб;
- кластеризация через удаление самых дорогих ребер MST;
- нахождение минимальной стоимости соединения объектов;
- проверка структуры графа через остов.

## Примеры

### Пример из лекции (Теория графов III–IV)

Вершины: `a, b, c, d, e`. Рёбра, отсортированные по весу:

| Ребро | Вес | Решение |
|---|---|---|
| ae | 1 | `+` добавляем (нет цикла) |
| cd | 2 | `+` добавляем |
| ab | 3 | `+` добавляем |
| be | 4 | `X` отказ: цикл `a-e-b-a` |
| bc | 5 | далее по правилам |
| ec | 6 | … |
| ed | 7 | … |

Шаг с `ab`: рёбра `ae` и `cd` уже в MST, `ab` не замыкает цикл → добавляем.

Шаг с `be`: вершины `b` и `e` уже связаны через `a` (путь `b-a-e`), поэтому `be` даёт цикл и **не** берётся — иначе ответ перестанет быть деревом.

### Короткий числовой пример

Пусть рёбра:

```text
(1, 2, вес 1)
(2, 3, вес 2)
(1, 3, вес 3)
(3, 4, вес 4)
(2, 4, вес 5)
```

Ход:

1. `(1, 2, 1)` — разные компоненты, добавляем.
2. `(2, 3, 2)` — добавляем.
3. `(1, 3, 3)` — уже одна компонента, пропускаем.
4. `(3, 4, 4)` — добавляем.

Ответ: рёбра `(1,2), (2,3), (3,4)`, вес `1+2+4=7`.

## Типичные ошибки

- Забыть отсортировать ребра.
- Использовать DFS для проверки цикла на каждом шаге и получить слишком медленное решение.
- Не применять DSU/СНМ.
- Добавлять ребро, если вершины уже в одной компоненте.
- Не проверять, что граф связный, когда требуется именно дерево.
- Путать Крускала с Примом: Крускал сортирует ребра глобально, Прим растит одно дерево из стартовой вершины.

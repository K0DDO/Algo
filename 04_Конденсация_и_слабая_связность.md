# Конденсация графа и слабая связность

## Введение / определения с нуля

В графах часто нужно понимать, из каких крупных частей состоит граф.

Для неориентированного графа базовое понятие — компонента связности.

Две вершины находятся в одной компоненте связности, если между ними есть путь.

Для ориентированного графа есть несколько разных понятий:

- достижимость с учетом направления ребер;
- слабая связность;
- сильная связность;
- конденсация графа.

### Слабая связность

Ориентированный граф называется слабо связным, если после замены всех ориентированных ребер на неориентированные граф становится связным.

То есть направление ребер игнорируется.

Пример:

```text
1 -> 2 <- 3
```

Из 1 нельзя дойти до 3 по направлениям ребер. Но если забыть направления, получится:

```text
1 -- 2 -- 3
```

Значит, все три вершины лежат в одной компоненте слабой связности.

В лекции сказано: компоненты слабой связности ищутся с помощью вспомогательного неориентированного графа и обхода по нему с пометкой вершин компонентами исходного графа.

### Сильная связность

В ориентированном графе две вершины `u` и `v` сильно связаны, если:

- из `u` достижима `v`;
- из `v` достижима `u`.

Компонента сильной связности, или SCC, — максимальное множество вершин, в котором каждая вершина достижима из каждой другой.

Например:

```text
1 -> 2 -> 3
^         |
|         v
+---------+
```

Вершины 1, 2, 3 лежат в одной компоненте сильной связности, потому что по циклу можно добраться из любой в любую.

### Конденсация графа

Конденсация ориентированного графа — это новый граф, в котором:

- каждая вершина соответствует одной компоненте сильной связности исходного графа;
- между компонентами есть ребро, если в исходном графе было ребро из вершины одной компоненты в вершину другой.

Конденсация всегда является DAG, то есть ориентированным ациклическим графом.

Почему? Если бы в конденсации был цикл компонент, то все компоненты из этого цикла были бы достижимы друг из друга, значит они должны были бы быть одной компонентой сильной связности.

## Логика работы (пошагово + псевдокод)

### Компоненты связности в неориентированном графе

Через DFS:

```text
FindComponents(G):
    for v in V:
        color[v] = white
        component[v] = 0

    count = 0

    for v in V:
        if color[v] == white:
            count = count + 1
            DFS(v, count)

DFS(v, count):
    color[v] = gray
    component[v] = count

    for to in adj[v]:
        if color[to] == white:
            DFS(to, count)

    color[v] = black
```

Это соответствует лекционной идее: если после очередного обхода остались непройденные вершины, запускаем обход из них и увеличиваем номер компоненты.

Можно использовать и BFS, если вместо рекурсии взять очередь.

### Компоненты слабой связности

Пусть исходный граф ориентированный.

Пошагово:

1. Построить неориентированную копию графа `U`.
2. Для каждого ориентированного ребра `u -> v` добавить в `U` два перехода:

```text
u -- v
```

то есть:

```text
U.adj[u].push(v)
U.adj[v].push(u)
```

3. Запустить DFS или BFS по `U`.
4. Номера компонент, найденные в `U`, будут номерами компонент слабой связности исходного графа.

Псевдокод:

```text
WeakComponents(G):
    U = empty undirected graph with same vertices

    for u in V:
        for v in G.adj[u]:
            U.adj[u].push(v)
            U.adj[v].push(u)

    return FindComponents(U)
```

### Алгоритм Косарайю для SCC

В лекции компоненты сильной связности предлагается искать через DFS в 3 этапа:

1. Построить граф `H` с обратными, инвертированными ребрами.
2. Выполнить DFS и найти `f[u]` — время окончания обработки вершины `u`.
3. Выполнить DFS во втором графе, перебирая вершины в порядке убывания `f[u]`.

В лекционном тексте также указано, что компоненты сильной связности графов `G` и `H` совпадают, поэтому можно:

- первый DFS выполнить на `G`, складывая вершины в стек по времени выхода;
- второй DFS выполнить на обратном графе `H`;
- или наоборот.

Ниже вариант: первый DFS по `G`, второй по `H`.

Псевдокод:

```text
Kosaraju(G):
    H = reverseGraph(G)
    visited[v] = false for all v
    stack = empty stack

    for v in V:
        if not visited[v]:
            dfsG(v)

    component[v] = 0 for all v
    count = 0

    while stack is not empty:
        v = stack.pop()
        if component[v] == 0:
            count = count + 1
            dfsH(v, count)

    return component, count

dfsG(v):
    visited[v] = true

    for to in G.adj[v]:
        if not visited[to]:
            dfsG(to)

    stack.push(v)

dfsH(v, count):
    component[v] = count

    for to in H.adj[v]:
        if component[to] == 0:
            dfsH(to, count)
```

Это совпадает с лекционным псевдокодом:

- `dfsG` помечает вершины и кладет их в `stack` после обработки;
- `dfsH` присваивает номер компоненты;
- внешний цикл достает вершины из стека.

### Построение конденсации

После нахождения `component[v]` строим граф компонент.

Пошагово:

1. Пусть всего `k` компонент.
2. Создаем граф `C` с вершинами `1..k`.
3. Для каждого ребра `u -> v` исходного графа:
   - `cu = component[u]`;
   - `cv = component[v]`;
   - если `cu != cv`, добавить ребро `cu -> cv` в конденсацию.
4. Дубликаты ребер можно удалить с помощью множеств.

Псевдокод:

```text
BuildCondensation(G, component, k):
    C = graph with vertices 1..k

    for u in V:
        for v in G.adj[u]:
            cu = component[u]
            cv = component[v]

            if cu != cv:
                C.addEdge(cu, cv)

    remove duplicate edges if needed
    return C
```

## Структура данных

Для слабой связности:

- `G.adj` — исходный ориентированный граф;
- `U.adj` — вспомогательный неориентированный граф;
- `color[v]` или `visited[v]`;
- `component[v]`;
- очередь для BFS или стек/рекурсия для DFS.

Для Косарайю:

- `G.adj` — исходный граф;
- `H.adj` — обратный граф;
- `visited[v]`;
- `stack` или список `order`;
- `component[v]`;
- `count` — число компонент.

Обратный граф строится так:

```text
for u in V:
    for v in G.adj[u]:
        H.adj[v].push(u)
```

Для конденсации:

- `component[v]` — номер SCC вершины;
- `condAdj[c]` — список соседних компонент;
- `set` для удаления повторяющихся ребер.

Если повторяющиеся ребра не мешают задаче, их можно оставить. Но для аккуратной конденсации обычно дубликаты удаляют.

## Сложность по времени и памяти

### Слабая связность

Построение неориентированной копии:

$$
O(|V|+|E|)
$$

Обход DFS или BFS:

$$
O(|V|+|E|)
$$

Итого:

$$
O(|V|+|E|)
$$

Память:

- исходный граф: `O(V+E)`;
- неориентированная копия: `O(V+E)`;
- массивы обхода: `O(V)`.

В лекции также указано: для слабой связности нужен дополнительный дубль хранения неориентированного варианта графа, если мы не хотим обходить ребра в обе стороны другим способом.

### Косарайю

Построение обратного графа:

$$
O(|V|+|E|)
$$

Первый DFS:

$$
O(|V|+|E|)
$$

Второй DFS:

$$
O(|V|+|E|)
$$

Итого:

$$
O(|V|+|E|)
$$

Память:

- `G`: `O(V+E)`;
- `H`: `O(V+E)`;
- `visited`, `component`, `stack`: `O(V)`.

### Конденсация

Построение по всем ребрам:

$$
O(|V|+|E|)
$$

Если удаляем дубликаты через множества, сложность зависит от реализации, но обычно остается линейной или близкой к линейной по числу ребер.

## Ограничения

Слабая связность игнорирует направления ребер. Поэтому она не отвечает на вопрос «можно ли дойти из `u` в `v` по направлению».

Сильная связность учитывает направления, но объединяет только взаимно достижимые вершины.

Косарайю требует:

- два DFS;
- обратный граф;
- память на стек порядка выхода.

Если граф очень большой, хранение обратного графа может быть дорогим.

Рекурсивный DFS может переполнить стек.

Номера компонент зависят от порядка обхода. Обычно важны не сами номера, а разбиение вершин на группы.

Конденсация может иметь меньше вершин, чем исходный граф, но в худшем случае число компонент равно `|V|`.

## Применимость

Слабая связность нужна, когда направление ребер не важно для грубой связности.

Примеры:

- понять, какие вершины принадлежат одному фрагменту сети;
- разбить ориентированный граф на части, если направления временно игнорируются;
- анализировать слабые компоненты веб-графа или графа ссылок.

Компоненты сильной связности нужны, когда важна взаимная достижимость.

Примеры:

- анализ зависимостей модулей;
- поиск циклических зависимостей;
- задачи на 2-SAT;
- оптимизация графов;
- сжатие графа до DAG;
- анализ состояний автоматов.

Конденсация полезна, потому что превращает произвольный ориентированный граф в DAG компонент.

После этого можно применять алгоритмы для DAG:

- топологическую сортировку;
- динамику по DAG;
- поиск источников и стоков компонент;
- анализ порядка зависимостей.

## Примеры с разбором

Рассмотрим ориентированный граф:

```text
1 -> 2
2 -> 3
3 -> 1
3 -> 4
4 -> 5
5 -> 4
6 -> 5
```

### Слабая связность

Если забыть направления:

```text
1 -- 2 -- 3 -- 4 -- 5 -- 6
```

Все вершины соединены в одной неориентированной компоненте.

Значит, компонент слабой связности одна:

```text
{1, 2, 3, 4, 5, 6}
```

### Сильная связность

Вершины 1, 2, 3:

```text
1 -> 2 -> 3 -> 1
```

Они взаимно достижимы, значит:

```text
SCC1 = {1, 2, 3}
```

Вершины 4 и 5:

```text
4 -> 5
5 -> 4
```

Значит:

```text
SCC2 = {4, 5}
```

Вершина 6 имеет ребро в 5, но из 5 нельзя вернуться в 6.

Значит:

```text
SCC3 = {6}
```

### Конденсация

Компоненты:

```text
A = {1, 2, 3}
B = {4, 5}
C = {6}
```

Ребро `3 -> 4` дает:

```text
A -> B
```

Ребро `6 -> 5` дает:

```text
C -> B
```

Конденсация:

```text
A -> B
C -> B
```

Это DAG.

### Косарайю на этом графе

Первый DFS кладет вершины в стек по времени выхода.

Если начать с 1, можно пройти:

```text
1 -> 2 -> 3 -> 4 -> 5
```

На выходе в стек попадут:

```text
5, 4, 3, 2, 1
```

Потом отдельно обработается 6:

```text
6
```

Порядок в стеке зависит от порядка обхода, но второй DFS по обратному графу, доставая вершины по убыванию времени выхода, выделит SCC.

Например, если первой достается 6, в обратном графе из 6 никуда не уйти, получаем `{6}`.

Если достается 1, обратные ребра внутри цикла позволяют собрать `{1,2,3}`.

Если достается 4 или 5, собирается `{4,5}`.

## Типичные ошибки / вопросы на экзамен

Типичные ошибки:

- путать слабую и сильную связность;
- искать слабую связность в исходном ориентированном графе, не добавив обратные переходы;
- считать, что компонента слабой связности означает взаимную достижимость;
- забывать построить обратный граф для Косарайю;
- выполнять второй DFS не в порядке убывания времени выхода;
- добавлять ребра внутри одной SCC в конденсацию;
- не удалять дубликаты ребер, когда это важно;
- думать, что конденсация может иметь цикл;
- путать компоненты связности неориентированного графа и SCC ориентированного.

Вопросы на экзамен:

1. Что такое слабая связность?
2. Как найти компоненты слабой связности?
3. Что такое сильная связность?
4. Что такое компонента сильной связности?
5. Как работает алгоритм Косарайю?
6. Зачем нужен обратный граф `H`?
7. Почему второй DFS идет по убыванию времени выхода?
8. Что такое конденсация графа?
9. Почему конденсация является DAG?
10. Какова сложность поиска SCC алгоритмом Косарайю?

Короткие ответы:

- Слабая связность игнорирует направления ребер.
- Для слабой связности строят неориентированную копию и запускают DFS/BFS.
- SCC — максимальное множество взаимно достижимых вершин.
- Косарайю: DFS для времен выхода, обратный граф, второй DFS по убыванию выхода.
- Конденсация всегда ациклична.

## Дополнительно (доказательства идей, варианты)

### Почему SCC одинаковы в графе и обратном графе

Если `u` и `v` взаимно достижимы в `G`, то:

```text
u ->* v
v ->* u
```

В обратном графе все пути разворачиваются:

```text
v ->* u
u ->* v
```

То есть взаимная достижимость сохраняется.

Поэтому компоненты сильной связности у `G` и `H` совпадают.

### Почему конденсация ациклична

Предположим, в конденсации есть цикл:

```text
C1 -> C2 -> ... -> Ck -> C1
```

Тогда из любой компоненты цикла можно добраться до любой другой по ребрам конденсации.

Значит, любые вершины из этих компонент взаимно достижимы в исходном графе.

Но тогда эти компоненты должны были быть одной SCC, а не разными.

Противоречие.

### Почему порядок Косарайю работает

На уровне конденсации SCC образуют DAG.

Первый DFS по времени выхода помогает выбрать компоненту, из которой во втором проходе по обратному графу нельзя «утечь» в еще не назначенные чужие компоненты.

Если брать вершины в неправильном порядке, второй DFS может слить несколько компонент вместе.

Порядок убывания времени выхода предотвращает это.

### Альтернативы

Кроме Косарайю есть:

- алгоритм Тарьяна;
- алгоритм Габова.

Тарьян находит SCC за один DFS и не требует явного обратного графа, но его сложнее понять с нуля.

Косарайю проще для экзамена:

```text
первый DFS -> стек по выходу -> обратный граф -> второй DFS
```

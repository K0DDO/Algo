# 22. Префикс-функция

## Определение

Префикс-функция строки `S` - это массив `pi`, где `pi[i]` равно длине наибольшего собственного префикса строки `S[0..i]`, который одновременно является ее суффиксом.

Собственный префикс - это префикс, не равный всей строке. Поэтому для первого символа:

```text
pi[0] = 0
```

Пример из лекции:

```text
P:  A B A C A B A B A C B
pi: 0 0 1 0 1 2 3 2 3 4 0
```

Еще примеры:

```text
pref("ABABAB") = "ABAB"
pref("ABCAAB") = "AB"
pref("AB")     = ""
```

## Интуиция

`pi[i]` отвечает на вопрос: какой самый длинный кусок начала строки уже совпадает с концом префикса `S[0..i]`.

Например, для строки `ababa`:

- у `a` нет собственного префикса-суффикса: `0`;
- у `aba` есть `a`: `1`;
- у `ababa` есть `aba`: `3`.

Префикс-функция нужна, чтобы при несовпадении символов не начинать сравнение заново, а перейти к следующему возможному совпадающему префиксу.

## Логика вычисления

Пусть мы уже посчитали `pi[0..i-1]` и хотим найти `pi[i]`.

Обозначим:

```text
k = pi[i - 1]
```

Это длина лучшего префикса-суффикса для предыдущей позиции. Мы пробуем продлить его символом `S[i]`.

Если:

```text
S[k] == S[i]
```

то можно увеличить совпадение:

```text
pi[i] = k + 1
```

Если символы не совпали, нужно взять более короткий префикс, который тоже является суффиксом. Он уже известен:

```text
k = pi[k - 1]
```

Так повторяем, пока либо найдем совпадение, либо `k` станет нулем.

## Алгоритм

```text
prefix_function(S):
    pi = array(len(S), 0)
    for i = 1..len(S)-1:
        k = pi[i - 1]
        while k > 0 and S[k] != S[i]:
            k = pi[k - 1]
        if S[k] == S[i]:
            k += 1
        pi[i] = k
    return pi
```

## Почему алгоритм линейный

На первый взгляд есть вложенный `while`, поэтому может казаться, что сложность `O(n^2)`. Но в лекции разбирается амортизационная идея:

- индекс `i` только растет и делает не больше `n` шагов;
- значение `k` может увеличиваться только после успешного совпадения;
- каждое уменьшение `k = pi[k-1]` компенсирует ранее сделанное увеличение;
- в худшем случае суммарно будет не больше `2n` существенных движений.

Поэтому сложность:

```text
O(n)
```

Память:

```text
O(n)
```

## Пример ручного счета

Возьмем строку:

```text
S = abacababacb
```

Из лекции для нее:

```text
S:  a b a c a b a b a c b
pi: 0 0 1 0 1 2 3 2 3 4 0
```

Ключевой момент на позиции, где возникает откат: если мы ожидали продолжить префикс длины `3`, но символ не совпал, мы не пробуем все длины подряд. Мы переходим к `pi[2]`, потом при необходимости к `pi[pi[2]-1]` и так далее.

## Использование для поиска подстроки

Чтобы найти образец `P` в тексте `T`, можно построить строку:

```text
S = P + "#" + T
```

где `#` - символ-разделитель, который не встречается ни в `P`, ни в `T`.

Затем считаем `pi` для `S`. Если в позиции `i`:

```text
pi[i] == |P|
```

то найдено вхождение образца, заканчивающееся в этой позиции. Начало в тексте:

```text
i - 2 * |P|
```

если считать индексы в объединенной строке с разделителем. Эквивалентно можно аккуратно пересчитать через позицию в `T`.

## Потоковый поиск

В лекции отдельно отмечено, что префикс-функция удобна для real-time обработки текста.

Не обязательно хранить всю строку `P#T`. Достаточно:

- заранее посчитать `pi` только для образца `P`;
- хранить `k` - текущую длину совпавшего префикса;
- читать текст по одному символу;
- при несовпадении откатывать `k = pi[k - 1]`;
- при `k == |P|` фиксировать вхождение и откатываться дальше.

Память:

```text
O(|P|)
```

Время:

```text
O(|P| + |T|)
```

При этом обработка одного символа в худшем случае может занять `O(|P|)`, но суммарно по всему тексту время линейное.

## Структуры данных

- Строка `S` или только образец `P`.
- Массив `pi`.
- Переменная `k`, если считаем потоково.
- Массив ответов для позиций вхождений.

## Ограничения

- Нужен разделитель, которого нет в строках, если используется конструкция `P#T`.
- Алгоритм ищет точные совпадения, а не приблизительные.
- Для динамически меняющегося образца `pi` придется пересчитывать.
- Для множества образцов лучше подходит Ахо-Корасик.

## Где применяется

- КМП для поиска подстроки.
- Построение автомата поиска одной подстроки.
- Поиск периодов строки.
- Проверка бордеров строки: префиксов, которые являются суффиксами.
- Задачи на сжатие, повторы и строки в олимпиадном программировании.

## Типичные ошибки

- Считать `pi[i]` для `S[0..i-1]`, но реализовывать для `S[0..i]` или наоборот. Важно зафиксировать индексацию.
- Забыть условие `k > 0` в цикле отката.
- После полного совпадения в КМП не откатить `k`, из-за чего пропускаются перекрывающиеся вхождения.
- Использовать разделитель, который встречается в тексте.

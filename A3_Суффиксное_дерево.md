# A3. Суффиксное дерево

## Идея

Суффиксное дерево - это сжатый бор всех суффиксов строки.

Если взять строку `S` и добавить в бор все суффиксы, получится суффиксный бор. Он прост, но может иметь `O(n^2)` вершин.

Суффиксное дерево сжимает цепочки вершин с одним ребенком в одно ребро. Ребро подписывается не одним символом, а подстрокой `S[l..r]`.

Так размер становится линейным:

```text
O(n)
```

при условии, что ребра хранятся как пары индексов в исходной строке, а не как отдельные копии подстрок.

## Терминатор

К строке обычно добавляют уникальный символ `$`, которого нет в алфавите:

```text
S = S + "$"
```

Терминатор нужен, чтобы:

- ни один суффикс не был префиксом другого;
- каждый суффикс заканчивался в отдельном листе;
- дерево имело корректную структуру.

Например, для `banana$` суффиксы:

```text
banana$
anana$
nana$
ana$
na$
a$
$
```

## Отличие от суффиксного бора

Суффиксный бор:

- ребро = один символ;
- каждая вершина соответствует некоторой подстроке;
- может иметь `O(n^2)` вершин.

Суффиксное дерево:

- ребро = целая подстрока;
- длинные цепочки сжаты;
- имеет `O(n)` вершин и ребер;
- путь от корня к листу соответствует суффиксу.

## Что хранится в вершинах и ребрах

В вершине:

- переходы по первым символам ребер;
- иногда суффиксная ссылка;
- для листа - индекс начала суффикса;
- дополнительные значения для задач: размер поддерева, цвет строки, количество листьев.

В ребре:

```text
start, end
```

Это границы подстроки исходной строки `S`.

Подпись ребра:

```text
S[start..end]
```

Хранить саму строку на ребре невыгодно, иначе можно потерять линейную память.

## Поиск подстроки

Чтобы проверить, входит ли `P` в `S`:

1. Начинаем в корне.
2. Идем по символам `P`.
3. На каждом шаге выбираем ребро, начинающееся с текущего символа.
4. Сравниваем символы `P` с подписью ребра.
5. Если `P` закончился внутри ребра или в вершине, подстрока найдена.
6. Если нужного ребра нет или символы не совпали, подстроки нет.

Сложность:

```text
O(|P|)
```

после построения дерева.

## Все вхождения подстроки

Если `P` найден и путь закончился в вершине или внутри ребра, все листья ниже этой точки соответствуют суффиксам, начинающимся с `P`.

Индексы этих листьев - позиции всех вхождений `P` в `S`.

Сложность:

```text
O(|P| + result)
```

где `result` - число найденных вхождений.

## Количество различных подстрок

В суффиксном боре каждая вершина, кроме корня, соответствовала бы некоторой подстроке. В суффиксном дереве цепочки сжаты, поэтому вклад ребра равен длине его подписи.

Количество различных подстрок:

```text
sum length(edge_label)
```

по всем ребрам дерева, если строка содержит терминатор, нужно аккуратно не считать подстроки с `$` для исходной строки.

## Самая длинная повторяющаяся подстрока

Повторяющаяся подстрока соответствует пути от корня к внутренней вершине, у которой в поддереве есть минимум два листа.

Самая длинная повторяющаяся подстрока - самая глубокая внутренняя вершина по суммарной длине ребер от корня.

Для `banana` это:

```text
ana
```

## Самая длинная общая подстрока двух строк

Для двух строк строят обобщенное суффиксное дерево:

```text
S = A + "#" + B + "$"
```

Разделители должны быть уникальными.

Листья помечают цветом:

- из строки `A`;
- из строки `B`.

Внутренняя вершина, в поддереве которой есть листья обоих цветов, соответствует общей подстроке. Самая глубокая такая вершина дает самую длинную общую подстроку.

## Суффиксные ссылки

Суффиксная ссылка в суффиксном дереве связывает вершину, соответствующую строке `aX`, с вершиной, соответствующей строке `X`, где `a` - первый символ.

Например:

```text
"banana" -> "anana"
"ana"    -> "na"
```

Суффиксные ссылки нужны для быстрых алгоритмов построения, прежде всего для алгоритма Укконена.

## Построение

Наивное построение:

1. Добавить все суффиксы в бор.
2. Сжать цепочки.

Сложность может быть:

```text
O(n^2)
```

Линейное построение:

- алгоритм Укконена строит дерево online за `O(n)`;
- алгоритм Маккрейта также строит за `O(n)`;
- можно построить суффиксное дерево из суффиксного массива и LCP за `O(n)`.

В учебных задачах часто достаточно понимать свойства дерева и уметь использовать его, а не писать Укконена с нуля.

## Алгоритм Укконена: идея без деталей реализации

Укконен добавляет символы строки по одному и поддерживает дерево для всех суффиксов текущего префикса.

Ключевые понятия:

- активная вершина;
- активное ребро;
- активная длина;
- остаток суффиксов, которые еще нужно добавить;
- суффиксные ссылки для быстрых переходов;
- открытые концы листьев, чтобы не обновлять каждый лист отдельно.

Почему сложно: нужно аккуратно разделять ребра, создавать внутренние вершины и обновлять активную точку.

## Сложность

Если дерево построено эффективным алгоритмом:

```text
Построение: O(n)
Память: O(n)
Поиск P: O(|P|)
Все вхождения P: O(|P| + result)
```

Если строить наивно:

```text
Построение: O(n^2)
Память: O(n^2) до сжатия или при плохом хранении
```

## Структуры данных

- Исходная строка `S`.
- Вершины с переходами по первым символам ребер.
- Ребра как пары индексов `(l, r)`.
- Суффиксные ссылки.
- Индексы суффиксов в листьях.
- Терминатор `$`.

## Ограничения

- Реализация сложнее, чем у суффиксного массива.
- Большие константы по памяти.
- Нужно аккуратно обрабатывать терминаторы.
- Для большинства практических задач суффиксный массив проще и компактнее.
- При динамическом изменении строки дерево обычно перестраивают.

## Сравнение с суффиксным массивом

Суффиксное дерево:

- поиск подстроки `O(|P|)`;
- легко получить все вхождения;
- удобно для многих задач на подстроки;
- сложнее реализация и больше память.

Суффиксный массив:

- проще хранить;
- построение `O(n log n)` проще реализовать;
- поиск `O(|P| log n)` в базовом варианте;
- меньше память.

## Применимость

- Полнотекстовые индексы.
- Поиск всех вхождений.
- Самые длинные повторяющиеся и общие подстроки.
- Биоинформатика.
- Теоретические задачи на строки.

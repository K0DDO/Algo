# 17. Максимальный поток: Форд-Фалкерсон и Эдмондс-Карп

## 1. Задача максимального потока

Есть сеть, по которой нужно передать как можно больше ресурса из источника в сток.

Классическая интерпретация из лекции:

- есть нефтепровод;
- вершины - узлы трубопровода;
- ребра - трубы;
- вес ребра - пропускная способность трубы;
- источник `s` - месторождение;
- сток `t` - завод.

Нужно найти максимальный объем, который можно прокачать из `s` в `t`.

## 2. Сеть

Сеть - это ориентированный граф:

```text
G = (V, E)
```

с двумя выделенными вершинами:

- `s` - источник;
- `t` - сток;

и функцией пропускной способности:

```text
c(u, v) >= 0
```

Если ребра `(u, v)` нет, обычно считают:

```text
c(u, v) = 0
```

## 3. Поток

Поток - это функция `f(u, v)`, которая показывает, сколько ресурса идет по ребру из `u` в `v`.

В лекции поток задавался через три свойства.

### 3.1. Ограничение пропускной способностью

```text
f(u, v) <= c(u, v)
```

По ребру нельзя отправить больше, чем позволяет его пропускная способность.

Для обычной прямой интерпретации также предполагается:

```text
f(u, v) >= 0
```

для исходных ребер. В формальном антисимметричном описании отрицательный поток по обратному направлению означает поток в прямую сторону.

### 3.2. Антисимметрия

```text
f(u, v) = -f(v, u)
```

Если из `u` в `v` идет `5`, то из `v` в `u` это можно считать как `-5`.

Это свойство удобно для описания обратных ребер в остаточной сети: обратное ребро позволяет "отменить" часть уже отправленного потока.

### 3.3. Сохранение потока

Для любой вершины, кроме источника и стока:

```text
sum f(v, u) = 0
```

Иными словами:

```text
сколько входит = столько выходит
```

Промежуточная вершина не создает и не уничтожает поток.

### 3.4. Величина потока

Величина потока:

```text
|f| = sum f(s, v)
```

То есть суммарный поток, выходящий из источника.

Эквивалентно можно считать суммарный поток, входящий в сток.

## 4. Остаточная сеть

Остаточная сеть показывает, как еще можно изменить текущий поток.

Для каждого исходного ребра `(u, v)` с пропускной способностью `c(u, v)` и текущим потоком `f(u, v)` появляются:

### Прямое остаточное ребро

```text
u -> v
capacity = c(u, v) - f(u, v)
```

Оно показывает, сколько еще можно дополнительно протолкнуть вперед.

### Обратное остаточное ребро

```text
v -> u
capacity = f(u, v)
```

Оно показывает, сколько потока можно отменить.

Пример из лекции:

```text
исходное ребро: A -> B
c = 10
f = 7
```

Тогда в остаточной сети:

```text
A -> B имеет остаточную пропускную способность 3
B -> A имеет остаточную пропускную способность 7
```

Инвариант:

```text
остаток вперед + возможность отмены назад = исходная емкость
3 + 7 = 10
```

Или в общем виде:

```text
cap[u][v] + back[v][u] = c(u, v)
```

## 5. Дополняющий путь и bottleneck

Дополняющий путь - это путь из `s` в `t` в остаточной сети, у которого все ребра имеют положительную остаточную пропускную способность.

Bottleneck - минимальная остаточная пропускная способность на найденном пути:

```text
delta = min residual_capacity(e)
```

Именно на `delta` можно увеличить текущий поток.

Если на пути есть ребра с остатками:

```text
10, 8, 5, 7
```

то bottleneck:

```text
delta = 5
```

Больше `5` по этому пути отправить нельзя, потому что самое узкое ребро не пропустит.

## 6. Алгоритм Форда-Фалкерсона

Форд-Фалкерсон - это общий метод:

1. Изначально поток по всем ребрам равен `0`.
2. Остаточная сеть совпадает с исходной сетью.
3. Ищем любой путь из `s` в `t` в остаточной сети.
4. Если пути нет, останавливаемся.
5. На найденном пути считаем bottleneck `delta`.
6. Проталкиваем `delta` по пути:
   - у прямых ребер уменьшаем остаточную пропускную способность;
   - у обратных ребер увеличиваем остаточную пропускную способность.
7. Повторяем, пока существует путь из `s` в `t`.

Когда пути из `s` в `t` в остаточной сети больше нет, поток максимален.

## 7. Реализация через DFS

В простом варианте путь ищется DFS.

Псевдокод:

```text
maxflow = 0

while true:
    used = [false] * V
    pushed = dfs(s, INF)
    if pushed == 0:
        break
    maxflow += pushed

dfs(v, flow):
    if v == t:
        return flow
    used[v] = true

    for edge in graph[v]:
        if edge.capacity > 0 and not used[edge.to]:
            pushed = dfs(edge.to, min(flow, edge.capacity))
            if pushed > 0:
                edge.capacity -= pushed
                edge.reverse.capacity += pushed
                return pushed

    return 0
```

Здесь `edge.capacity` обычно хранит не исходную емкость, а текущую остаточную емкость.

## 8. Сложность Форда-Фалкерсона

Если все пропускные способности целые, то каждая успешная итерация увеличивает поток хотя бы на `1`.

Пусть `|f*|` - величина максимального потока.

Один DFS стоит `O(E)`.

Число успешных итераций не больше `|f*|`.

Итого:

```text
O(E * |f*|)
```

Проблема: сложность зависит не только от размера графа, но и от величины ответа. Если пропускные способности большие, алгоритм может быть медленным.

Если пропускные способности иррациональные, обычный Форд-Фалкерсон с произвольным выбором путей может даже не завершиться.

## 9. Пример-убийца для DFS: `1000/1`

В лекции был показан граф:

```text
s -> A capacity 1000
s -> B capacity 1000
A -> B capacity 1
A -> t capacity 1000
B -> t capacity 1000
```

Максимальный поток равен `2000`.

Но DFS может выбирать плохие пути:

```text
s -> A -> B -> t  bottleneck = 1
s -> B -> A -> t  bottleneck = 1
s -> A -> B -> t  bottleneck = 1
...
```

Он "пинг-понгом" гоняет поток через узкое ребро `A -> B` емкости `1`.

В результате вместо двух крупных проталкиваний DFS может сделать около `2000` итераций.

Хорошие пути были бы:

```text
s -> A -> t  bottleneck = 1000
s -> B -> t  bottleneck = 1000
```

Но простой DFS не обязан их выбирать.

## 10. Алгоритм Эдмондса-Карпа

Эдмондс-Карп - это конкретная реализация Форда-Фалкерсона, где дополняющий путь всегда выбирается BFS.

Ключевая идея:

> Всегда берем кратчайший по числу ребер путь из `s` в `t` в остаточной сети.

То есть вместо произвольного DFS используется BFS.

На примере-убийце BFS сразу найдет:

```text
s -> A -> t
s -> B -> t
```

потому что эти пути имеют длину `2`, а путь через `A -> B` имеет длину `3`.

## 11. Псевдокод Эдмондса-Карпа

```text
maxflow = 0

while true:
    parent = bfs(s, t)
    if parent[t] is empty:
        break

    delta = INF
    cur = t
    while cur != s:
        e = parent[cur]
        delta = min(delta, e.capacity)
        cur = e.from

    cur = t
    while cur != s:
        e = parent[cur]
        e.capacity -= delta
        e.reverse.capacity += delta
        cur = e.from

    maxflow += delta
```

BFS хранит для каждой достигнутой вершины ребро, по которому в нее пришли. По массиву предков потом восстанавливается путь.

## 12. Почему Эдмондс-Карп работает быстрее

Обозначим:

```text
d(v) = расстояние от s до v в остаточной сети
```

где расстояние - число ребер в кратчайшем пути.

Важные факты из лекции:

1. Расстояния `d(v)` не уменьшаются от итерации к итерации.
2. Если ребро стало bottleneck и "умерло", то для его последующего "воскрешения" расстояние до его начала должно вырасти минимум на `2`.
3. Одно ребро может умирать не более `O(V)` раз.
4. Каждая итерация насыщает хотя бы одно ребро.

### Интуиция про "смерть ребер"

Пусть BFS выбрал кратчайший путь и ребро `(u, v)` на нем стало насыщенным, то есть его остаточная емкость стала `0`.

Чтобы это ребро снова появилось с положительной остаточной емкостью, нужно протолкнуть поток по обратному ребру `(v, u)`.

Но обратное ребро может попасть в кратчайший путь только при изменившейся структуре расстояний. Из-за выбора кратчайших путей расстояние до `u` к следующей "смерти" того же ребра вырастает как минимум на `2`.

Так как расстояния ограничены `O(V)`, одно ребро не может становиться критическим бесконечно много раз.

## 13. Сложность Эдмондса-Карпа

Одна итерация:

- BFS по остаточной сети: `O(E)`;
- восстановление пути и обновление ребер: `O(V)`, что не больше `O(E)` для связной полезной части сети.

Сколько итераций:

- каждое насыщение "убивает" хотя бы одно ребро;
- в остаточной сети `O(E)` ребер с учетом обратных;
- каждое ребро может умирать `O(V)` раз.

Итого итераций:

```text
O(V * E)
```

Общая сложность:

```text
O(V * E^2)
```

Память:

```text
O(V + E)
```

при хранении списками смежности.

## 14. Разрез

Разрез `(S, T)` - это разбиение множества вершин на две части:

- `S` содержит источник `s`;
- `T` содержит сток `t`;
- `S union T = V`;
- `S intersection T = empty`.

Пропускная способность разреза:

```text
c(S, T) = сумма c(u, v) по всем ребрам u in S, v in T
```

Важно: считаются только ребра из `S` в `T`, а не обратно.

Поток через разрез:

```text
f(S, T) = сумма f(u, v) по ребрам u in S, v in T
```

## 15. Леммы о разрезах

Из лекции:

1. Поток через любой разрез равен величине потока:

```text
f(S, T) = |f|
```

2. Для любого потока и любого разреза:

```text
|f| <= c(S, T)
```

Поток не может быть больше пропускной способности любого разреза.

3. Если для некоторого потока и разреза:

```text
|f| = c(S, T)
```

то:

- поток максимален;
- разрез минимален.

## 16. Теорема max-flow = min-cut

Теорема:

> Величина максимального потока равна пропускной способности минимального разреза.

Сначала всегда верно:

```text
max |f| <= min c(S, T)
```

потому что любой поток ограничен любым разрезом.

Осталось понять, почему достигается равенство.

Когда алгоритм Форда-Фалкерсона остановился, в остаточной сети нет пути из `s` в `t`.

Построим:

```text
S = все вершины, достижимые из s в остаточной сети
T = V \ S
```

Тогда `t` не достижима, значит `t in T`.

Для любого ребра `(u, v)`, где `u in S`, `v in T`:

- остаточная пропускная способность равна `0`;
- иначе `v` была бы достижима из `s` и попала бы в `S`;
- значит ребро полностью насыщено: `f(u, v) = c(u, v)`.

Следовательно:

```text
|f| = c(S, T)
```

Значит найденный поток максимален, а построенный разрез минимален.

## 17. Как построить минимальный разрез после max-flow

После завершения алгоритма:

1. Берем остаточную сеть.
2. Запускаем DFS или BFS из `s` только по ребрам с положительной остаточной емкостью.
3. Все достигнутые вершины образуют `S`.
4. Остальные вершины образуют `T`.
5. Ребра исходного графа из `S` в `T` образуют минимальный разрез.

Это важный практический прием: max-flow дает не только величину потока, но и конкретное "узкое место" сети.

## 18. Структуры данных

Удобная структура ребра:

```text
Edge:
    to
    rev        индекс обратного ребра
    capacity   текущая остаточная емкость
```

При добавлении исходного ребра `u -> v` емкости `c` добавляют две записи:

```text
u -> v capacity c
v -> u capacity 0
```

При проталкивании `delta`:

```text
forward.capacity -= delta
reverse.capacity += delta
```

Так не нужно отдельно хранить исходный поток: он закодирован в остаточных емкостях.

## 19. Ограничения и применимость

Форд-Фалкерсон с DFS:

- прост в реализации;
- хорошо работает на малых графах и небольших целых емкостях;
- имеет сложность `O(E * |f*|)`;
- может быть очень медленным при больших емкостях;
- с иррациональными емкостями может не завершиться.

Эдмондс-Карп:

- тоже прост;
- всегда выбирает кратчайший путь BFS;
- имеет полиномиальную сложность `O(V * E^2)`;
- не зависит от величины максимального потока;
- обычно надежнее как учебный и базовый алгоритм.

## 20. Итог

Максимальный поток ищется через последовательное улучшение текущего потока по дополняющим путям в остаточной сети.

Главные понятия:

- сеть: ориентированный граф с `s`, `t` и емкостями;
- поток: ограничение, антисимметрия, сохранение;
- остаточная сеть: сколько можно добавить вперед и отменить назад;
- bottleneck: минимум на дополняющем пути;
- Форд-Фалкерсон: любой путь, часто DFS, `O(E * |f*|)`;
- Эдмондс-Карп: кратчайший путь BFS, `O(V * E^2)`;
- max-flow = min-cut;
- минимальный разрез строится как `S =` вершины, достижимые из `s` в остаточной сети после завершения алгоритма.

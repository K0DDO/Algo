# 14. Алгоритм Флойда-Уоршелла

## Введение

Алгоритм Флойда-Уоршелла находит кратчайшие расстояния между всеми парами вершин во взвешенном графе.

В отличие от Дейкстры и Беллмана-Форда, которые обычно запускаются от одного источника, Флойд-Уоршелл сразу строит таблицу `dist[i][j]`: кратчайшее расстояние из `i` в `j`.

Алгоритм допускает отрицательные веса ребер, но не допускает отрицательные циклы, если нужен корректный конечный ответ. Отрицательные циклы можно обнаруживать по диагонали матрицы расстояний.

## Логика алгоритма и DP

Главное состояние:

```text
dp[k][i][j] = кратчайшее расстояние из i в j,
              если в качестве промежуточных разрешены только вершины 1..k
```

Переход:

```text
dp[k][i][j] = min(
    dp[k-1][i][j],
    dp[k-1][i][k] + dp[k-1][k][j]
)
```

То есть кратчайший путь из `i` в `j` либо не использует вершину `k`, либо использует ее как промежуточную и разбивается на путь `i -> k` и путь `k -> j`.

На практике трехмерный массив не нужен. Используют одну матрицу `dist[i][j]`, обновляя ее по слоям `k`.

## Порядок циклов

Ключевой лекционный факт: три цикла идут в порядке:

1. промежуточные вершины;
2. вершины начала пути;
3. вершины конца пути.

Псевдокод:

```text
for k in V:              // промежуточная вершина
    for i in V:          // начало пути
        for j in V:      // конец пути
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
```

Именно внешний цикл по `k` сохраняет смысл DP: после обработки `k` разрешены промежуточные вершины из уже рассмотренного множества.

## Инициализация

Перед запуском:

```text
dist[i][i] = 0
dist[u][v] = weight(u, v), если есть ребро u -> v
dist[u][v] = INF, если ребра нет
```

Если между двумя вершинами несколько ребер, нужно взять минимальный вес.

Диагональ ставится в `0`. Это важно не только для корректных расстояний из вершины в саму себя, но и для детекта отрицательных циклов.

## Детект отрицательных циклов

После выполнения алгоритма:

```text
если dist[v][v] < 0 для некоторой вершины v,
то существует отрицательный цикл, достижимый из v и возвращающийся в v
```

В лекционной формулировке: для поиска циклов отрицательного веса в матрице расстояний на диагонали изначально записывают нули, а после релаксаций смотрят, не стали ли диагональные значения отрицательными.

Если `dist[v][v] < 0`, можно пройти из `v` в `v` с отрицательной суммарной стоимостью, то есть есть отрицательный цикл.

## Восстановление путей

Если нужно восстановить сам путь, можно хранить матрицу `next[i][j]`.

Инициализация:

```text
if edge i -> j exists:
    next[i][j] = j
else:
    next[i][j] = -1
```

При улучшении:

```text
if dist[i][k] + dist[k][j] < dist[i][j]:
    dist[i][j] = dist[i][k] + dist[k][j]
    next[i][j] = next[i][k]
```

Восстановление:

```text
path = [i]
while i != j:
    i = next[i][j]
    path.push(i)
```

## Структуры данных

Основные структуры:

- матрица `dist[V][V]`;
- при необходимости матрица `next[V][V]` или `parent[V][V]`;
- список или матрица исходных ребер для инициализации.

Алгоритм естественно работает с матрицей смежности/весов. Для очень разреженных графов он может быть неоптимален по памяти и времени.

## Сложность

Три вложенных цикла по вершинам дают:

```text
время: O(V^3)
```

Матрица расстояний:

```text
память: O(V^2)
```

Если хранить трехмерный `dp[k][i][j]`, память была бы `O(V^3)`, но это не нужно: достаточно одной матрицы `dist`, потому что каждый слой можно обновлять на месте.

## Ограничения

Алгоритм плохо подходит для очень больших графов из-за `O(V^3)` времени и `O(V^2)` памяти.

Если есть отрицательный цикл, кратчайшие пути для пар вершин, которые могут пройти через этот цикл, не имеют конечного значения.

Нужно проверять `INF`, чтобы не складывать бесконечность:

```text
if dist[i][k] != INF and dist[k][j] != INF:
    dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```

В неориентированном графе отрицательное ребро сразу создает отрицательный цикл длины 2, если ребро можно пройти в обе стороны.

## Применимость

Флойд-Уоршелл удобен, когда:

- нужно знать расстояния между всеми парами вершин;
- `V` не слишком велико;
- граф плотный;
- нужна простая реализация;
- есть отрицательные ребра, но нет отрицательных циклов;
- нужно проверить наличие отрицательного цикла через диагональ.

Примеры:

- таблицы расстояний между городами;
- анализ достижимости и стоимости переходов между состояниями;
- вычисление транзитивного замыкания в булевой версии;
- задачи с ограничением `V <= 400` или около того.

## Примеры

Пусть вершины `1, 2, 3`, ребра:

```text
1 -> 2 (4)
2 -> 3 (-2)
1 -> 3 (10)
```

Инициализация:

```text
dist =
0    4    10
INF  0    -2
INF  INF  0
```

Когда `k = 2`, проверяем путь `1 -> 2 -> 3`:

```text
dist[1][2] + dist[2][3] = 4 + (-2) = 2
```

Это лучше, чем `dist[1][3] = 10`, поэтому обновляем:

```text
dist[1][3] = 2
```

Итог:

```text
кратчайший путь 1 -> 3 имеет вес 2
путь: 1 -> 2 -> 3
```

## Связь с лекциями

В лекции "Теория Графов III-IV" акцент делается на том, что мы проходим всю матрицу `|V| x |V|` для каждой промежуточной вершины. Поэтому порядок циклов важно запомнить именно так:

```text
for intermediate
    for start
        for finish
```

Это не просто техническая деталь, а отражение DP-смысла `dp[k][i][j]`.

## Типичные ошибки

- Поставить циклы в неправильном порядке и разрушить инвариант DP.
- Не занулить диагональ.
- Забыть проверить диагональ для отрицательных циклов.
- Складывать `INF + weight`.
- Использовать Флойда на слишком большом графе.
- Не обработать несколько ребер между одной парой вершин.
- Путать "все пары" с "один источник".
